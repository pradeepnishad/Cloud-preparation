# Step-by-step: Create an IAM Admin User + MFA

## Step 1 — Sign in as Root User

Go to the AWS Management Console and choose **Root user**.

Enter:

```text
Root email
    ↓
Root password
    ↓
Root MFA
    ↓
AWS Console
```

AWS recommends **not using the root user for everyday work**. Keep it for tasks that specifically require root credentials. ([AWS Documentation][2])

---

## Step 2 — Open IAM

In the AWS Console:

**Search → IAM → IAM**

Then from the left-hand menu:

```text
IAM
 └── Users
```

Click **Users**.

---

## Step 3 — Create the IAM User

Click:

**Create user**

For example, enter:

```text
User name:
pradeepnishad
```

If you want this user to log into the AWS Console, select the option to provide **AWS Management Console access**.

AWS will create console credentials for this user. ([AWS Documentation][3])

### Important

For a user who only needs console access, **don't create access keys** just because they're available. AWS recommends creating only the credentials the user actually needs. ([AWS Documentation][3])

---

# Step 4 — Give the User Permissions

AWS IAM users have **no permissions by default**. You need to attach permissions through policies or groups. ([AWS Documentation][4])

For your learning account, you can choose:

**Permissions options → Add user to group**

Create a group such as:

```text
AWS-Admins
```

Then attach:

```text
AdministratorAccess
```

to that group.

Your structure becomes:

```text
AWS Account
     │
     ├── Root User
     │
     └── IAM User
           │
           └── AWS-Admins Group
                    │
                    └── AdministratorAccess
```

### Why use a group?

Instead of attaching `AdministratorAccess` directly to the user, you're learning a more scalable approach:

```text
User
 ↓
Group
 ↓
Policy
 ↓
Permissions
```

AWS recommends using groups to manage permissions when users have common access requirements. ([AWS Documentation][3])

---

# Step 5 — Create the User

Review everything and click:

**Create user**

You should now have something like:

```text
IAM User
Name: pradeepnishad
Console access: Enabled
Group: AWS-Admins
Policy: AdministratorAccess
```

AWS will provide the information needed to sign in, including the console sign-in URL/credentials. ([AWS Documentation][3])

---

# Step 6 — Sign in as the IAM User

**Don't immediately continue working as root.**

Open the IAM user sign-in URL.

It will look approximately like:

```text
https://<account-id>.signin.aws.amazon.com/console/
```

AWS requires an IAM user to provide the **account ID/account alias + username + password** when signing in. ([AWS Documentation][5])

Enter:

```text
Account ID / Alias
        ↓
IAM username
        ↓
Password
        ↓
AWS Console
```

---

# Step 7 — Configure MFA

Now that you're working with the IAM user, go to:

```text
IAM
 ↓
Users
 ↓
pradeepnishad
 ↓
Security credentials
 ↓
Multi-factor authentication (MFA)
 ↓
Assign MFA device
```

Choose:

**Authenticator app**

For example:

* Google Authenticator
* Authy
* Microsoft Authenticator
* Another compatible TOTP authenticator

AWS supports virtual MFA devices that generate time-based codes. ([AWS Documentation][6])

---

# Step 8 — Scan the QR Code

AWS will show you a QR code.

On your phone:

```text
Authenticator App
       ↓
Add account
       ↓
Scan QR code
       ↓
AWS MFA account added
```

The app will generate a **6-digit code** that changes periodically.

### Important — this is where you had the problem earlier

AWS asks for **two consecutive MFA codes**.

For example:

```text
Code 1
381492

      ↓ wait for the next code

Code 2
725104
```

Don't enter:

```text
381492
381492   ❌
```

The second field needs the **new code generated by the authenticator**.

Then click:

**Add MFA**

AWS requires the MFA device during console sign-in once MFA is configured. ([AWS Documentation][6])

---

# Step 9 — Log Out of Root

Once your IAM user is working:

```text
Root User
    ↓
Logout
```

From this point onward, for your normal AWS learning:

```text
IAM User
    ↓
MFA
    ↓
AWS Console
```

You don't need to keep using the root account.

---

# Step 10 — Your Final Setup

You should now have:

```text
                 AWS ACCOUNT
                      │
        ┌─────────────┴─────────────┐
        │                           │
   ROOT USER                   IAM USER
        │                           │
     MFA 🔐                    MFA 🔐
        │                           │
   Emergency /               AWS-Admins
   account tasks                  │
                                  │
                           AdministratorAccess
                                  │
                                  ↓
                         AWS Resources
                    ┌─────┬─────┬─────┐
                    │ EC2 │ S3  │ VPC │
                    └─────┴─────┴─────┘
```

### The concept you should remember

```text
ROOT USER
   │
   │ Creates
   ↓
IAM USER
   │
   │ Gets permissions through
   ↓
GROUP / POLICY
   │
   │ Protected by
   ↓
MFA
   │
   ↓
AWS CONSOLE
```

**Root = account owner / highly privileged account**

**IAM user = identity you use for your normal learning/work in this setup**

**IAM policy = defines what that identity can do**

**MFA = second authentication factor**

**AdministratorAccess = essentially full administrative permissions, so it's appropriate for a dedicated learning account but not a good default for normal production users.** AWS recommends moving toward **least-privilege permissions** as your needs become clearer.
