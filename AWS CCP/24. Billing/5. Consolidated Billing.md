# AWS Consolidated Billing

### What is Consolidated Billing?

**Consolidated Billing** is a feature of **AWS Organizations** that allows multiple AWS accounts to be combined under **one bill**.

Think of it like this:

> **Multiple AWS accounts → One organization → One bill**

For example:

```text
AWS Organization
       │
       ├── Management/Payer Account
       │       └── Pays the bill
       │
       ├── Development Account
       │
       ├── Production Account
       │
       └── Testing Account
```

The individual accounts are still separate AWS accounts, but AWS combines their billing.

---

## 1. One account pays for all accounts

The organization has a **management account** (historically called the master account) that is responsible for paying the charges of the member accounts.

Example:

| Account     |    Usage | Who pays?              |
| ----------- | -------: | ---------------------- |
| Development |     $100 | Management account     |
| Production  |     $500 | Management account     |
| Testing     |      $50 | Management account     |
| **Total**   | **$650** | **Management account** |

So instead of receiving three separate bills, the organization gets **one consolidated bill**.

### Important for exam

**Consolidated Billing = Multiple AWS accounts + one bill**

So AWS doesn't charge you an extra fee simply for using consolidated billing.

# 3. Cost Explorer

Your slide specifically mentions **AWS Cost Explorer**.

Cost Explorer can be used to **visualize usage and costs** across the accounts in the organization.

For example, management could analyze:

```text
Production → $5,000
Development → $1,500
Testing → $500
------------------
Total      → $7,000
```

This helps organizations understand where their AWS spending is going.

# 4. Volume Discounts

This is one of the **most important concepts** in the second photo.

AWS offers **volume discounts** for certain services.

The basic idea is:

> **More combined usage → potentially lower price tiers**

With Consolidated Billing, usage from multiple accounts can be **combined** for applicable volume pricing.

### Example from your slide

Suppose:

* Odo uses **4 TB**
* Dax uses **8 TB**
* Combined usage = **12 TB**

Without consolidation:

```text
Odo = 4 TB
Dax = 8 TB

Each account is considered separately.
```

The slide uses:

* First 10 TB → **$0.17/GB**
* Next 40 TB → **$0.13/GB**

Because the accounts are consolidated, AWS can consider the **combined 12 TB** for the applicable volume pricing.

So:

### Without consolidation

Odo:

**4 × 1024 × $0.17 = $696.32**

Dax:

**8 × 1024 × $0.17 = $1,392.64**

Total:

**$696.32 + $1,392.64 = $2,088.96**

### With consolidation

Combined usage:

**12 TB**

First 10 TB:

**10 × 1024 × $0.17 = $1,740.80**

Remaining 2 TB:

**2 × 1024 × $0.13 = $266.24**

Total:

**$1,740.80 + $266.24 = $2,007.04**

So the consolidated amount is lower in this example.

# 5. Why organizations use Consolidated Billing

There are several benefits shown in your slides:

### 💰 1. One bill

Instead of managing bills for every AWS account separately, the organization gets a consolidated bill.

### 📊 2. Centralized cost visibility

The management account can use **Cost Explorer** to analyze usage and spending.

### 📉 3. Volume discounts

Eligible usage can be combined across accounts to help reach lower pricing tiers.

### 🏢 4. Easier organization-wide billing

Large companies can have:

```text
Company
│
├── Finance AWS Account
├── Development AWS Account
├── Production AWS Account
├── Security AWS Account
└── Testing AWS Account
```

All can belong to the same AWS Organization for centralized billing.

---

# One important distinction

Don't confuse **Consolidated Billing** with **merging accounts**.

Consolidated Billing does **not** mean:

> "All AWS accounts become one account."

Instead:

```text
Account A ──┐
Account B ──┼── AWS Organization ── One consolidated bill
Account C ──┘
```

The accounts remain separate.
