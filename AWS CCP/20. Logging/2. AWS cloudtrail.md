## AWS CloudTrail — Event History vs Trails

These two slides add an important detail to what you learned about CloudTrail.

### 1. CloudTrail Event History

**CloudTrail logs API activity by default** and provides an **Event History** view.

According to your notes, Event History keeps the **last 90 days** of CloudTrail events.

You can use it to investigate things like:

* Who performed an action?
* What API call was made?
* When did it happen?
* Which AWS resource/service was involved?

So:

> **Event History → Quick access to recent CloudTrail activity**

---

### 2. What if you need more than 90 days?

If you need CloudTrail records for **more than 90 days**, your notes say you need to **create a Trail**.

Think of it like:

```text
CloudTrail
    │
    ├── Event History
    │      └── Last 90 days
    │
    └── Trail
           └── Long-term logging
```

---

### 3. Where do Trails store the logs?

A CloudTrail **Trail outputs logs to Amazon S3**.

So the flow is:

```text
AWS API Activity
       ↓
   CloudTrail
       ↓
     Trail
       ↓
      S3
```

This allows you to retain CloudTrail logs beyond the Event History period.

---

### 4. How do you analyze Trail logs?

Your slide points out an important difference:

**Trails don't have the same GUI as Event History.**

For analyzing the Trail data, your notes mention:

> **Amazon Athena**

So you can think:

```text
Trail
  ↓
S3
  ↓
Athena
  ↓
Analyze CloudTrail logs
```

---

## 🔥 Exam Memory

Remember this:

> **Event History = 90 days + GUI**

> **Need more than 90 days = Create a Trail**

> **Trail logs → S3**

> **Analyze Trail data → Athena**

And your previous CloudTrail memory still applies:

**WHERE → Source IP**
**WHEN → EventTime**
**WHO → User/UserAgent**
**WHAT → Region/Resource/Action**

### One-line answer

**CloudTrail records AWS API activity; Event History provides recent activity, while Trails send CloudTrail logs to S3 for longer-term storage and analysis.**
