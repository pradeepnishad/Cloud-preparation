# AWS Container Services

Your screenshot groups AWS container-related services into **Primary Services**, **Provisioning & Deployment**, and **Supporting Services**. I'll follow that structure.

## 1. Amazon ECS — Elastic Container Service

### Definition

**Amazon ECS** is AWS's managed container orchestration service for running and managing containers.

In the screenshot, ECS is described as:

* **No cold starts**
* **Self-managed EC2**

The key idea is that ECS manages the orchestration of your containers, while you can choose the underlying compute.

### How it works

A simplified architecture:

```text
Container Image
      ↓
     ECS
      ↓
ECS Task / Service
      ↓
EC2 / Fargate
```

With **ECS on EC2**, you are responsible for managing the EC2 infrastructure.

### Why use ECS?

Use ECS when you want to run containerized applications and need AWS-native container orchestration.

### Scenario

You have a web application packaged as a Docker image:

```text
Docker Image
     ↓
ECR
     ↓
ECS
     ↓
EC2 instances
     ↓
Running containers
```

# 2. AWS Fargate

### Definition

**AWS Fargate** is a serverless compute engine for containers.

The important difference from ECS on EC2 is:

```text
ECS + EC2
→ You manage EC2

ECS + Fargate
→ AWS manages the underlying compute
```

The screenshot highlights:

* More robust than Lambda
* Scale to zero cost
* AWS-managed EC2

### Why use Fargate?

When you want to run containers **without managing EC2 servers**.

### Scenario

You have a containerized API but don't want to:

* Launch EC2 instances
* Patch operating systems
* Manage container hosts
* Maintain server capacity

You can run the container using:

```text
ECS
 +
Fargate
```

### Exam memory

> **Fargate = Containers without managing servers.**

---

# 3. Amazon EKS — Elastic Kubernetes Service

### Definition

**Amazon EKS** is AWS's managed Kubernetes service.

Kubernetes is an open-source container orchestration platform.

The screenshot highlights:

* Open source
* Avoid vendor lock-in

### Why use EKS?

Use EKS when your organization wants **Kubernetes** for managing containerized workloads.

### Scenario

A company already has Kubernetes expertise and wants to run its Kubernetes workloads on AWS.

```text
Kubernetes
     ↓
    EKS
     ↓
AWS infrastructure
```

### ECS vs EKS

| ECS                                | EKS                                      |
| ---------------------------------- | ---------------------------------------- |
| AWS-native container orchestration | Kubernetes                               |
| AWS-specific ecosystem             | Kubernetes ecosystem                     |
| Simpler AWS-native approach        | Useful for Kubernetes-based environments |

### Exam memory

> **ECS = AWS container orchestration**
> **EKS = Kubernetes on AWS**

# 4. AWS Lambda

### Definition

**AWS Lambda** is a serverless compute service that runs code in response to events without requiring you to manage servers.

The screenshot highlights:

* Think about code
* Short-running tasks
* Can deploy custom containers

### Why use Lambda?

When your workload can be broken into **short-running, event-driven functions**.

### Scenario

A user uploads an image to S3:

```text
User
 ↓
S3
 ↓
Lambda
 ↓
Resize image
```

You don't need to maintain a server just to perform the image-processing task.

### Important distinction

Lambda **can run container images**, but Lambda itself is not the same thing as a general-purpose container orchestration platform.

---

# 5. AWS Elastic Beanstalk

### Definition

**AWS Elastic Beanstalk (EB)** is a platform service that simplifies application deployment and environment management.

The screenshot describes it as:

> **ECS on training wheels**

This is a simplified way of remembering that Beanstalk abstracts away much of the infrastructure configuration.

### Why use it?

When you want to deploy an application without manually configuring all the underlying AWS infrastructure.

### Scenario

You have a web application and want AWS to handle much of the environment setup while you focus primarily on your application.

---

# 6. AWS App Runner

### Definition

**AWS App Runner** is a fully managed service for deploying containerized web applications and APIs.

The screenshot describes it as:

> **Platform as a Service specifically for containers**

### Why use App Runner?

When you have a container and want a simpler deployment experience without managing the underlying servers.

### Scenario

You have:

```text
Docker Image
     ↓
App Runner
     ↓
Running Web Application
```

You don't need to manually build an ECS cluster and manage its infrastructure.

---

# 7. AWS Copilot CLI

### Definition

**AWS Copilot CLI** is a command-line tool designed to help build, release, and operate production-ready containerized applications on AWS.

The screenshot specifically mentions:

* AWS App Runner
* Amazon ECS
* AWS Fargate

### Why use it?

Instead of manually configuring many AWS resources, developers can use Copilot commands to simplify container application deployment and operations.

---

# 8. Amazon ECR — Elastic Container Registry

### Definition

**Amazon ECR** is a managed container image registry.

Your screenshot describes it as:

> **Repos for your Docker Images**

Think of ECR as a place where you store your container images.

### Workflow

```text
Dockerfile
    ↓
Build Image
    ↓
ECR
    ↓
ECS / Fargate / EKS
    ↓
Running Container
```

### Why use ECR?

Your container platform needs somewhere to retrieve container images from.

### Important distinction

**ECR does not run your containers.**

It **stores container images**.

> **ECR = Container Image Storage**

---

# 9. AWS X-Ray

### Definition

**AWS X-Ray** helps analyze and debug requests as they move through distributed applications and microservices.

The screenshot describes it as:

> **Analyze and debug between microservices**

### Why use it?

Microservice architectures can contain many services:

```text
User
 ↓
API
 ↓
Service A
 ↓
Service B
 ↓
Database
```

If the request becomes slow or fails, X-Ray can help identify where the problem occurred.

### Memory

> **X-Ray = Trace and troubleshoot distributed applications.**

---

# 10. AWS Step Functions

### Definition

**AWS Step Functions** is a workflow/state-machine service that can coordinate multiple AWS services and tasks.

Your screenshot specifically mentions:

> **Stitch together Lambdas and ECS tasks**

Example:

```text
Start
 ↓
Lambda
 ↓
ECS Task
 ↓
Lambda
 ↓
End
```

It is useful when an application has multiple steps that must execute in a particular sequence or based on conditions.

### Memory

> **Step Functions = Connect multiple steps/services into a workflow.**
