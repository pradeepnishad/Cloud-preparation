# Docker

## 1. Definition

**Docker** is a set of Platform as a Service (PaaS) products that uses **OS-level virtualization** to deliver software in packages called **containers**.

In simple terms:

> **Docker packages an application together with its dependencies so it can run consistently inside a container.**

The source also describes Docker as one of the earliest widely popularized open-source container platforms.

---

## 2. Why use Docker?

Without containers, an application may depend on:

* Specific Python/Java/Node.js versions
* Libraries
* Packages
* Configuration
* OS-level dependencies

This can create the classic problem:

> **“It works on my machine.”**

Docker packages the application and its required dependencies into a container so the application has a consistent environment.

---

## 3. How Docker works

Docker uses **OS-level virtualization**.

Unlike a traditional VM, containers don't require a complete guest operating system for every application.

Conceptually:

```text
Virtual Machines

VM 1              VM 2
App + Libraries   App + Libraries
Guest OS          Guest OS
-------------------------
Hypervisor
-------------------------
Host OS
```

Docker:

```text
Container 1       Container 2
App + Libraries   App + Libraries
-----------------------------
Docker Engine
-----------------------------
Host OS
```

This is why containers can generally be more lightweight than full virtual machines.

# 4. Dockerfile

A **Dockerfile** is a configuration file that describes how to build/provision a container image.

Example from your screenshot:

```dockerfile
FROM python:3.8-alpine3.12
COPY . /app
WORKDIR /app
RUN pip install -r requirements.txt
CMD ["python3", "app.py"]
```

This tells Docker things such as:

* `FROM` → starting/base image
* `COPY` → copy application files
* `WORKDIR` → set working directory
* `RUN` → execute a command while building the image
* `CMD` → default command when the container starts

Think of a Dockerfile as:

> **Instructions/recipe for creating a container image.**

# 5. Docker CLI

**Docker CLI** provides command-line commands for working with Docker.

You can use it to:

* Build images
* Download images
* Upload images
* Run containers
* Stop containers
* Debug containers
* Manage containers

Example:

```bash
docker build .
docker run my-app
docker ps
docker stop my-app
```

So:

**Docker CLI → interact with Docker from the terminal.**

---

# 6. Docker Compose

**Docker Compose** is a tool and configuration approach for working with **multiple containers**.

For example, a web application might have:

```text
Web Application
      │
      ├── Frontend Container
      ├── Backend Container
      ├── Database Container
      └── Redis Container
```

Instead of manually managing every container, Docker Compose allows you to define the multi-container application configuration.

Typically this is done using a Compose YAML file.

### Scenario

You are developing a Django application that requires:

```text
Django
PostgreSQL
Redis
```

Docker Compose can define all three containers and how they interact.

# 7. Docker Swarm

**Docker Swarm** is Docker's orchestration tool for managing **multi-container architectures**.

It allows multiple Docker hosts to work together as a cluster.

Conceptually:

```text
Docker Swarm
     │
 ┌───┼────┐
 ↓   ↓    ↓
Node Node Node
 │    │    │
Containers
```

For your AWS/Cloud learning, remember that **Kubernetes is another container orchestration system** and is much more commonly encountered in modern cloud-native environments.

---

# 8. Docker Hub

**Docker Hub** is a public online repository where container images can be published and downloaded.

Think of it like:

> **A public registry for container images.**

For example, developers can pull existing images rather than building everything from scratch.

Conceptually:

```text
Dockerfile
    ↓
Build
    ↓
Docker Image
    ↓
Docker Hub
    ↓
Other developers
    ↓
docker pull
```

# 9. Open Container Initiative (OCI)

The **Open Container Initiative (OCI)** is an open governance structure for creating **open industry standards around container formats and runtimes**.

The screenshot states that Docker established the OCI and that it is now maintained by the **Linux Foundation**.

The important concept for your exam:

> **OCI = open standards for container formats and runtimes.**

This helps different container technologies follow common standards rather than being completely locked to one implementation.

---

# 10. Docker vs Kubernetes

This distinction is important.

| Docker                                          | Kubernetes                                      |
| ----------------------------------------------- | ----------------------------------------------- |
| Container platform/tooling                      | Container orchestration system                  |
| Builds container images                         | Manages containerized workloads                 |
| Runs containers                                 | Coordinates containers across nodes             |
| Docker CLI                                      | `kubectl` is commonly used                      |
| Docker Compose for multi-container local setups | Kubernetes for large-scale orchestration        |
| Docker Swarm is Docker's orchestration option   | Kubernetes is a separate orchestration platform |

Simple memory:

> **Docker = Create & Run Containers**
> **Kubernetes = Orchestrate Containers**

# 11. Scenario

Imagine you build a Python application:

```text
app.py
requirements.txt
```

Your application requires a specific Python version and several libraries.

You create:

```text
Dockerfile
     ↓
Docker build
     ↓
Docker Image
     ↓
Docker Container
     ↓
Application runs
```

Now you can run the same container on:

* Your laptop
* A development server
* An AWS EC2 instance
* A container platform

without manually installing the same dependencies each time.

# 12. Important Docker Terms

| Term               | Meaning                                             |
| ------------------ | --------------------------------------------------- |
| **Docker**         | Container platform/tooling                          |
| **Container**      | Running isolated application environment            |
| **Image**          | Template/package used to create containers          |
| **Dockerfile**     | Instructions for building an image                  |
| **Docker CLI**     | Command-line interface for Docker                   |
| **Docker Compose** | Tool/configuration for multi-container applications |

| **Docker Hub**     | Public container image registry                     |
| **OCI**            | Open standards for container formats/runtimes       |
