This screenshot is explaining **Dedicated Hosts** and comparing them with **Dedicated Instances**.

---

## 1. What is a Dedicated Host?

### Definition

An **EC2 Dedicated Host** is a **physical server dedicated to a single customer/account**.

Unlike normal EC2 instances, where AWS manages placement across its physical infrastructure, a Dedicated Host gives you visibility and additional control over the underlying physical host.

The screenshot specifically highlights:

* **Single-tenant**
* **Physical server isolation**
* **BYOL (Bring Your Own License)**
* Visibility into physical characteristics such as:

  * Sockets
  * Cores
  * Host ID

### Simple picture

Normal EC2:

```text
AWS Physical Server
├── Customer A EC2
├── Customer A EC2
└── Other workloads
```

Dedicated Host:

```text
Dedicated Physical Server
└── Your EC2 instances
```

---

# 2. Why use a Dedicated Host?

The major reason highlighted by your source is:

### BYOL — Bring Your Own License

Some software licenses are based on **physical machine characteristics** such as:

* Physical sockets
* CPU cores
* Physical host

A Dedicated Host provides visibility/control over those physical characteristics, which can help support applicable BYOL licensing requirements.

### Scenario

Suppose an enterprise already owns software licenses whose licensing terms depend on the physical hardware.

They want to run that software on AWS.

A Dedicated Host can provide the physical-host visibility and dedicated server arrangement needed for applicable licensing models.

> Important: BYOL eligibility depends on the **software vendor's licensing terms and AWS requirements**. Owning a license doesn't automatically make it eligible for use on AWS.

### Dedicated Instance

# 4. Dedicated Host vs Dedicated Instance

This is the most important part of your screenshot.

| Feature                          | Dedicated Instance | Dedicated Host            |
| -------------------------------- | ------------------ | ------------------------- |
| Isolation                        | Instance isolation | Physical server isolation |
| Billing                          | Per instance       | Per host                  |
| Physical characteristics visible | No                 | Yes                       |
| Sockets/cores/Host ID            | No visibility      | Visible                   |
| Host affinity/control            | No                 | Yes                       |
| Targeted placement control       | No                 | Yes                       |
| Allocation request               | No                 | Yes                       |

Dedicated Host

# 6. Host Affinity

### Definition

**Affinity** refers to maintaining a relationship between an EC2 instance and a particular Dedicated Host.

The screenshot says Dedicated Hosts allow:

> **Consistency deploy to the same instances to the same physical server**

The basic idea is that you can have greater control over where your EC2 instances are placed.

### Scenario

Suppose you want a particular EC2 instance to remain associated with a particular Dedicated Host.

Dedicated Hosts provide capabilities for this type of placement control.

---

# 7. Targeted Instance Placement

With normal EC2 placement, you don't generally control the exact physical server where AWS places your instance.

With Dedicated Hosts, you have **additional control over instance placement on the physical server**.

Think:

```text
Normal EC2
   ↓
AWS decides physical placement

Dedicated Host
   ↓
You have additional placement control
```

---

# 8. Billing

The screenshot highlights an important difference:

### Dedicated Instance

```text
Billing
↓
Per instance
```

### Dedicated Host

```text
Billing
↓
Per host
```

So the pricing model is different.

You pay for the **Dedicated Host capacity**, rather than simply paying individually for each EC2 instance in the same way as Dedicated Instances.

---

# 9. Allocation Request

The screenshot says:

### Dedicated Instance

> Add capacity using an allocation request → **No**

### Dedicated Host

> Add capacity using an allocation request → **Yes**

The key concept for your exam is simply that Dedicated Hosts provide an **allocation mechanism for obtaining dedicated host capacity**.
