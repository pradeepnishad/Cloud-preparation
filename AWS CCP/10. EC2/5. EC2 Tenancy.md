# 🖥️ EC2 Tenancy

This screenshot explains the **three EC2 tenancy options**:

1. **Dedicated Host**
2. **Dedicated Instance**
3. **Default tenancy**

The main idea is **how EC2 instances are placed on physical AWS hardware**.

---

# 1. What is EC2 Tenancy?

### Definition

**EC2 tenancy determines how your EC2 instances are placed on the underlying physical hardware.**

In simple terms:

> **Tenancy = Who shares the physical server?**

Your screenshot shows three levels:

```text
Dedicated Host
Dedicated Instance
Default
```

---

# 2. Dedicated Host

### Definition

With a **Dedicated Host**, your EC2 instances run on a **physical server dedicated to your account**, and you have control/visibility over physical host attributes.

The screenshot says:

> "Your server lives here and you have control of the physical attributes."

Conceptually:

```text
Physical Server
┌──────────────────┐
│ Your EC2         │
│ Your EC2         │
│ Your EC2         │
│                  │
│ Dedicated to you │
└──────────────────┘
```

### Key idea

You are getting the **physical host** dedicated to you.

This is particularly relevant for:

* Physical server isolation
* Certain BYOL licensing requirements
* Physical host visibility/control
* Specific placement requirements

### Memory

> **Dedicated Host = Your physical server**

---

# 3. Dedicated Instance

### Definition

With a **Dedicated Instance**, your EC2 instance runs on hardware dedicated to your account, but you **don't have the same level of visibility/control over the physical host** as with a Dedicated Host.

Your screenshot says:

> "Your server always lives here."

The important concept is **instance-level dedication**, rather than getting control over the physical host.

Conceptually:

```text
Physical AWS Server
┌──────────────────┐
│ Your EC2         │
│ Your EC2         │
│ Your EC2         │
└──────────────────┘
```

The physical server is dedicated to your account, but AWS manages the underlying host.

### Memory

> **Dedicated Instance = Your EC2 is dedicated, but you don't control the physical host.**

---

# 4. Default Tenancy

### Definition

**Default tenancy** is the normal EC2 tenancy option.

The screenshot says:

> "Your instance live here until reboot."

The important idea is that your EC2 instance runs on AWS's shared infrastructure according to AWS's normal placement system.

Conceptually:

```text
Physical Server
┌──────────────────┐
│ Customer A EC2   │
│ Customer B EC2   │
│ Customer C EC2   │
│ Customer D EC2   │
└──────────────────┘
```

Multiple customers' instances can run on the same physical infrastructure while remaining logically isolated.

### What does "until reboot" mean in the screenshot?

The source is emphasizing that **default tenancy does not provide a persistent physical-host placement guarantee**. AWS can place/re-place the instance according to its infrastructure management.

### Memory

> **Default = Normal EC2 placement**

---

# 🔥 The Three Options

| Tenancy                | Physical host             | Customer control                         |
| ---------------------- | ------------------------- | ---------------------------------------- |
| **Default**            | Shared AWS infrastructure | Lowest                                   |
| **Dedicated Instance** | Dedicated to your account | More limited                             |
| **Dedicated Host**     | Dedicated physical server | Highest physical-host visibility/control |

---

# 🧠 The Difference You Really Need to Understand

Think about the question:

> **"What exactly am I getting dedicated?"**

### Default

```text
Nothing physically dedicated
        ↓
Normal EC2 placement
```

### Dedicated Instance

```text
EC2 instance
      ↓
Dedicated hardware for your account
```

### Dedicated Host

```text
Entire physical server
        ↓
Dedicated to your account
        ↓
Physical host visibility/control
```

---

# 🎯 Exam Scenarios

### Scenario 1

You simply need a normal EC2 virtual server.

→ **Default tenancy**

---

### Scenario 2

You need an EC2 instance running on hardware dedicated to your account, but you don't need physical host-level control.

→ **Dedicated Instance**

---

### Scenario 3

You need a **dedicated physical server** and visibility into physical characteristics such as sockets, cores, and host ID.

→ **Dedicated Host**

---

### Scenario 4

You have applicable software licensing requirements based on physical server characteristics.

→ **Dedicated Host**
