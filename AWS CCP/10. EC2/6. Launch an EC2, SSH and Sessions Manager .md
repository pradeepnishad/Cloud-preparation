If you're learning AWS EC2, these are the three things you should understand:

## 1. Launch an EC2 Instance

Basic flow:

```text
AWS Console
   ↓
EC2
   ↓
Launch instance
   ↓
Choose AMI
   ↓
Choose instance type
   ↓
Create/choose key pair
   ↓
Configure network
   ↓
Configure security group
   ↓
Launch
```

For a beginner Linux instance:

* **AMI:** Ubuntu Server 24.04 LTS or Amazon Linux
* **Instance type:** `t3.micro` or eligible free-tier option
* **Key pair:** Create/download `.pem`
* **Security group:** SSH (`TCP 22`) from **My IP**
* **Storage:** Default 8–10 GB is enough for practice

After launching, note the instance's **Public IPv4 address**.

---

## 2. SSH into EC2

SSH allows you to remotely access the Linux server.

On your local Linux machine:

```bash
chmod 400 my-key.pem
```

Then:

```bash
ssh -i my-key.pem ubuntu@<EC2-PUBLIC-IP>
```

For Amazon Linux:

```bash
ssh -i my-key.pem ec2-user@<EC2-PUBLIC-IP>
```

Example:

```bash
ssh -i aws-learning.pem ubuntu@13.234.XX.XX
```

You'll then get a shell running **on the EC2 instance**:

```text
ubuntu@ip-172-31-10-25:~$
```

You can verify:

```bash
hostname
```

```bash
whoami
```

```bash
uname -a
```

### What SSH requires

```text
Your PC
   │
   │ SSH : TCP 22
   ↓
Internet
   │
   ↓
EC2
   │
   └── Security Group allows TCP 22
```

The EC2 must also have network connectivity and an appropriate route to the internet.

# 3. AWS Systems Manager Session Manager

**Session Manager** lets you access your EC2 instance without opening inbound SSH port 22.

Instead of:

```text
Your PC
   │
   │ SSH : 22
   ↓
EC2
```

you get:

```text
Your PC
   │
   │ HTTPS
   ↓
AWS Systems Manager
   │
   ↓
SSM Agent
   │
   ↓
EC2
```

This is particularly useful in enterprise environments because you don't need to expose SSH to the internet.

### What you need

Your EC2 needs:

1. **SSM Agent**
2. An IAM role attached to the EC2 with appropriate Systems Manager permissions, commonly `AmazonSSMManagedInstanceCore`
3. Network connectivity to Systems Manager endpoints

Then go to:

```text
AWS Console
 → EC2
 → Instances
 → Select instance
 → Connect
 → Session Manager
 → Connect
```

You'll get a terminal directly in your browser.

---

## SSH vs Session Manager

| Feature                    | SSH            | Session Manager |
| -------------------------- | -------------- | --------------- |
| Port 22 required           | Yes            | No              |
| Key pair required          | Usually        | No              |
| Public IP required         | Usually        | No              |
| Browser terminal           | No             | Yes             |
| IAM integration            | Limited        | Strong          |
| Centralized access control | Limited        | Yes             |
| Good for private instances | More difficult | Yes             |
| Enterprise-friendly        | Common         | Very useful     |

### The important concept

Think of them as **two different ways of accessing the same EC2 server**:

```text
                 EC2
                  │
          ┌───────┴────────┐
          │                │
         SSH          Session Manager
          │                │
     TCP Port 22       AWS SSM
          │                │
      SSH client       Browser/CLI
```

For your AWS learning, I would actually practice **both**: first SSH to understand traditional Linux/cloud administration, then Session Manager to understand the AWS-native approach.
