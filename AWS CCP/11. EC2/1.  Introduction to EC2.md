# ⚙️ Introduction to Amazon EC2

Your screenshot introduces **Amazon EC2 (Elastic Compute Cloud)** and the main choices you make when launching an EC2 instance.

---

## 1. What is Amazon EC2?

### Definition

**Amazon EC2 (Elastic Compute Cloud) is a highly configurable virtual server service in AWS.**

An **EC2 instance** is essentially a virtual machine running in AWS.

The screenshot highlights two important characteristics:

* **Highly configurable virtual server**
* **Resizable compute capacity**

You can launch new instances in minutes rather than purchasing and setting up physical servers.

### Simple example

Instead of buying a physical server:

```text
Physical Server
     ↓
Buy hardware
     ↓
Install OS
     ↓
Configure server
     ↓
Start application
```

You can use:

```text
AWS
 ↓
EC2
 ↓
Choose configuration
 ↓
Launch
 ↓
Virtual server
```

---

# 2. Why Use EC2?

EC2 gives you control over the configuration of your virtual server.

You can choose things such as:

* Operating system
* CPU
* Memory
* Storage
* Networking
* Security
* Startup configuration

### Scenario

Suppose you need a Linux server to host a web application.

You can:

```text
Choose Linux AMI
      ↓
Choose EC2 instance type
      ↓
Add storage
      ↓
Configure networking/security
      ↓
Launch EC2
      ↓
Install/run application
```

---

# 3. AMI — Amazon Machine Image

The screenshot says:

> **Choose OS via Amazon Machine Image (AMI)**

### Definition

An **AMI is a template used to launch an EC2 instance.**

It can contain the operating system and other software/configuration needed as the starting point for the instance.

Examples shown in the screenshot include:

* Red Hat
* Ubuntu
* Windows
* Amazon Linux
* SUSE

### Example

You choose:

```text
AMI → Ubuntu
```

Then launch an EC2 instance.

The resulting instance starts with the selected Ubuntu environment.

### 🧠 Remember

> **AMI = Starting template/image for EC2**

---

# 4. Instance Type

After choosing the AMI, you choose an **EC2 instance type**.

The instance type determines the compute characteristics available to the instance, such as:

* CPU
* Memory
* Networking performance
* Other capabilities

Your screenshot gives two examples:

### t2.nano

```text
1 vCPU
0.5 GB memory
```

A very small instance configuration.

### c4.8xlarge

The screenshot shows:

```text
36 vCPU
60 GB memory
10 Gigabit network performance
```

This demonstrates that EC2 instances can have **very different compute capacities**.

### 🧠 Remember

> **Instance Type = How much compute capacity your EC2 gets**

---

# 5. Storage

The screenshot shows:

> **Add Storage (EBS, EFS)**

You can attach storage to your EC2 architecture depending on your requirements.

You've already learned:

```text
EBS → Block storage
EFS → File storage
```

### Example

An EC2 web server might use:

```text
EC2
 │
 └── EBS
      ↓
   OS / applications / data
```

Multiple EC2 instances can potentially use an EFS filesystem:

```text
EC2 ──┐
      ├── EFS
EC2 ──┤
      │
EC2 ──┘
```

# 7. Security Groups

A **Security Group** acts as a virtual firewall for the EC2 instance/resource.

For example, you might allow:

```text
TCP 22  → SSH
TCP 80  → HTTP
TCP 443 → HTTPS
```

You learned earlier:

> **Security Group = Resource/instance-level firewall**

So when launching EC2, security configuration is an important part of the setup.

---

# 8. Key Pairs

A **key pair** is used for secure access to an EC2 instance, particularly for SSH-based access to Linux instances.

Conceptually:

```text
You
 ↓
Private key
 ↓
EC2
 ↓
SSH
```

The private key must be protected.

### 🧠 Remember

> **Key Pair → Secure access to EC2**

---

# 9. User Data

**User Data** allows you to provide commands/scripts that can run when an EC2 instance launches.

For example, you could use a startup script to install a web server.

Conceptually:

```bash
#!/bin/bash
# Install web server
# Start service
# Configure application
```

Then:

```text
Launch EC2
    ↓
User Data executes
    ↓
Software/configuration setup
    ↓
Server ready
```

This is particularly useful for **automation**.

---

# 10. IAM Roles

An **IAM role** can give an EC2 instance permissions to access other AWS resources.

For example:

```text
EC2
 ↓
IAM Role
 ↓
S3
```

Instead of putting long-term AWS access keys inside the application, the instance can use an appropriate IAM role.

### Scenario

Your EC2 application needs to read files from S3.

You can create:

```text
IAM Role
   ↓
Permission: Read from S3
   ↓
Attach role to EC2
```

The application can then make AWS API calls according to those permissions.

### 🧠 Remember

> **IAM Role → Give EC2 AWS permissions**

---

# 11. Placement Groups

The screenshot also mentions **Placement Groups**.

Placement groups influence how EC2 instances are positioned relative to one another in AWS infrastructure.

For Cloud Practitioner, know that placement groups are used to influence the **placement of EC2 instances** for particular workload requirements.

Don't go too deep into the different placement strategies yet unless your course reaches them.
