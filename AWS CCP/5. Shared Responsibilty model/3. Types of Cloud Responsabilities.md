# 🔐 Types of Cloud Responsibilities

In the **AWS Shared Responsibility Model**, responsibilities are broadly divided into **two main types**:

1. **AWS responsibility — Security OF the Cloud**
2. **Customer responsibility — Security IN the Cloud**

The exact customer responsibility changes depending on the AWS service you use.

---

# 1. AWS Responsibility — Security OF the Cloud

### Definition

AWS is responsible for protecting the **underlying infrastructure that runs AWS Cloud services**.

Think:

> **AWS secures the cloud itself.**

### AWS is responsible for things such as:

```text
AWS
│
├── Data Centers
├── Physical Servers
├── Physical Storage
├── Physical Networking
├── Hardware
└── Virtualization Infrastructure
```

### Example

When you create an EC2 instance, you don't have to physically manage:

* The AWS data center
* Physical server hardware
* Physical networking equipment
* Power and cooling
* Physical security

AWS handles these.

### Scenario

You launch an EC2 instance:

```text
Your EC2
    ↓
Virtualization
    ↓
Physical Server
    ↓
AWS Data Center
```

You manage the EC2 environment, but **AWS manages the physical infrastructure underneath it**.

### Memory:

> 🏢 **AWS = Building + Foundation**

---

# 2. Customer Responsibility — Security IN the Cloud

### Definition

The customer is responsible for **appropriately securing and configuring the resources, applications, identities, and data they use in AWS**.

Think:

> **Customer secures what they put inside the cloud.**

Depending on the service, this can include:

```text
Customer
│
├── Data
├── IAM
├── Users
├── Permissions
├── Applications
├── Guest OS
├── Network configuration
└── Security configuration
```

### Example

You launch a Windows EC2 instance.

You are responsible for things such as:

```text
Windows configuration
OS patching
Application security
IAM permissions
Security Group rules
Your data
```

AWS doesn't automatically patch your application or decide who should have access to your data.

### Memory:

> 🧳 **Customer = What you put inside the building**

---

# 3. Responsibility Depends on the Service

This is **very important for the Cloud Practitioner exam**.

The division isn't exactly the same for every AWS service.

Consider:

```text
          Customer Responsibility
                  ↓

EC2  ────────────────────► More
                            customer
                            responsibility

RDS  ───────────────► Less

Managed Services ──► Even less
                  ↑
          AWS Responsibility
```

The more AWS manages for you, the more responsibility AWS takes for that part of the infrastructure.

---

# 4. Example: EC2

With EC2:

```text
                 EC2
                  │
       ┌──────────┴──────────┐
       ↓                     ↓
      AWS                 Customer
       │                     │
Physical infrastructure   Guest OS
Hardware                   Applications
Networking                 Data
Virtualization             IAM
                           Security configuration
```

### AWS:

* Physical infrastructure
* Physical servers
* Data centers
* Underlying networking
* Virtualization

### Customer:

* Guest OS
* OS configuration/patching
* Applications
* Data
* IAM permissions
* Security Groups

---

# 5. Example: Amazon RDS

With RDS, AWS manages more of the underlying platform than with EC2.

```text
                RDS
                 │
       ┌─────────┴─────────┐
       ↓                   ↓
      AWS               Customer
       │                   │
Infrastructure            Data
Database platform          Access
Underlying management     Configuration
```

So you don't have the same level of operating-system responsibility that you have with a customer-managed EC2 instance.

### Key idea:

> **Managed service → AWS manages more → customer manages less of the underlying infrastructure.**

---

# 6. Example: IAM

IAM is mainly a customer-side responsibility.

Suppose you create:

```text
IAM User
    ↓
IAM Policy
    ↓
Permissions
```

You decide:

```text
Who can access AWS?
What can they access?
What actions can they perform?
```

For example:

```text
Developer
   ↓
S3
   ↓
Read-only access
```

Giving the developer unnecessary administrator permissions would be a customer-side security configuration issue.

---

# 7. Example: Security Groups

AWS provides the **Security Group** feature.

But you configure its rules.

For example:

```text
Security Group
│
├── TCP 443 → Allow
└── TCP 22  → Allow from appropriate source
```

AWS provides the firewall mechanism.

**You are responsible for configuring it appropriately.**

---

# 8. Three Important Areas to Remember

For exams, you can think of responsibilities in three broad layers:

```text
1. AWS
   ↓
Infrastructure

2. Customer
   ↓
Configuration + Applications + Data

3. Shared/Service-dependent
   ↓
Responsibilities vary by service
```

The third category is important because not everything can simply be labeled 100% AWS or 100% customer.

---

# 9. Responsibility Comparison

| Responsibility                 | Generally              |
| ------------------------------ | ---------------------- |
| Physical data-center security  | **AWS**                |
| Physical servers               | **AWS**                |
| Physical networking            | **AWS**                |
| Underlying virtualization      | **AWS**                |
| Customer data                  | **Customer**           |
| IAM users/permissions          | **Customer**           |
| Application security           | **Customer**           |
| EC2 guest OS                   | **Customer**           |
| EC2 OS patching                | **Customer**           |
| Security Group configuration   | **Customer**           |
| Service-specific configuration | **Depends on service** |

---

# 10. Scenario-Based Example

Imagine you're running:

```text
Internet
   ↓
Load Balancer
   ↓
EC2
   ↓
RDS
```

### AWS handles:

```text
Physical data center
        ↓
Physical hardware
        ↓
Physical networking
        ↓
Underlying AWS infrastructure
```

### You handle:

```text
IAM
 ↓
Security Groups
 ↓
EC2 OS
 ↓
Applications
 ↓
Your data
```

And RDS has a different responsibility boundary because AWS manages more of the database platform.

---

# 🎯 Exam Questions

### If the question says:

**"Who secures AWS data centers?"**

→ **AWS**

**"Who manages physical hardware?"**

→ **AWS**

**"Who manages IAM permissions?"**

→ **Customer**

**"Who patches an EC2 guest operating system?"**

→ **Customer**

**"Who configures Security Group rules?"**

→ **Customer**

**"Does the customer have the same responsibility for EC2 and RDS?"**

→ **No. The responsibility changes depending on the service.**

# 🧠 Final Summary

```text
             SHARED RESPONSIBILITY
                     │
          ┌──────────┴──────────┐
          ↓                     ↓
        AWS                 CUSTOMER
          ↓                     ↓
 Security OF Cloud       Security IN Cloud
          ↓                     ↓
 Data Centers             Data
 Physical Hardware        IAM
 Networking               Applications
 Virtualization           OS (where applicable)
 Infrastructure           Configurations
```

### 🔥 Remember:

> **AWS → Security OF the Cloud**

> **Customer → Security IN the Cloud**

> **Service determines how the responsibilities are divided.**

**Easy analogy:**
🏢 **AWS owns and secures the building.**
🧳 **You are responsible for securing what you bring inside it.**
