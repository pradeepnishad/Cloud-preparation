# ☁️ Shared Responsibility for Compute

**Shared responsibility for compute** means understanding **which parts of a compute environment AWS manages and which parts you, as the customer, must manage.**

The exact responsibility depends on the compute service you're using.

The easiest way to understand it is:

> **AWS manages the underlying infrastructure; the customer manages the parts of the compute environment that AWS has not taken over.**

---

# 1. What Is "Compute"?

In AWS, **compute** means the resources used to run applications and workloads.

Examples include:

```text
EC2
Lambda
ECS
EKS
```

But these services don't give you the same level of control.

For example:

```text
EC2
↓
You manage the operating system

Lambda
↓
AWS manages the servers and OS
```

Therefore, your security responsibilities change depending on the compute service.

---

# 2. EC2 — More Customer Responsibility

**Amazon EC2** gives you a virtual server.

Think of it as:

```text
AWS Physical Infrastructure
        ↓
     EC2 VM
        ↓
Guest Operating System
        ↓
Your Application
```

### AWS is responsible for:

```text
AWS
│
├── Physical data centers
├── Physical servers
├── Physical networking
├── Hardware
└── Virtualization infrastructure
```

### Customer is responsible for:

```text
Customer
│
├── Guest operating system
├── OS configuration
├── OS patching
├── Applications
├── Application configuration
├── Data
└── Appropriate security configuration
```

### Example

You launch a Windows Server EC2 instance.

If Windows needs security patches, **you are generally responsible for patching the guest OS** because you're managing that OS.

AWS doesn't log into your Windows VM and manage your application for you.

---

# 3. Lambda — More AWS Responsibility

Now consider **AWS Lambda**.

With Lambda, you provide your function code and configuration.

You don't manage:

```text
Physical server
Operating system
Server hardware
Underlying infrastructure
```

AWS manages those underlying components.

Conceptually:

```text
             Lambda
                │
        ┌───────┴────────┐
        ↓                ↓
       AWS            Customer
        │                │
 Servers/OS          Function code
 Infrastructure      Configuration
                     Data/access
```

So compared with EC2:

```text
EC2
→ More customer responsibility

Lambda
→ More AWS responsibility
```

---

# 4. Why Is the Responsibility Different?

Because AWS manages different amounts of the infrastructure.

### EC2

You receive a virtual machine:

```text
AWS
 ↓
Virtual Machine
 ↓
You manage OS
 ↓
You manage application
```

### Lambda

You provide the function:

```text
AWS
 ↓
Infrastructure
 ↓
OS
 ↓
Runtime infrastructure
 ↓
Your function
```

AWS manages much more of the underlying environment.

---

# 5. EC2 vs Lambda

| Responsibility            | EC2          | Lambda       |
| ------------------------- | ------------ | ------------ |
| Physical hardware         | AWS          | AWS          |
| Data center               | AWS          | AWS          |
| Underlying infrastructure | AWS          | AWS          |
| Guest OS                  | **Customer** | **AWS**      |
| OS patching               | **Customer** | **AWS**      |
| Application/function code | **Customer** | **Customer** |
| Customer data             | **Customer** | **Customer** |
| IAM permissions           | **Customer** | **Customer** |
| Service configuration     | Customer     | Customer     |

The important exam idea isn't memorizing every row.

Remember:

> **EC2 gives you more control, so you have more responsibility.**

> **Lambda is more managed, so AWS takes more responsibility for the underlying environment.**

---

# 6. ECS and Containers

You can also encounter **Amazon ECS**.

ECS is a container orchestration service.

The responsibility depends on how you're running your containers.

For example, with **ECS on AWS Fargate**, AWS manages the underlying infrastructure needed to run the containers.

You focus more on:

```text
Customer
│
├── Container image
├── Application
├── Task definition
├── IAM
├── Network configuration
└── Data
```

AWS manages the underlying compute infrastructure.

This follows the same general principle:

> **More managed service → less infrastructure management for the customer.**

---

# 7. EKS

With **Amazon EKS**, AWS provides managed Kubernetes control-plane components, while your responsibility depends on the compute option and configuration you're using.

For example:

```text
EKS
│
├── AWS-managed control plane
│
└── Compute
    ├── EC2 → more customer responsibility
    └── Fargate → more AWS-managed infrastructure
```

For Cloud Practitioner, you don't need to go deeply into Kubernetes responsibility boundaries yet.

The key idea is:

> **Responsibility depends on the specific service and configuration.**

---

# 8. The Compute Responsibility Spectrum

A useful mental model is:

```text
More Customer Control
        ↓
        EC2
        │
        │
        ECS
        │
        │
      Fargate
        │
        │
      Lambda
        ↓
More AWS-Managed Infrastructure
```

This is a simplified learning model rather than a strict ranking of every responsibility.

As AWS manages more of the infrastructure:

```text
AWS manages more
        ↓
Customer manages less underlying infrastructure
```

---

# 9. Scenario-Based Example

Suppose your company has a Python application.

### Option 1 — EC2

You deploy:

```text
EC2
 ↓
Linux
 ↓
Python
 ↓
Application
```

You need to think about:

```text
OS patches
Security configuration
Application
Data
IAM
Networking
```

---

### Option 2 — Lambda

You deploy:

```text
Lambda
 ↓
Python function
```

You don't manage the underlying server or OS.

You focus more on:

```text
Function code
IAM permissions
Configuration
Application logic
Data
```

So the responsibility boundary changes.

---

# 10. How to Identify Responsibility in an Exam

When you see a compute question, ask:

### Question 1:

**What compute service is being used?**

```text
EC2?
Lambda?
ECS?
Fargate?
EKS?
```

### Question 2:

**Does the customer manage the OS?**

If yes:

→ Customer has OS-related responsibility.

If AWS manages the OS/infrastructure:

→ AWS takes that responsibility.

### Question 3:

**Is the question about physical infrastructure?**

→ Generally **AWS**

### Question 4:

**Is it about customer code, data, IAM, or configuration?**

→ Generally **Customer**

---

# 🎯 Common Cloud Practitioner Exam Questions

### Q: Who is responsible for patching the guest OS on an EC2 instance?

**Customer**

---

### Q: Who is responsible for physical security of the servers running EC2?

**AWS**

---

### Q: Who manages the underlying servers for Lambda?

**AWS**

---

### Q: Who is responsible for the Lambda function code?

**Customer**

---

### Q: Does using a managed compute service eliminate all customer security responsibilities?

**No.**

The customer still has responsibilities such as appropriate IAM, code, data, and configuration.

> **EC2 guest OS → Customer**
