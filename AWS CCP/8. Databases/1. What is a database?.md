# 🗄️ What Is a Database?

If you're moving from AWS storage into databases, the key distinction to keep in mind is this:

> **Storage gives you a place to keep data; a database gives your application a structured way to store, organize, search, update, and manage that data.**

---

## 1. Definition

A **database** is an organized collection of data that allows you to **store, manage, search, update, and retrieve information efficiently**.

For example, an online shopping application needs to keep track of:

```text
Customers
Products
Orders
Payments
Addresses
```

Instead of keeping all of this in unrelated files, the application can use a database.

---

# 2. Why Do We Need a Database?

Imagine an e-commerce application with **1 million customers**.

You might need to perform operations like:

```text
Find customer with ID 1052
Find all orders for customer 1052
Find products under ₹500
Update customer's address
Check whether an order has been paid
```

A database is built to handle these kinds of operations efficiently, especially as the amount of data and number of users grow.

---

# 3. What Kind of Data Can a Database Store?

A database can hold many types of application information:

```text
Customers
Products
Orders
Transactions
Employee records
Application data
Logs
Configurations
```

For example:

```text
Customer ID | Name   | Email
------------|--------|-------------------
101         | Rahul  | rahul@example.com
102         | Priya  | priya@example.com
103         | Amit   | amit@example.com
```

---

# 4. Database vs Normal File

You can store information in a normal file:

```text
customers.txt
```

But as your application grows, managing the data this way becomes difficult.

Imagine:

```text
1 million customers
100 million orders
```

You need efficient mechanisms for:

* Searching
* Updating
* Relationships between data
* Concurrent access
* Security
* Backup and recovery
* Data consistency

Databases provide mechanisms specifically designed for these requirements.

---

# 5. How Does an Application Use a Database?

A basic application architecture looks like this:

```text
              User
                ↓
          Application
                ↓
            Database
                ↓
              Data
```

For example, when you click **"My Orders"**:

```text
User
 ↓
Website
 ↓
Application
 ↓
Database query
 ↓
Orders returned
 ↓
Website displays orders
```

The application communicates with the database using database queries, APIs, drivers, or other database interfaces.

# 7. Main Types of Databases

At the Cloud Practitioner level, you should first understand two major categories:

```text
Databases
│
├── Relational
└── NoSQL
```

---

# 8. Relational Database

A **relational database** organizes data into **tables containing rows and columns**.

Example:

```text
CUSTOMERS

ID | Name   | Email
---|--------|----------------
1  | Rahul  | rahul@email.com
2  | Priya  | priya@email.com
3  | Amit   | amit@email.com
```

Relational databases commonly use **SQL — Structured Query Language**.

For example:

```sql
SELECT * FROM customers;
```

Common relational databases include:

* MySQL
* PostgreSQL
* Microsoft SQL Server
* Oracle Database
* Amazon RDS
* Amazon Aurora

---

# 9. NoSQL Database

**NoSQL** databases use data models other than the traditional relational table model.

For example, a document-oriented database might store:

```json
{
  "id": 101,
  "name": "Rahul",
  "email": "rahul@example.com"
}
```

NoSQL databases are often useful for workloads requiring **flexible schemas and/or large-scale distributed access**.

An important AWS example is:

> **Amazon DynamoDB**

---

# 10. Relational vs NoSQL

| Relational                | NoSQL                         |
| ------------------------- | ----------------------------- |
| Tables                    | Various non-relational models |
| Rows and columns          | Documents, key-value, etc.    |
| Usually structured schema | Often more flexible schema    |
| SQL commonly used         | Query mechanisms vary         |
| MySQL                     | DynamoDB                      |
| PostgreSQL                | MongoDB                       |

Don't think of one as universally better. The appropriate choice depends on what the application needs.

---

# 11. What Is a Database Management System?

A **Database Management System (DBMS)** is software used to create, manage, access, and control databases.

Conceptually:

```text
Application
     ↓
    DBMS
     ↓
  Database
```

Examples include:

```text
MySQL
PostgreSQL
Oracle
SQL Server
```

In AWS, managed database services can take care of much of the underlying database infrastructure for you.

---

# 12. Databases in AWS

AWS provides several database services.

### Amazon RDS

**Amazon Relational Database Service (RDS)** is a managed relational database service.

```text
Application
     ↓
Amazon RDS
     ↓
Relational Database
```

RDS supports database engines such as:

* PostgreSQL
* MySQL
* MariaDB
* Oracle
* SQL Server

### Amazon DynamoDB

A managed **NoSQL database**:

```text
Application
     ↓
DynamoDB
     ↓
NoSQL data
```

### Amazon Aurora

A cloud-optimized relational database engine compatible with **MySQL and PostgreSQL**.

---

# 13. Database vs Storage

Since you're studying **EBS, EFS, and S3**, this distinction is especially important.

### Storage

Storage primarily provides a place to **store data**.

```text
S3  → Objects
EBS → Blocks
EFS → Files
```

### Database

A database provides a system for applications to **store, organize, query, update, and manage application data**.

```text
Application
     ↓
Database
     ↓
Customers
Orders
Products
Transactions
```

So remember:

> **Storage = Where/how data is stored**

> **Database = How application data is organized and managed**

---

# 14. Scenario-Based Example

Suppose you're building an online shopping application.

You could have:

```text
                E-commerce App
                     │
          ┌──────────┴──────────┐
          ↓                     ↓
         S3                   RDS
          │                     │
   Product Images        Customers/Orders
   Videos                Products
   Documents             Transactions
```

### S3

Stores objects such as:

```text
shoe.jpg
phone.jpg
product-video.mp4
```

### RDS

Manages application records such as:

```text
Customers
Orders
Products
Payments
```

So the distinction is:

> **S3 stores objects, while a database manages application records and their relationships.**

# 🎯 Exam-Focused Points

### What is a database?

> **An organized collection of data that allows efficient storage, management, retrieval, and updating of information.**

### What is a relational database?

> **A database that organizes data into tables, rows, and columns; SQL is commonly used.**

### What is NoSQL?

> **A family of non-relational database models such as key-value and document databases.**

### AWS managed relational database service?

→ **Amazon RDS**

### AWS managed NoSQL database?

→ **Amazon DynamoDB**

### AWS object storage?

→ **Amazon S3**
