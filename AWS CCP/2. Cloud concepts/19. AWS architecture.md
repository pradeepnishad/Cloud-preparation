# ☁️ AWS Architecture

## 1. Definition

**AWS architecture** is the way you **design and organize AWS resources and services** so that an application can meet its requirements for **security, reliability, availability, scalability, performance, and cost**.

Simple definition:

> **AWS Architecture = How AWS services are arranged and connected to build an application or solution.**

It's not just about knowing individual services. It's about understanding **how they work together**.

---

# 2. What Is AWS Architecture?

Imagine you're building an e-commerce website.

You could use:

```text
                    Internet
                       ↓
                Route 53 (DNS)
                       ↓
                Load Balancer
                 ↙         ↘
             EC2-A        EC2-B
             AZ-1         AZ-2
                 ↘         ↙
                  Database
                    ↓
                   RDS
                    ↓
                Data/Backup
```

Each service has a specific responsibility.

For example:

* **Route 53** → DNS
* **Load Balancer** → distributes traffic
* **EC2** → application compute
* **RDS** → relational database
* **S3** → object storage
* **IAM** → access control
* **CloudWatch** → monitoring

The architecture describes **how all these components work together**.

---

# 3. Why Do We Need AWS Architecture?

A poorly designed application can have problems such as:

```text
Single server
    ↓
Server fails
    ↓
Application goes down
```

A better architecture introduces redundancy:

```text
             Load Balancer
              ↙        ↘
           EC2-A      EC2-B
           AZ-1       AZ-2
```

Now if one instance fails, the other can continue serving traffic.

Good architecture helps you achieve:

* 🔐 Security
* 🟢 High availability
* 🔄 Reliability
* 📈 Scalability
* ⚡ Performance
* 💰 Cost optimization
* 🔧 Operational efficiency

# 4. How to Design AWS Architecture

A typical process is:

### Step 1 — Understand requirements

Ask:

* How many users?
* What type of application?
* How much traffic?
* Is traffic predictable?
* How important is availability?
* What data needs protection?
* What are the compliance requirements?
* What is the budget?

---

### Step 2 — Select appropriate services

For example:

```text
Web application
      ↓
Compute → EC2
Storage → S3
Database → RDS
DNS → Route 53
Monitoring → CloudWatch
Access → IAM
```

---

### Step 3 — Connect the services

Design how users and services communicate.

```text
User
 ↓
Route 53
 ↓
Load Balancer
 ↓
EC2
 ↓
RDS
```

---

### Step 4 — Add security

Consider:

* IAM
* Security groups
* Network controls
* Encryption
* Access policies
* Logging and monitoring

---

### Step 5 — Design for failure

Don't depend on one component.

```text
        Load Balancer
          ↙       ↘
       AZ-1       AZ-2
        ↓           ↓
      EC2-A       EC2-B
```

---

### Step 6 — Design for changing demand

Use scalability and elasticity.

```text
Low traffic
    ↓
2 EC2

High traffic
    ↓
10 EC2

Low traffic again
    ↓
2 EC2
```

---

### Step 7 — Optimize costs

Consider:

* Right-sizing
* Auto Scaling
* Appropriate storage
* Managed services
* Pricing models
* Removing unused resources

---

# 5. When Do You Use AWS Architecture?

Basically, **whenever you're building a real solution on AWS**.

For example:

### Simple website

```text
User
 ↓
S3
 ↓
Website
```

### Dynamic web application

```text
User
 ↓
Load Balancer
 ↓
EC2
 ↓
RDS
```

### Highly available application

```text
              Load Balancer
               /         \
            AZ-1         AZ-2
             ↓             ↓
           EC2-A         EC2-B
               \         /
                  RDS
```

The architecture becomes more sophisticated as the requirements become more demanding.

# 6. Scenario-Based Example

Suppose you're building an online shopping platform.

Requirements:

* Thousands of users
* Traffic can suddenly increase
* Application should remain available if a server fails
* Customer data must be protected
* Costs should be controlled

You might design:

```text
                         USERS
                           │
                           ↓
                     Route 53
                           │
                           ↓
                  Application Load
                     Balancer
                    ↙       ↘
                  AZ-1      AZ-2
                   ↓          ↓
                 EC2        EC2
                   ↘          ↙
                     RDS
                       │
                       ↓
                      S3
```

Then add:

```text
IAM       → Access control
CloudWatch → Monitoring
Auto Scaling → Automatic scaling
Security Groups → Network-level instance security
Encryption → Data protection
```

Now you're not simply "using EC2 and RDS."

You're **architecting a complete AWS solution**.

# 7. AWS Well-Architected Framework

When you start learning AWS architecture more deeply, you'll encounter the **AWS Well-Architected Framework**.

It provides guidance for designing and reviewing cloud workloads.

The six pillars are:

| Pillar                     | Main focus                                  |
| -------------------------- | ------------------------------------------- |
| **Operational Excellence** | Run and improve systems effectively         |
| **Security**               | Protect systems and data                    |
| **Reliability**            | Recover from failures and meet requirements |
| **Performance Efficiency** | Use resources efficiently                   |
| **Cost Optimization**      | Avoid unnecessary costs                     |
| **Sustainability**         | Minimize environmental impact               |

### Memory:

**O-S-R-P-C-S**

> **Operational Excellence → Security → Reliability → Performance → Cost → Sustainability**

You'll encounter these heavily when you move into **Solutions Architect** material.

# 8. AWS Architecture vs AWS Services

This distinction is important.

### AWS Service

A single building block:

> **EC2 = compute**

### AWS Architecture

How multiple building blocks work together:

```text
Route 53
   ↓
Load Balancer
   ↓
EC2
   ↓
RDS
   ↓
S3
```

So:

> **Learning services = learning the building blocks.**

> **Learning architecture = learning how to combine those building blocks to solve problems.**
