# ☁️ Right-Sized Infrastructure

## 1. Definition

**Right-sizing** means selecting and configuring cloud resources so that their **capacity matches the actual workload requirements**.

In simple words:

> **Use the right amount of computing resources for the workload—not too much and not too little.**

For example, if an application only needs 2 vCPUs and 4 GB RAM, using a server with 16 vCPUs and 64 GB RAM may be unnecessary and increase costs.

---

## 2. What is Right-Sized Infrastructure?

Infrastructure can be **over-provisioned** or **under-provisioned**.

### Over-provisioned

You allocate more resources than the application needs.

```text
Required:
2 vCPU + 4 GB RAM

Allocated:
8 vCPU + 32 GB RAM

        ↓
Unused capacity
        ↓
💰 Wasted money
```

### Under-provisioned

You allocate too few resources.

```text
Required:
8 vCPU + 16 GB RAM

Allocated:
2 vCPU + 4 GB RAM

        ↓
Poor performance
        ↓
Possible downtime/errors
```

### Right-sized

```text
Workload requirements
        ↓
Analyze usage
        ↓
Choose suitable resource
        ↓
Good performance + efficient cost
```

---

# 3. Why Use Right-Sized Infrastructure?

The main reason is **cost optimization**.

If you choose resources that are larger than necessary, you're paying for unused capacity.

Right-sizing helps you:

* Reduce unnecessary cloud costs
* Improve resource utilization
* Avoid over-provisioning
* Maintain appropriate performance
* Make infrastructure more efficient

The important balance is:

> **Don't optimize cost so aggressively that you hurt application performance.**

---

# 4. How to Right-Size Infrastructure

A typical process looks like this:

```text
1. Deploy resource
       ↓
2. Monitor usage
       ↓
3. Analyze CPU / RAM / Network / Storage
       ↓
4. Compare actual usage with allocated capacity
       ↓
5. Resize if necessary
       ↓
6. Monitor again
```

For example:

Your EC2 instance has:

```text
8 vCPU
32 GB RAM
```

But after monitoring for several weeks:

```text
CPU usage → 10–15%
RAM usage → 20%
```

You may determine that a smaller instance is sufficient.

---

# 5. What Should You Analyze?

Right-sizing isn't just about CPU.

Look at:

### Compute

* CPU utilization
* Memory utilization
* Number of instances
* Instance type

### Storage

* Storage capacity
* Storage performance
* How frequently data is accessed

### Network

* Network throughput
* Data transfer requirements

### Application workload

* Number of users
* Requests per second
* Traffic patterns
* Peak usage

You want to understand the **actual workload**, rather than guessing.

---

# 6. When Should You Use Right-Sizing?

Right-sizing is especially useful when:

* You migrated an existing application to AWS
* Your workload has changed
* Resources are consistently underutilized
* You discover oversized EC2 instances
* Your AWS bill is unexpectedly high
* You have long-running workloads
* Development/test environments are oversized

It should also be performed **continuously**, because workloads change over time.

# 7. Scenario-Based Example

Imagine a company runs a web application on:

```text
EC2 Instance
8 vCPU
32 GB RAM
```

They monitor it for a month.

Average usage:

```text
CPU → 15%
RAM → 25%
```

The infrastructure is clearly using only a small portion of its available capacity.

The company evaluates a smaller instance:

```text
4 vCPU
16 GB RAM
```

If testing shows that the smaller instance still provides the required performance:

```text
8 vCPU / 32 GB
       ↓
Right-size
       ↓
4 vCPU / 16 GB
       ↓
Lower infrastructure cost
```

However, if the workload later grows significantly, they can scale up or scale out.

---

# 8. Right-Sizing vs Scalability vs Elasticity

These concepts are related but **not the same**.

| Concept               | Meaning                                        |
| --------------------- | ---------------------------------------------- |
| **Right-sizing**      | Choose the appropriate resource size           |
| **Scalability**       | Ability to increase/decrease capacity          |
| **Elasticity**        | Dynamically adjust resources as demand changes |
| **Capacity planning** | Estimate how much capacity will be needed      |

### Easy example:

```text
Right-sizing
→ "Should I use a 2 vCPU or 4 vCPU instance?"

Scalability
→ "Can I increase from 2 to 4 instances?"

Elasticity
→ "Can instances automatically increase during a traffic spike
   and decrease afterward?"

Capacity planning
→ "How much capacity will I need next year?"
```

---

# 9. Exam Perspective 🎯

Watch for phrases such as:

* **"Resource is underutilized"**
* **"Instance is larger than required"**
* **"Reduce unnecessary cloud spending"**
* **"Optimize resource utilization"**
* **"Choose an appropriately sized instance"**
* **"Analyze utilization and select a smaller instance"**

These strongly point toward **right-sizing**.

### Exam trap

If the question says:

> "Automatically add or remove resources based on demand."

That's **elasticity**, not right-sizing.

If it says:

> "The EC2 instance is consistently underutilized and the company wants to reduce costs."

That's **right-sizing**.
