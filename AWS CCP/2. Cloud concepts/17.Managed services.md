# ☁️ Managed Services in AWS

## 1. Definition

**Managed services** are cloud services where **AWS manages much of the underlying infrastructure and operational work for you**, allowing you to focus more on your application and business.

Simple definition:

> **Managed service = AWS takes care of the infrastructure/maintenance so you don't have to manage everything yourself.**

For example, with **Amazon RDS**, you don't have to manually manage the physical database server, operating system maintenance, and many routine database administration tasks.

---

# 2. What Does "Managed" Mean?

Compare running a database yourself with using a managed database service.

### Self-managed

```text
You
 ↓
Physical/Virtual Server
 ↓
Operating System
 ↓
Database Installation
 ↓
Patching
 ↓
Backups
 ↓
Database
 ↓
Application
```

You are responsible for many of these tasks.

### Managed service

```text
You
 ↓
AWS Managed Database Service
 ↓
Database
 ↓
Application
```

AWS handles much of the underlying infrastructure and routine management.

**Important:** Managed does **not** mean AWS manages absolutely everything. You still have responsibilities depending on the service and configuration.

---

# 3. Why Use Managed Services?

### ① Focus on Your Business

Instead of spending time managing infrastructure:

```text
Infrastructure maintenance
        ↓
AWS handles much of it
        ↓
You focus on
Application + Customers + Business
```

This connects directly to the AWS benefit:

> **Focus on your business**

---

### ② Reduce Operational Overhead

You don't need to perform every infrastructure task manually.

For example, with a managed database, AWS can handle many routine activities such as:

* Infrastructure provisioning
* Hardware maintenance
* Software patching
* Backups
* Monitoring/maintenance capabilities

depending on the service.

---

### ③ Faster Deployment

Managed services can allow you to provision capabilities quickly.

For example:

```text
Need database
     ↓
Create RDS database
     ↓
Configure required settings
     ↓
Database available
```

Instead of:

```text
Buy server
 ↓
Install OS
 ↓
Configure server
 ↓
Install database
 ↓
Configure database
 ↓
Configure backups
 ↓
Maintain server
```

---

### ④ Reduce Undifferentiated Heavy Lifting

This is an **important AWS exam concept**.

**Undifferentiated heavy lifting** means spending time on infrastructure tasks that don't directly differentiate your business.

For example:

> A food-delivery company's competitive advantage is its ordering, delivery, and customer experience—not maintaining physical database servers.

Using managed services lets the company spend more time on its actual application.

---

# 4. How to Use Managed Services

Instead of building and managing infrastructure yourself, select an AWS service that provides the capability you need.

### Example: Database

Instead of:

```text
EC2
 ↓
Install MySQL
 ↓
Configure
 ↓
Patch
 ↓
Backup
 ↓
Maintain
```

You could use:

```text
Application
     ↓
Amazon RDS
     ↓
AWS manages much of the underlying infrastructure
```

Other examples:

| Requirement          | AWS managed service example |
| -------------------- | --------------------------- |
| Relational database  | Amazon RDS                  |
| Object storage       | Amazon S3                   |
| Serverless functions | AWS Lambda                  |
| Message queue        | Amazon SQS                  |
| DNS                  | Amazon Route 53             |
| Monitoring           | Amazon CloudWatch           |

The level of management differs between services.

---

# 5. When Should You Use Managed Services?

Use managed services when you want to:

* Reduce infrastructure management
* Reduce operational overhead
* Deploy faster
* Focus on application development
* Avoid maintaining physical infrastructure
* Automate routine maintenance
* Scale without managing everything manually

They're particularly useful when infrastructure management isn't part of your company's core value.

Your team needs a relational database for:

```text

Delivery information
```

Your team is responsible for many operational tasks:

```text

 ↓

 ↓
MySQL
 ↓
Patching
 ↓
Backups
 ↓

```

Your developers now spend significant time maintaining the database infrastructure.

### Option 2 — Managed service

Use **Amazon RDS**:

```text
Food Delivery App
        ↓
```

# 7. Managed Services vs Self-Managed

| Self-Managed               | Managed Service                 |
| -------------------------- | ------------------------------- |
| More control               | Less infrastructure control     |
| More administration        | Less administration             |
| More maintenance           | Less maintenance                |
| More operational work      | Reduced operational work        |
| More responsibility        | AWS handles more infrastructure |
| Can require more expertise | Easier operationally            |

### Important trade-off

Managed services generally give you **less control over the underlying infrastructure**, but in return you get **less operational responsibility**.

---

# 8. Managed Services and Cost

Managed services can help reduce costs, but don't assume:

> **Managed = always cheaper.**

There are two types of cost to consider:

```text
Infrastructure cost
        +
Operational/management cost
        ↓
Total cost
```

A managed service might cost more directly than running software yourself on an EC2 instance, but it can reduce:

* Administration effort
* Maintenance work
* Infrastructure management
* Operational overhead
* Time spent on routine tasks

So you should consider **TCO (Total Cost of Ownership)** rather than only the service price.

---

# 9. Managed Services vs Serverless

These concepts are related but **not identical**.

### Managed service

AWS manages much of the underlying infrastructure.

Example:

> Amazon RDS

You still interact with and configure the database.

### Serverless

You don't manage servers or server capacity directly.

Example:

> AWS Lambda

You provide your code, and AWS handles the underlying compute infrastructure.

So:

> **Serverless services are highly managed, but not every managed service is serverless.**
