# ☁️ Capacity Planning in Cloud

## 1. What is Capacity Planning?

### Definition

**Capacity planning** is the process of determining **how much computing infrastructure and resources are required to handle an application's current and expected future workload**.

In simple words:

> **Capacity Planning = Predict how much infrastructure you will need and make sure you have enough capacity to handle the workload.**

Capacity can include:

* CPU
* Memory
* Storage
* Network bandwidth
* Database capacity
* Number of servers/instances

---

# 2. Why Do We Need Capacity Planning?

Every application needs resources to operate.

The problem is that **demand changes over time**.

For example:

```text
Normal day       → 1,000 users
Weekend          → 5,000 users
Festival sale    → 100,000 users
```

You need to make sure your infrastructure can handle these changes.

If you **underestimate** capacity:

```text
Demand ↑
   ↓
Not enough resources
   ↓
Slow application
   ↓
Possible downtime ❌
```

If you **overestimate** capacity:

```text
Too many resources
       ↓
Resources remain unused
       ↓
Unnecessary cost 💰
```

So capacity planning tries to find the right balance.

---

# 3. Capacity Planning in Traditional IT

Capacity planning is particularly challenging with physical infrastructure.

Imagine a company wants to build an e-commerce website.

They estimate:

> "We might need 20 servers next year."

So they purchase 20 physical servers.

```text
Expected demand
      ↓
Estimate capacity
      ↓
Buy hardware
      ↓
Install & configure
      ↓
Use infrastructure
```

But there are two possibilities.

### Scenario A — Demand is lower

```text
20 servers purchased
       ↓
Only 8 needed
       ↓
12 servers underutilized
       ↓
Wasted investment 💸
```

### Scenario B — Demand is higher

```text
20 servers purchased
       ↓
Need 40 servers
       ↓
20 additional servers required
       ↓
Purchase + installation delay
```

This is why traditional capacity planning can be difficult.

---

# 4. Capacity Planning in Cloud

Cloud computing changes the way we approach capacity.

Instead of purchasing all infrastructure upfront, you can:

```text
Estimate requirement
       ↓
Provision resources
       ↓
Monitor actual workload
       ↓
Adjust capacity
       ↓
Scale when required
```

You still need to **plan**, but you don't necessarily need to permanently purchase infrastructure for your maximum expected demand.

---

# 5. How Do We Perform Capacity Planning?

A basic capacity-planning process looks like this:

```text
             Capacity Planning
                    ↓
        ┌───────────┴───────────┐
        ↓                       ↓
 Understand workload       Predict demand
        ↓                       ↓
 Current usage          Future requirements
        └───────────┬───────────┘
                    ↓
             Select resources
                    ↓
             Deploy resources
                    ↓
                Monitor
                    ↓
            Adjust capacity
```

Let's break this down.

---

## Step 1 — Understand Current Workload

First, understand what your application currently requires.

You might look at:

* CPU usage
* Memory usage
* Storage usage
* Network traffic
* Number of users
* Requests per second
* Database workload

Example:

```text
Current workload:

CPU     → 40%
Memory  → 60%
Storage → 500 GB
Traffic → 10,000 requests/hour
```

---

# 6. Step 2 — Predict Future Demand

Now ask:

> **"How much workload will we have in the future?"**

For example:

```text
Today       → 10,000 users
Next month  → 20,000 users
Next year   → 100,000 users
```

You need to consider:

* Business growth
* Seasonal traffic
* Marketing campaigns
* Product launches
* Special events
* Expected user growth

---

# 7. Step 3 — Choose Appropriate Capacity

Based on the expected workload, you select appropriate resources.

For example:

```text
Small workload
     ↓
Small compute resources

Large workload
     ↓
Larger/more compute resources
```

You might choose:

* EC2 instance types
* Storage capacity
* Database capacity
* Network capacity

---

# 8. Step 4 — Monitor Actual Usage

Your prediction won't always be perfect.

That's why you monitor the real workload.

For example:

```text
Expected CPU → 50%

Actual CPU → 85%
```

You might need more capacity.

Or:

```text
Expected CPU → 50%

Actual CPU → 15%
```

You may have over-provisioned.

---

# 9. Step 5 — Adjust Capacity

After monitoring, you adjust your infrastructure.

```text
Demand ↑
   ↓
Increase capacity
```

or:

```text
Demand ↓
   ↓
Decrease capacity
```

This is where **scalability and elasticity** become extremely useful.

---

# 10. Capacity Planning vs Scalability

These concepts are related but different.

### 📊 Capacity Planning

> **How much capacity will I need?**

It focuses on **planning and forecasting**.

### 📈 Scalability

> **Can my system increase/decrease its capacity?**

It focuses on the system's **ability to change capacity**.

### 🔄 Elasticity

> **Can resources dynamically adjust to changing demand?**

It focuses on **dynamic/automatic adjustment**.

### Example

Imagine an e-commerce company expects a festival sale.

**Capacity planning:**

> "We expect traffic to increase 10×."

**Scalability:**

> "Our architecture can increase from 5 to 50 instances."

**Elasticity:**

> "The infrastructure automatically scales up during the traffic spike and scales back down afterward."

---

# 11. 🧪 Real-World Scenario

Imagine you operate a **college examination portal**.

### Normal days

```text
Users = 1,000
Servers = 2
```

### During result publication

```text
Users = 100,000
```

Capacity planning asks:

> "How much infrastructure should we prepare for result day?"

You analyze historical data and estimate the expected traffic.

You might decide that the architecture needs enough capacity to handle a large spike.

Then you use scalable infrastructure.

```text
Normal
  ↓
2 instances

Result day
  ↓
More instances

After result day
  ↓
Reduce capacity
```

### What happened?

**Capacity planning** helped determine the expected requirement.

**Scalability** allowed capacity to increase.

**Elasticity** can automate the adjustment.

---

# 12. What Happens Without Capacity Planning?

Imagine a company doesn't plan capacity at all.

```text
Traffic suddenly increases
          ↓
Infrastructure insufficient
          ↓
CPU reaches 100%
          ↓
Application slows
          ↓
Users experience problems ❌
```

Or the opposite:

```text
Company predicts huge demand
          ↓
Purchases excessive infrastructure
          ↓
Actual demand is low
          ↓
Resources remain unused
          ↓
Higher costs 💸
```

So capacity planning helps avoid both:

> **Under-provisioning** and **over-provisioning**.

---

# 13. Capacity Planning in Cloud Doesn't Mean Perfect Prediction

This is an important concept.

Cloud doesn't completely eliminate capacity planning.

You still need to understand:

* Expected workload
* Resource requirements
* Growth
* Performance requirements
* Cost

But cloud makes it easier to **adjust when your prediction is wrong**.

Think:

```text
Traditional IT
Plan → Buy → Fixed capacity

Cloud
Plan → Provision → Monitor → Adjust → Scale
```

That's one of the major benefits of cloud infrastructure.

# 📋 Final Summary

| Concept                | Meaning                                                       |
| ---------------------- | ------------------------------------------------------------- |
| **Capacity Planning**  | Determining how much infrastructure/resources are required    |
| **Main goal**          | Have enough capacity without excessive unused resources       |
| **Under-provisioning** | Not enough resources → performance/availability problems      |
| **Over-provisioning**  | Too many resources → unnecessary cost                         |
| **Cloud advantage**    | Easier to adjust capacity when predictions change             |
| **Scalability**        | Ability to increase/decrease capacity                         |
| **Elasticity**         | Dynamically/automatically adjust capacity according to demand |

### 🔥 One-line memory

> **Capacity Planning = Predict how much capacity you need; Scalability = ability to change it; Elasticity = dynamically adjust it as demand changes.**

### 🎯 Think of it as:

**Plan → Provision → Monitor → Adjust → Scale**

That's the complete picture of **capacity planning in the cloud**.
