# 💰 Pay-As-You-Go Pricing

## 1. What is Pay-As-You-Go?

### Definition

**Pay-As-You-Go (PAYG)** is a cloud pricing model where you **pay for the AWS resources and services you actually consume**, rather than making a large upfront investment in physical infrastructure.

In simple words:

> **Use resources → Pay for usage. Stop using resources → Stop paying for that usage.**

It is similar to paying for electricity:


More electricity used → Higher bill
Less electricity used  → Lower bill


Cloud computing follows a similar idea.

---

# 2. Why Do We Use Pay-As-You-Go?

In traditional IT, companies often have to purchase infrastructure **before they know exactly how much they will need**.

For example:


Company
  ↓
Buy 10 servers
  ↓
Pay upfront
  ↓
Install & maintain
  ↓
Use them


But what if the company only needs 4 servers?


10 servers purchased
↓
Only 4 actually used
↓
6 servers sitting idle
↓
Money wasted 💸


With AWS, you can provision resources according to your requirements and pay based on usage.

---

# 3. How Does Pay-As-You-Go Work?

The basic model is:


Choose AWS service
       ↓
Provision resource
       ↓
Use resource
       ↓
AWS measures usage
       ↓
You are charged according to pricing


For example, suppose you create an EC2 instance.


EC2 instance
     ↓
Run it for some period
     ↓
Usage is measured
     ↓
You are charged according to the applicable pricing


If you no longer need it and terminate it, you generally stop incurring the corresponding instance running charges.

⚠️ **Important:** Terminating one resource doesn't necessarily eliminate all charges. Other resources such as storage, snapshots, IP-related resources, databases, or data transfer can have separate charges.

---

# 4. What Can You Pay For?

AWS has many different services, and their pricing models can differ.

Depending on the service, you may pay based on things such as:

* Compute usage
* Storage consumed
* Number of requests
* Database capacity/usage
* Data transfer
* Other service-specific metrics

So don't think:

> "AWS charges me only for the number of servers."

Instead:

> **AWS pricing depends on the service and the amount/type of resources you consume.**

# 7. 💡 Pay-As-You-Go and Elasticity

These concepts work very well together.

### Elasticity

> Resources dynamically increase/decrease according to demand.

### Pay-As-You-Go

> You pay according to the resources/services you consume.

Together:


Demand ↑
   ↓
Resources ↑
   ↓
Usage ↑
   ↓
Cost ↑

Demand ↓
   ↓
Resources ↓
   ↓
Usage ↓
   ↓
Cost ↓


This allows infrastructure and spending to better match workload requirements.

# 8. Pay-As-You-Go vs Traditional IT

| Traditional IT                         | AWS Pay-As-You-Go                                       |
| -------------------------------------- | ------------------------------------------------------- |
| Large upfront investment               | Lower upfront infrastructure investment                 |
| Purchase hardware                      | Provision cloud resources                               |
| Own physical infrastructure            | Use AWS infrastructure                                  |
| Capacity must often be planned ahead   | Resources can be provisioned as needed                  |
| Hardware can remain unused             | Resources can be created/removed as requirements change |
| Maintenance of physical infrastructure | AWS manages the underlying physical infrastructure      |

---

# 9. When Should We Use Pay-As-You-Go?

It is especially useful when:

### 🧪 Experimenting

You need infrastructure temporarily.


Create → Test → Delete


### 🚀 Starting a business

You don't want to purchase a large amount of infrastructure before knowing your actual requirements.

### 📈 Unpredictable workloads

You don't know how much capacity you'll need.

### 🌱 Growing applications

Your infrastructure requirements increase as your users increase.

### 💻 Development and testing

You can create environments when required and remove them afterward.

---

# 10. Important: Pay-As-You-Go Does NOT Mean Free

This is an important exam and practical point.

**Pay-as-you-go ≠ free**

It means:

> **You pay based on usage rather than paying a large upfront infrastructure cost.**

For example:


Use more resources
       ↓
More usage
       ↓
Higher bill


So AWS cost management is still important.

---

# 11. ⚠️ Example of Unexpected Cost

Suppose you create an EC2 instance for testing.

You finish testing but forget to stop/terminate it.


Day 1 → Running
Day 2 → Running
Day 3 → Running
Day 4 → Running
...


You may continue accumulating charges.

That's why you should:

* Remove resources you no longer need
* Monitor usage
* Set budgets/alerts where appropriate
* Understand the pricing model of each service

# 🎯 Don't Confuse These Concepts

### 💰 Pay-As-You-Go

**How you pay**

> Pay according to usage.

### 📈 Scalability

**How capacity changes**

> Increase/decrease capacity to handle workload.

### 🔄 Elasticity

**How dynamically capacity follows demand**

> Automatically/dynamically scale resources up and down.

### ⚡ Agility

**How quickly you can respond**

> Quickly provision and change infrastructure.

### 🟢 Availability

**Whether the system remains accessible**

> Keep applications running despite failures.
