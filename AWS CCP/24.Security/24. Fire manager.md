# 🧾 AWS Audit Manager

### What is AWS Audit Manager?

**AWS Audit Manager continuously audits your AWS usage to simplify risk and compliance assessment.**

Think:

> **Audit Manager = Collect evidence → Assess compliance → Generate report**

---

## 1. 📚 Framework Library

The **Framework Library** contains frameworks based on different **compliance standards**.

You can browse frameworks that support standards such as:

- **PCI**
- **CIS**
- **SOC 2**
- **HIPAA**
- And others

### Simple example

Suppose your company needs to demonstrate compliance with **PCI**.

You can find a PCI-related framework in the Framework Library and use its controls to perform your assessment.

---

## 2. 🎛️ Control Library

The **Control Library** contains controls that you can use for your assessments.

You can:

- Browse existing controls
- Create your **own controls**
- Use controls in a **custom framework**

### Framework vs Control

Think of it like this:

**Framework = Collection/structure of controls**

**Control = Individual compliance check**

Example:

> PCI Framework  
> ↓  
> Control 1  
> Control 2  
> Control 3  
> Control 4

---

## 3. 📝 Assessments

You can create **assessments** to:

- Review the evidence collected
- Evaluate compliance
- Generate an **assessment report**

So:

**Assessment → Review evidence → Generate report**

---

## 4. 📥 Evidence Collection

One of the important points from the slide:

> Audit Manager can **continuously collect evidence**.

It can directly integrate with:

- **AWS Config**
- **AWS Security Hub**

This evidence can then be used during your compliance assessment.

### Example

Imagine your company needs to prove that certain security controls are being followed.

Audit Manager can continuously collect relevant evidence instead of requiring someone to manually gather everything every time an audit occurs.

---

# 🧠 Exam-focused distinction

| Service | Main purpose |
|---|---|
| **AWS Audit Manager** | 📋 Audit & compliance evidence |
| **AWS Security Hub** | 🛡️ Security posture & findings |
| **AWS Config** | ⚙️ Resource configuration/compliance |
| **AWS Artifact** | 📄 Access AWS compliance reports |
| **AWS Inspector** | 🔍 Vulnerability/security assessment |
| **GuardDuty** | 🚨 Threat detection |

### ⭐ Most important distinction

**AWS Artifact vs Audit Manager**

**Artifact** → *"Show me AWS's compliance documents/reports."*

**Audit Manager** → *"Help me continuously collect evidence about my AWS environment for my own audits/compliance assessments."*

# 🔥 AWS Firewall Manager

### What is AWS Firewall Manager?

**AWS Firewall Manager allows you to centrally configure and manage firewall rules across accounts and applications.**

The key word is:

> **CENTRALLY** 🎯

It's particularly useful when you have **multiple AWS accounts** and want to manage security/firewall policies from one place.

---

## 1. 🧱 What can Firewall Manager manage?

According to the slide, Firewall Manager can manage:

- **AWS WAF**
- **AWS WAF Classic**
- **AWS Shield Advanced**
- **Security Groups**
- **Network Access Controls**
- **AWS Network Firewall**
- **Amazon Route 53 Resolver DNS Firewall**
- **Third-party firewall services**

So instead of configuring firewall policies individually across many accounts, Firewall Manager lets you manage them centrally.

---

# 2. 🏢 AWS Organizations

One important prerequisite shown in the slide:

> Your account must be a **member of AWS Organizations**.

This makes sense because Firewall Manager is designed for centrally managing security policies across multiple AWS accounts.

### Think:

```text
AWS Organization
       │
       ├── Account A
       ├── Account B
       ├── Account C
       └── Account D
             ↑
      Firewall Manager
      Central policies
```

---

# 3. ⚙️ AWS Config is required

The slide specifically says:

> **AWS Config must be enabled for your accounts and Regions.**

So remember:

**Firewall Manager → requires AWS Config**

---

# 4. 🔗 AWS RAM

Another prerequisite shown:

> **AWS Resource Access Manager (RAM)** may need to be enabled for specific services.

The slide gives examples:

- AWS Network Firewall
- Route 53 Resolver DNS Firewall

So for certain Firewall Manager-managed services:

**Firewall Manager + RAM**

---

# 5. 🛡️ Security Group Policies

The screenshot at the bottom shows that Firewall Manager can apply policies to **security groups**.

For example, you can create policies that:

- Identify/report when security groups become **non-compliant**
- Disassociate other security groups from resources within the policy scope
- Distribute tags from a primary security group
- Distribute security-group references

The exact policy options depend on the targeted AWS service.

---

# 🎯 Why would you use Firewall Manager?

Imagine a company has:

**50 AWS accounts**

Without Firewall Manager:

```text
Account 1 → Configure WAF
Account 2 → Configure WAF
Account 3 → Configure WAF
...
Account 50 → Configure WAF
```

That's difficult to maintain.

With Firewall Manager:

```text
             Firewall Manager
                    │
          Central security policy
                    │
       ┌────────────┼────────────┐
       ↓            ↓            ↓
   Account 1    Account 2    Account 3
       ↓            ↓            ↓
      WAF          WAF          WAF
```

You manage the policy **centrally**.
