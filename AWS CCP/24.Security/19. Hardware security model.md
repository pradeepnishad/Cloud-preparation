# 🔐 Hardware Security Module (HSM)

Based on your slide, here's the **AWS Practitioner exam-focused breakdown**.

## 1. What is an HSM?

**HSM = Hardware Security Module**

An HSM is a **physical hardware device designed to securely store encryption keys**.

The key point from the slide:

> **HSMs hold encryption keys in memory and never write them to disk.**

Think of it as a highly protected hardware vault for cryptographic keys.

```text
Application
    ↓
   HSM
 ┌───────────────┐
 │ Encryption    │
 │ Keys          │
 │ 🔐 🔐 🔐      │
 └───────────────┘
```

---

## 2. Why use an HSM?

The primary purpose is **protecting cryptographic keys**.

Instead of keeping important encryption keys in ordinary storage:

```text
Encryption Key
      ↓
   🔐 HSM
      ↓
Protected key material
```

The HSM is specifically designed to provide stronger protection for those keys.

---

# 3. FIPS

Your slide introduces **FIPS**:

### FIPS = Federal Information Processing Standard

It is a **US and Canadian government standard** that specifies security requirements for cryptographic modules that protect sensitive information.

For your exam, associate:

> **FIPS → Cryptographic security requirements**

---

# 4. Multi-tenant HSM

Your slide says:

> **Multi-tenant HSMs → FIPS 140-2 Level 2 Compliant**

### What does multi-tenant mean?

Multiple customers share the same physical HSM, while being **virtually isolated** from one another.

```text
             Physical HSM
        ┌─────────────────────┐
        │ Customer A 🔐       │
        │ Customer B 🔐       │
        │ Customer C 🔐       │
        └─────────────────────┘
          Virtual isolation
```

### Example from the slide:

**AWS KMS**

So remember:

**Multi-tenant → AWS KMS → FIPS 140-2 Level 2**

---

# 5. Single-tenant HSM

Your slide says:

> **Single-tenant HSMs → FIPS 140-2 Level 3 Compliant**

### What does single-tenant mean?

A **single customer gets a dedicated HSM**.

```text
          Dedicated HSM
       ┌─────────────────┐
       │ Customer 🔐     │
       │                 │
       │ Keys            │
       └─────────────────┘
```

### Example from the slide:

**AWS CloudHSM**

So:

**Single-tenant → AWS CloudHSM → FIPS 140-2 Level 3**

---

# 🆚 AWS KMS vs AWS CloudHSM

This is the **most important part to remember from this slide**.

| | AWS KMS | AWS CloudHSM |
|---|---|---|
| HSM model in slide | **Multi-tenant** | **Single-tenant** |
| Isolation | Virtual | Dedicated |
| FIPS level shown | **140-2 Level 2** | **140-2 Level 3** |
| Main idea | Managed key management | Dedicated HSM |

### 🧠 Memory trick

> **KMS = shared HSM infrastructure**  
> **CloudHSM = dedicated HSM**

Or:

> **KMS → Level 2 → Multi**  
> **CloudHSM → Level 3 → Single**

## 🎯 Exam traps

If the question says:

**"FIPS 140-2 Level 3"**
