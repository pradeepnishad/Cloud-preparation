# 🛡️ AWS WAF — Web Application Firewall

### What is AWS WAF?

**AWS WAF (Web Application Firewall)** protects your **web applications from common web exploits and malicious HTTP/HTTPS traffic**.

Think:

> **WAF = Filter incoming web requests and decide ALLOW or DENY.**

It works mainly at the **application layer (Layer 7)**.

---

## 1. What does WAF actually do?

When a user sends an HTTP request:

```text
User
  ↓
HTTP/HTTPS Request
  ↓
AWS WAF
  ↓
ALLOW or DENY
  ↓
Your Application
```

WAF examines the **contents of HTTP requests** and applies rules.

For example:

```text
User → "GET /login"
           ↓
         WAF
           ↓
      Is this request
       suspicious?
       ↙       ↘
     YES        NO
      ↓          ↓
    DENY       ALLOW
```

---

# 2. WAF Rules

You can create your own rules to:

### ✅ ALLOW traffic
Allow requests matching certain conditions.

### ❌ DENY traffic
Block requests matching suspicious conditions.

Rules can inspect things such as:

- IP addresses
- HTTP headers
- Request methods
- Query strings
- Request body
- URI paths
- Request contents

The important exam phrase from your slide is:

> **ALLOW or DENY traffic based on the contents of an HTTP request.**

---

# 3. WAF Rule Sets

You don't necessarily have to create every security rule yourself.

You can use a **ruleset from a trusted AWS Security Partner** through the **AWS WAF Rules Marketplace**.

So:

```text
Your Application
       ↓
     AWS WAF
       ↓
 ┌───────────────┐
 │ Your Rules    │
 │      OR       │
 │ Marketplace   │
 │ Rulesets      │
 └───────────────┘
```

# 🧠 WAF vs AWS Shield

This is **very important for the exam**.

| Service | Main Purpose |
|---|---|
| **AWS WAF** | Protect web applications from malicious HTTP/HTTPS requests |
| **AWS Shield** | Protect against DDoS attacks |
| **AWS GuardDuty** | Detect suspicious/malicious activity |
| **AWS Inspector** | Find vulnerabilities/security issues in workloads |

### Remember:

**WAF → Web attacks**

**Shield → DDoS**

**GuardDuty → Threat detection**

**Inspector → Vulnerability assessment**

---

# 🔥 WAF vs Shield example

Suppose an attacker sends:

```text
10 million requests
       ↓
    Your website
```

That's primarily a **DDoS problem** → **AWS Shield**.

But suppose someone sends:

```text
Malicious HTTP request
        ↓
SQL injection attempt
        ↓
Your web application
```

That's a **web application attack** → **AWS WAF**.

In practice, they can work **together**.

```text
Internet
   ↓
CloudFront / ALB
   ↓
AWS Shield
   ↓
AWS WAF
   ↓
Application
```
