# 🐛 Vulnerabilities

## 🔹 WHAT?

A **vulnerability** is a **hole or weakness in an application** that can allow an attacker to cause harm to the application's stakeholders.

According to the slide, a vulnerability can be:

- A **design flaw**
- An **implementation bug**

### Simple example

```text
Application
     ↓
Weakness / Vulnerability
     ↓
Attacker exploits it
     ↓
Potential harm
```

So remember:

> **Vulnerability = A weakness that an attacker can exploit.**

---

# 🔹 WHERE?

Vulnerabilities can exist at different parts of an application:

- Application code
- Input validation
- Authentication & authorization
- Memory management
- File handling
- Network communication
- Cryptography
- Error handling
- Third-party components
- Session management
- Configuration

The slide lists many examples of vulnerabilities.

---

# 🔹 HOW?

An attacker can exploit a vulnerability when the application doesn't properly handle a particular situation.

For example:

```text
User Input
    ↓
Application doesn't validate input properly
    ↓
Unexpected/malicious input
    ↓
Application behaves incorrectly
    ↓
Attacker may cause harm
```

This is why **secure design, proper validation, access control, error handling, and secure coding practices** are important.

---

# 🔐 IMPORTANT VULNERABILITIES FROM THE SLIDE

## 1️⃣ Buffer Overflow

A **buffer overflow** occurs when a program writes more data into a memory buffer than it was designed to hold.

```text
Buffer capacity: 10 bytes

Input: 20 bytes
        ↓
[10 bytes][Extra data]
              ↓
        Overflow
```

📌 **Remember:**  
**Buffer Overflow → Too much data → Memory boundary problem**

---

## 2️⃣ Improper Data Validation ⭐

The application fails to properly validate data supplied to it.

```text
User Input
    ↓
❌ No proper validation
    ↓
Application processes bad input
```

📌 **Remember:**  
**Improper validation → Untrusted input isn't checked correctly.**

---

## 3️⃣ Least Privilege Violation ⭐

The application/user receives **more privileges than necessary**.

Example:

```text
User only needs:
Read access

But receives:
Read + Write + Delete + Admin
```

This increases the potential impact if that account is compromised.

📌 **Remember:**

> **Least privilege = Give only the permissions required.**

---

## 4️⃣ Memory Leak

A program fails to properly release memory that it no longer needs.

```text
Application
 ↓
Allocates memory
 ↓
Uses memory
 ↓
❌ Doesn't release it
 ↓
Memory consumption increases
```

Over time this can affect application performance.

📌 **Remember:**  
**Memory leak → Memory isn't properly released.**

---

## 5️⃣ Hard-Coded Password

A password is directly embedded inside application code.

Example concept:

```text
Application Code
      ↓
"password123"
```

This is dangerous because anyone who gains access to the code may discover the credential.

📌 **Remember:**  
**Never embed sensitive credentials directly in application code.**

---

## 6️⃣ Using a Broken or Risky Cryptographic Algorithm

The slide identifies using a **broken or risky cryptographic algorithm** as a vulnerability.

The problem is relying on cryptographic mechanisms that aren't sufficiently secure.

```text
Sensitive Data
      ↓
Weak/Broken Algorithm
      ↓
Reduced protection
```

📌 **Remember:**  
**Weak cryptography → Weak protection of data.**

# ⚡ QUICK REVISION

### What?
> **Vulnerability = A weakness or flaw that can be exploited by an attacker.**

### Where?
> **Application design, code, configuration, memory, authentication, network communication, cryptography, etc.**

### How?
> **An attacker exploits the weakness → causes unintended behavior or harm.**

### 🧠 Memory Trick

**Vulnerability = Weakness → Exploit → Impact**

```text
Weakness
   ↓
Exploitation
   ↓
Impact
```

**Important distinction:**

> **Vulnerability ≠ Attack**

A **vulnerability** is the weakness.  
An **attack** is the action used to exploit that weakness.
