# 🛡️ Defense in Depth — AWS Security

## 🔹 WHAT?

**Defense in Depth** is a security strategy where you use **multiple layers of security controls** instead of depending on a single security mechanism.

The idea is simple:

> **If one security layer fails, other layers can still protect the system.**

Think of it like a building with multiple security controls:

```text
Physical Security
       ↓
Policies & Access
       ↓
Perimeter
       ↓
Networking
       ↓
VM / Compute
       ↓
Applications
       ↓
Data
```

The slide identifies **7 layers of security**:

1. Data
2. Application
3. Compute
4. Network
5. Perimeter
6. Identity & Access
7. Physical

---

# 🔹 WHERE?

Defense in Depth applies across the **entire cloud environment**, from the physical AWS data center all the way to the data stored by your application.

### The 7 Layers

| Layer | What it protects |
|---|---|
| **1. Data** | Business/customer data |
| **2. Application** | Applications and software |
| **3. Compute** | VMs and compute resources |
| **4. Network** | Communication between resources |
| **5. Perimeter** | Protection from external attacks |
| **6. Identity & Access** | Who can access infrastructure |
| **7. Physical** | Physical AWS infrastructure |

---

# 🔹 HOW?

## 1️⃣ Data Layer

### What?
Protects **business and customer data**.

The slide specifically mentions:

- Controlling access to data
- **Encryption** to protect data

### Example

```text
User → Application → Database
                         ↓
                    Encrypted Data
```

Even if someone obtains access to the underlying storage, encryption can provide an additional layer of protection.

### 🔑 Remember
**Data = Access + Encryption**

---

# 2️⃣ Application Layer

### What?
Protects the applications running in your environment.

The goal is to ensure applications are:

- Secure
- Free from security vulnerabilities

### Example

```text
User
 ↓
Application
 ↓
Database
```

If the application contains a vulnerability, attackers may exploit it to access resources or data.

### 🔑 Remember
**Application = Secure code + Vulnerability protection**

---

# 3️⃣ Compute Layer

### What?
Protects access to **virtual machines / compute resources**.

The slide specifically mentions controlling access through:

- Ports
- On-premises environments
- Cloud environments

### Example

For an EC2 instance:

```text
Internet
   ↓
Allowed ports
   ↓
EC2 Instance
```

Only required network access should be allowed.

### 🔑 Remember
**Compute = Protect your VMs**

---

# 4️⃣ Network Layer

### What?
Controls communication between resources.

The slide emphasizes:

> **Limit communication between resources using segmentation and access controls.**

### Example

Instead of allowing every resource to communicate with every other resource:

```text
Web Tier
   ↓
Application Tier
   ↓
Database Tier
```

You can restrict which parts of the network can communicate.

### Key concepts

- **Network segmentation**
- **Access controls**
- Restrict unnecessary communication

### 🔑 Remember
**Network = Control who can talk to whom**

---

# 5️⃣ Perimeter Layer

### What?
Protects your environment from **large-scale external attacks**.

The slide specifically mentions:

> **DDoS protection**

A **Distributed Denial-of-Service (DDoS)** attack attempts to overwhelm resources with a huge amount of traffic.

### Flow

```text
Attackers
   ↓
Massive traffic
   ↓
[ Perimeter Protection ]
   ↓
Application
```

The perimeter layer attempts to filter malicious traffic **before it can cause a denial of service for users**.

### 🔑 Remember

**Perimeter = Protect from external attacks**

---

# 6️⃣ Identity & Access Layer ⭐

### What?
Controls **who can access your infrastructure and what they are allowed to do**.

The slide highlights:

- Access control
- Infrastructure access
- Change control

This is one of the most important concepts in AWS security.

### Example

```text
Employee
   ↓
Identity
   ↓
Authentication
   ↓
Authorization
   ↓
AWS Resource
```

You don't want every user to have unlimited access.

### Principle

> Give users only the permissions they actually need.

### 🔑 Remember

**Identity & Access = Who can access what?**

---

# 7️⃣ Physical Layer

### What?
Protects the **physical infrastructure**.

The slide describes this as:

> Limiting access to a data center to only authorized personnel.

AWS operates physical data centers, so physical security is another layer of the overall security model.

### Example

```text
AWS Data Center
       ↓
Physical Security
       ↓
Authorized Personnel
       ↓
Infrastructure
```

### 🔑 Remember

**Physical = Protect the actual data center**

---

# 🧠 HOW THE 7 LAYERS WORK TOGETHER

Imagine an attacker trying to reach your database:

```text
                ATTACKER
                   ↓
        ┌──────────────────┐
        │ 1. PERIMETER     │ ← DDoS protection
        └────────┬─────────┘
                 ↓
        ┌──────────────────┐
        │ 2. NETWORK       │ ← Segmentation
        └────────┬─────────┘
                 ↓
        ┌──────────────────┐
        │ 3. IDENTITY      │ ← Access control
        └────────┬─────────┘
                 ↓
        ┌──────────────────┐
        │ 4. COMPUTE       │ ← VM/port protection
        └────────┬─────────┘
                 ↓
        ┌──────────────────┐
        │ 5. APPLICATION   │ ← Secure application
        └────────┬─────────┘
                 ↓
        ┌──────────────────┐
        │ 6. DATA          │ ← Encryption/access
        └──────────────────┘
```

And underneath the entire environment is **physical security** protecting the actual infrastructure.

# 🎯 AWS EXAM FOCUS

### If the question says:

**"Use multiple layers of security so that if one control fails, others remain."**

👉 **Defense in Depth**

### If it mentions:

- **Encryption / customer data** → 🗄️ **Data**
- **Vulnerable application/code** → 💻 **Application**
- **VMs / ports** → 🖥️ **Compute**
- **Segmentation / communication** → 🌐 **Network**
- **DDoS protection** → 🛡️ **Perimeter**
- **Permissions / access / users** → 👤 **Identity & Access**
- **Data center / authorized personnel** → 🏢 **Physical**
