# 🌐 Enterprise / Hybrid Networking

This diagram covers **four important AWS networking concepts** for connecting on-premises environments with AWS and keeping AWS-to-AWS traffic private:

1. **AWS Direct Connect**
2. **AWS VPN**
3. **AWS PrivateLink / VPC Interface Endpoints**
4. **Hybrid networking**

---

# 1. AWS Direct Connect

### Definition

**AWS Direct Connect provides a dedicated network connection from an on-premises data center to AWS.**

The screenshot describes it as a **dedicated gigabit connection** from the on-premises data center to AWS.

Think:

```text
On-Premises Data Center
        │
        │ Dedicated connection
        ↓
   AWS Direct Connect
        │
        ↓
       VPC
```

### Why use Direct Connect?

Use it when an organization needs a **dedicated, consistent network connection** between its on-premises infrastructure and AWS.

It can provide:

* More consistent network connectivity
* High bandwidth
* Private connectivity between on-premises and AWS
* Better suitability for large amounts of ongoing traffic

### Scenario

A company has a large on-premises data center containing databases and applications.

It also has applications running in AWS:

```text
On-Premises
├── Database
├── File servers
└── Applications
        │
        │ Direct Connect
        ↓
AWS VPC
├── EC2
└── Applications
```

The company needs regular connectivity between both environments.

→ **AWS Direct Connect**

### 🧠 Remember

> **Direct Connect = Dedicated connection from on-premises to AWS**

---

# 2. AWS VPN

### Definition

An **AWS VPN provides a secure connection between networks over an existing network connection, commonly using the Internet.**

The screenshot describes AWS VPN as a secure connection between:

* On-premises
* Remote offices
* Mobile employees

Think:

```text
On-Premises
      │
      │ Encrypted VPN connection
      │
   Internet
      │
      ↓
     AWS
```

### Why use VPN?

VPNs are useful when you want secure connectivity without requiring a dedicated physical connection.

Common use cases:

* Connecting an office to AWS
* Connecting an on-premises network to a VPC
* Remote employees connecting securely
* Connecting branch offices

### Scenario

A company has a small office that needs to connect securely to its AWS VPC.

Instead of establishing a dedicated connection, it can use a VPN connection over the Internet.

```text
Office
  ↓
Encrypted VPN
  ↓
Internet
  ↓
AWS VPC
```

### Direct Connect vs VPN

|                         | Direct Connect                         | VPN                                        |
| ----------------------- | -------------------------------------- | ------------------------------------------ |
| Connection              | Dedicated network connection           | Typically uses Internet                    |
| Main idea               | Dedicated connectivity                 | Secure encrypted connectivity              |
| Use case                | Consistent/high-bandwidth connectivity | Secure connectivity without dedicated link |
| Physical dedicated link | Yes                                    | No                                         |

### 🧠 Remember

> **VPN = Secure connection over the network/Internet**

# 3. AWS PrivateLink

### Definition

**AWS PrivateLink provides private connectivity to supported services without requiring traffic to traverse the public Internet.**

The screenshot describes **VPC Interface Endpoints** as keeping traffic within the AWS network rather than traversing the Internet.

Think:

```text
Your VPC
   │
   ↓
VPC Interface Endpoint
   │
   ↓
AWS/service endpoint
```

The traffic can remain on the AWS network rather than going through the public Internet.

---

# 4. VPC Interface Endpoint

An **Interface Endpoint** is a VPC endpoint that uses **AWS PrivateLink** to provide private connectivity to supported services.

For example:

```text
EC2
 │
 ↓
Interface Endpoint
 │
 ↓
AWS Service
```

Instead of:

```text
EC2
 ↓
Internet
 ↓
AWS Service
```

the endpoint provides a private path.

### Why use it?

Use PrivateLink/interface endpoints when you want:

* Private connectivity
* Traffic to stay within AWS networking
* Reduced exposure to the public Internet
* Private access to supported AWS services or endpoint services

### Scenario

Suppose an EC2 instance in a private subnet needs to communicate with a supported AWS service.

You can use an interface endpoint:

```text
Private EC2
     ↓
Interface Endpoint
     ↓
AWS Service
```

The EC2 doesn't need to access that service through the public Internet.

### 🧠 Remember

> **PrivateLink = Private access to services**

# 5. What is Hybrid Networking?

### Definition

**Hybrid networking connects your on-premises infrastructure with resources running in the AWS Cloud.**

For example:

```text
        Hybrid Environment

On-Premises                 AWS
┌──────────────┐          ┌──────────────┐
│ Servers      │          │ EC2          │
│ Databases    │ ←──────→ │ VPC          │
│ Applications │          │ Services     │
└──────────────┘          └──────────────┘
```

Your organization doesn't have to move everything to AWS immediately.

Some workloads can remain on-premises while others run in AWS.

### Scenario

A company keeps its existing database on-premises but moves its web application to AWS.

```text
Users
  ↓
AWS EC2
  ↓
Hybrid connection
  ↓
On-Premises Database
```

That's a **hybrid environment**.
