# AWS VPC — Only VPC

## 1. What is a VPC?

**VPC (Virtual Private Cloud)** is a logically isolated virtual network that you create in AWS.

It gives you control over the networking environment in which your AWS resources run.

Think of it as:

> **VPC = Your own private network inside AWS.**

Example:

```text
AWS Region
│
└── VPC
    └── Your private network
```

A VPC lets you define things such as:

- IP address range
- IPv4/IPv6 addressing
- Network segmentation
- DNS settings
- Tenancy
- Which Availability Zones the VPC uses
- Whether resources can communicate with each other

---

# 2. VPC Scope

A VPC is **Regional**.

For example:

```text
Mumbai Region
└── VPC
    ├── AZ 1
    ├── AZ 2
    └── AZ 3
```

A VPC can span multiple Availability Zones **within the same AWS Region**.

It cannot span multiple AWS Regions.

For example:

```text
Mumbai Region
└── VPC-A

Singapore Region
└── VPC-B
```

These are separate VPCs.

---

# 3. VPC CIDR Block

When you create a VPC, you specify its **IP address range** using CIDR notation.

Example:

```text
10.0.0.0/16
```

This defines the IPv4 address space available within the VPC.

A VPC might therefore look like:

```text
VPC
10.0.0.0/16
```

You can then divide that address space into smaller networks.

For example:

```text
VPC: 10.0.0.0/16

10.0.1.0/24
10.0.2.0/24
10.0.3.0/24
...
```

Those smaller ranges are used by subnets.

---

# 4. Private IPv4 Address Ranges

VPCs commonly use private IPv4 ranges defined by RFC 1918:

| CIDR | Range |
|---|---|
| `10.0.0.0/8` | 10.0.0.0 – 10.255.255.255 |
| `172.16.0.0/12` | 172.16.0.0 – 172.31.255.255 |
| `192.168.0.0/16` | 192.168.0.0 – 192.168.255.255 |

Example:

```text
10.0.0.0/16
```

is a common VPC CIDR.

---

# 5. VPC and Subnets

A VPC itself is a large network.

You divide it into smaller networks called **subnets**.

Example:

```text
VPC
10.0.0.0/16
│
├── Subnet
│   10.0.1.0/24
│
├── Subnet
│   10.0.2.0/24
│
└── Subnet
    10.0.3.0/24
```

Important relationship:

> **VPC → contains subnets**

And:

> **A subnet belongs to one VPC.**

---

# 6. VPC and Availability Zones

A VPC can span multiple AZs.

However, **a subnet exists in only one AZ**.

Example:

```text
VPC
10.0.0.0/16
│
├── AZ-A
│   ├── Subnet A
│   └── Subnet B
│
└── AZ-B
    ├── Subnet C
    └── Subnet D
```

So:

**VPC → Regional**

**Subnet → AZ-specific**

This is an important AWS exam concept.

---

# 7. Default VPC

AWS provides a **default VPC** in each AWS Region for accounts that have one.

It allows you to launch resources without manually designing a VPC first.

Conceptually:

```text
AWS Region
│
└── Default VPC
    ├── Subnets
    ├── Route tables
    └── Other default networking configuration
```

You can also create your own **custom VPC**.

---

# 8. Custom VPC

A custom VPC allows you to design your own network architecture.

For example:

```text
VPC
10.20.0.0/16
│
├── Subnet
│   10.20.1.0/24
│
├── Subnet
│   10.20.2.0/24
│
└── Subnet
    10.20.3.0/24
```

Custom VPCs are commonly used when you need specific:

- IP addressing
- Network segmentation
- Security requirements
- Connectivity requirements
- Enterprise architecture

---

# 9. VPC Tenancy

When creating a VPC, AWS historically provides a **tenancy** option.

The main concepts are:

### Default tenancy

Resources generally run on shared AWS hardware.

### Dedicated tenancy

Resources run on dedicated hardware.

For Cloud Practitioner, remember:

> **VPC tenancy determines whether resources use shared or dedicated hardware.**

Dedicated tenancy can have additional cost implications and service limitations.

---

# 10. VPC IPv4 Addressing

A VPC can have an IPv4 CIDR block.

Example:

```text
10.0.0.0/16
```

You can also associate additional IPv4 CIDR blocks with a VPC when your architecture requires more address space, subject to AWS rules and limits.

Example:

```text
VPC
├── 10.0.0.0/16
└── 172.16.0.0/16
```

---

# 11. VPC IPv6

VPCs can also support IPv6.

IPv6 uses **128-bit addresses**, providing an extremely large address space.

Example:

```text
2001:db8:1234::/56
```

The important concept is:

```text
IPv4 → 32-bit
IPv6 → 128-bit
```

---

# 12. VPC DNS

AWS provides DNS functionality for VPCs.

Two important VPC DNS attributes are:

### DNS resolution

Controls whether DNS resolution is supported in the VPC.

### DNS hostnames

Controls whether instances launched in the VPC receive DNS hostnames where applicable.

So conceptually:

```text
VPC
│
└── DNS
    ├── DNS resolution
    └── DNS hostnames
```

---

# 13. VPC DHCP Options

A VPC can have a **DHCP option set** associated with it.

DHCP options can provide network configuration information such as:

- Domain name
- DNS servers
- NTP servers

Conceptually:

```text
VPC
 ↓
DHCP Options
 ↓
Network configuration for resources
```

For Cloud Practitioner, knowing the purpose is usually enough.

---

# 14. VPC Limits

AWS imposes limits on VPC resources.

Examples include limits around:

- Number of VPCs
- CIDR blocks
- Subnets
- Route tables
- Network interfaces
- Security groups

Many VPC limits are adjustable through AWS Service Quotas, while some have fixed constraints.

For the exam, don't focus heavily on memorizing numerical limits unless your course specifically requires them.

---

# 15. VPC Isolation

One of the fundamental characteristics of a VPC is **logical isolation**.

For example:

```text
Account
│
├── VPC-A
│   10.0.0.0/16
│
└── VPC-B
    10.1.0.0/16
```

These are separate virtual networks.

Resources in different VPCs don't automatically communicate with each other.

Connectivity must be deliberately configured.

---

# 16. VPC Architecture Concept

At the highest level:

```text
                    AWS REGION
                        │
                        ▼
                    ┌───────┐
                    │  VPC  │
                    └───┬───┘
                        │
              ┌─────────┼─────────┐
              ▼         ▼         ▼
           Subnet    Subnet    Subnet
              │         │         │
              ▼         ▼         ▼
           Resources Resources Resources
```

The important hierarchy is:

```text
AWS Region
    ↓
   VPC
    ↓
 Subnets
    ↓
 AWS Resources
```

---

# 17. VPC vs Traditional Data Center Network

A useful way to understand VPC:

| Traditional networking | AWS |
|---|---|
| Data center network | VPC |
| Network segment | Subnet |
| IP address range | CIDR |
| Network routing | Route tables |
| Firewall | Security controls |
| Physical network | AWS virtual network |

VPC gives you many of the concepts you're familiar with from traditional networking, but implemented virtually through AWS.

---

# 18. What VPC Actually Gives You

The core purpose of VPC is to give you control over your AWS network.

Think:

```text
                    VPC
                     │
       ┌─────────────┼─────────────┐
       │             │             │
       ▼             ▼             ▼
   IP Address     Network       Network
    Space        Segmentation    Control
       │             │             │
       ▼             ▼             ▼
     CIDR         Subnets       Routing/
                                Security
```

# 19. Most Important VPC Terms

For your AWS Practitioner preparation, know these definitions:

| Term | Meaning |
|---|---|
| **VPC** | Isolated virtual network in AWS |
| **CIDR** | Defines an IP address range |
| **Subnet** | Smaller network inside a VPC |
| **Region** | VPC's geographic AWS location |
| **Availability Zone** | Subnet's physical isolation boundary |
| **Default VPC** | AWS-provided VPC for easy resource deployment |
| **Custom VPC** | VPC designed by the customer |
| **IPv4** | 32-bit IP addressing |
| **IPv6** | 128-bit IP addressing |
| **DHCP Options** | Network configuration options |
| **DNS Resolution** | DNS lookup capability within VPC |
| **DNS Hostnames** | DNS hostnames for resources |

And remember these **5 core facts**:

1. **VPC = logically isolated virtual network**
2. **VPC is Regional**
3. **VPC contains subnets**
4. **Each subnet belongs to one AZ**
5. **CIDR defines the VPC's IP address range**
