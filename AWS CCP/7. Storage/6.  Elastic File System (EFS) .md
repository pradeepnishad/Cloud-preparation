# 📁 Amazon Elastic File System (EFS)

## 1. Definition

**Amazon Elastic File System (EFS)** is a **fully managed, elastic, cloud-native file storage service** for AWS.

The simplest way to think about EFS is:

> **EFS is a shared network filesystem that multiple compute resources can access at the same time.**

Unlike EBS, which is primarily used as a virtual disk for an EC2 instance, EFS is designed for **shared file access**.

```text id="f8s9pz"
                  EFS
                   │
        ┌──────────┼──────────┐
        ↓          ↓          ↓
      EC2-A      EC2-B      EC2-C
        │          │          │
        └──────────┴──────────┘
              Shared Files
```

---

# 2. What Is File Storage?

File storage organizes data as **files and directories**.

For example:

```text id="4i4w7c"
/application
│
├── config.txt
├── users
│   ├── user1.json
│   └── user2.json
│
└── logs
    ├── app.log
    └── error.log
```

The operating system interacts with the filesystem using normal file operations such as:

```text id="w4b0a8"
Create
Read
Write
Delete
```

This is different from:

```text
EBS → Block storage
S3  → Object storage
EFS → File storage
```

---

# 3. Why Use EFS?

The main reason to use EFS is:

> **Multiple servers need access to the same files.**

For example:

```text id="i5u1j7"
             EFS
          /   |   \
         ↓    ↓    ↓
       EC2   EC2   EC2
         \    |    /
          Shared Files
```

All three EC2 instances can access the same EFS filesystem according to the configured permissions.

---

# 4. EFS Is a Network File System

EFS provides a filesystem that compute resources access **over the network**.

The basic architecture is:

```text id="g6t8dy"
EC2
 │
 │ Network
 ↓
EFS
 │
 ↓
Files
```

Your application can interact with EFS like a filesystem rather than calling an object-storage API for every file operation.

---

# 5. EFS and Multiple EC2 Instances

This is one of the most important things to remember.

Suppose you have three web servers:

```text id="0l3k82"
               Load Balancer
                    ↓
          ┌─────────┼─────────┐
          ↓         ↓         ↓
        EC2-A     EC2-B     EC2-C
          │         │         │
          └─────────┼─────────┘
                    ↓
                   EFS
```

All three servers can access the same shared files.

For example:

```text id="jyr2yc"
EFS
└── uploads
    ├── image1.jpg
    ├── image2.jpg
    └── document.pdf
```

EC2-A, EC2-B and EC2-C can access those files through the shared filesystem.

---

# 6. Scenario-Based Example

Imagine you have an application running on **three EC2 instances**.

Users upload profile pictures.

If you stored them only on the local disk of EC2-A:

```text id="s0g4d5"
User
 ↓
EC2-A
 ↓
image.jpg
```

A problem occurs if another request goes to EC2-B:

```text id="x3h3lv"
User
 ↓
EC2-B
 ↓
Where is image.jpg?
```

EC2-B doesn't automatically have the file stored on EC2-A.

With EFS:

```text id="d7z9l8"
              EFS
               │
      ┌────────┼────────┐
      ↓        ↓        ↓
    EC2-A    EC2-B    EC2-C
      │        │        │
      └────────┼────────┘
               ↓
          image.jpg
```

All instances can access the shared file.

---

# 7. Why Is It Called "Elastic" File System?

EFS is designed to **grow and shrink automatically as your stored data changes**.

You don't need to manually choose a fixed disk size in the same way you do when provisioning a traditional fixed-size disk.

Conceptually:

```text id="jqw2fh"
100 GB data
    ↓
EFS grows

500 GB data
    ↓
EFS grows

1 TB data
    ↓
EFS grows
```

This makes EFS useful when storage requirements can change over time.

### 🧠 Memory

> **Elastic = storage capacity adjusts as your data grows/shrinks.**

# 8. EFS vs EBS

This is extremely important for the exam.

### EBS

```text id="d5l3vx"
EC2
 ↓
EBS
 ↓
Virtual Disk
```

Think:

> **One EC2's virtual hard drive**

### EFS

```text id="v6b8gk"
        EFS
      /  |  \
    EC2 EC2 EC2
```

Think:

> **Shared network filesystem**

---

## Comparison

| Feature             | EBS                                | EFS                            |
| ------------------- | ---------------------------------- | ------------------------------ |
| Storage type        | Block                              | File                           |
| Think of it as      | Virtual hard drive                 | Shared network drive           |
| Main use            | EC2 disk                           | Shared files                   |
| Multiple EC2 access | Limited/specific attachment models | Designed for concurrent access |
| Capacity            | Provisioned/configured volume      | Elastic                        |
| Access              | Block device                       | Network filesystem             |
| Best for            | OS, applications, databases        | Shared application files       |

### Memory:

> **EBS = Disk**

> **EFS = Shared Drive**

---

# 9. EFS vs S3

EFS and S3 can both store files, but they work differently.

### EFS

```text id="u5z8kq"
EC2
 ↓
Mount filesystem
 ↓
Read/write files
```

### S3

```text id="a6t4z0"
Application
 ↓
API / HTTPS
 ↓
S3
 ↓
Object
```

### Main distinction

> **EFS behaves like a filesystem.**

> **S3 stores data as objects.**

---

## Example

If your application expects:

```text id="n2p8cq"
/shared/config.txt
/shared/logs/app.log
```

a file system such as EFS is appropriate.

If you want to store:

```text id="y0p1jk"
video.mp4
backup.zip
image.jpg
```

as objects accessed through APIs, S3 is typically the appropriate model.

---

# 10. EFS and NFS

Your course screenshot identifies EFS as a **cloud-native NFS file system service**.

**NFS = Network File System.**

It allows a computer to access files over a network as if they were part of a filesystem.

Conceptually:

```text id="l5r2kx"
EC2
 │
 │ NFS
 ↓
EFS
 │
 ↓
Shared filesystem
```

For Cloud Practitioner, remember:

> **EFS → File storage → NFS → Shared access**

---

# 11. When Should You Use EFS?

Use EFS when you have requirements such as:

### Multiple EC2 instances need the same files

```text id="e9w2z4"
EC2 ─┐
EC2 ─┼→ EFS
EC2 ─┘
```

### Application needs a shared filesystem

For example:

```text id="8f6v0b"
Shared application files
Shared content
Shared uploads
```

### Storage requirements change

EFS can scale with the amount of stored data.

---

# 12. When Should You NOT Choose EFS?

If you simply need a virtual disk for one EC2 instance:

```text id="h3p5y6"
EC2 → Virtual Disk
```

Think **EBS** first.

If you need highly scalable object storage:

```text id="q9z2nd"
Images
Videos
Backups
Documents
```

Think **S3**.
