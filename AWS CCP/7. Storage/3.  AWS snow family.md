# ❄️ AWS Snow Family

The **AWS Snow Family** is a group of physical devices designed to help **move data into or out of the AWS Cloud** when transferring the data over the internet or a private network would be:

* Too slow
* Difficult
* Expensive

The key idea is:

> **Instead of sending a huge amount of data over the network, physically send the storage/compute device to AWS.**

---

# 1. Why Do We Need the Snow Family?

Normally, you might transfer data like this:

```text
On-Premises Data Center
        │
        │ Internet / Network
        ↓
       AWS
```

This works well for normal amounts of data.

But imagine you have:

```text
100 TB
500 TB
1 PB
```

Transferring that much data over a network could take a very long time.

Instead:

```text
On-Premises
    ↓
Load data onto Snow device
    ↓
Physically transport device
    ↓
AWS
    ↓
Data uploaded
```

This is called **physical data transfer**.

# 3. AWS Snowcone

## Definition

**Snowcone** is the smaller, portable device in the Snow Family.

According to your source, it comes in two storage sizes:

* **8 TB HDD**
* **14 TB SSD**

Think:

```text
Snowcone
   ↓
Small
Portable
Lower storage capacity
```

---

## Why Use Snowcone?

Use it when you need to physically move a **smaller amount of data** or need a compact device that can be deployed in remote locations.

### Scenario

Imagine an organization has a remote site where internet connectivity is poor.

```text
Remote Site
     ↓
Snowcone
     ↓
Store data locally
     ↓
Physically transfer
     ↓
AWS
```

Instead of trying to upload everything through a slow connection, the data can be transferred using the physical device.

### 🧠 Memory

> **Snowcone = Small and portable**

---

# 4. AWS Snowball Edge

## Definition

**Snowball Edge** is a larger physical data-transfer and compute device.

Your screenshot shows two general types:

### Storage Optimized

```text
80 TB
```

### Compute Optimized

```text
39.5 TB
```

So Snowball Edge isn't just about moving data.

It can also provide **compute capabilities at the edge**.

# 6. Snowball Edge — Compute Optimized

The screenshot lists:

> **Compute Optimized → 39.5 TB**

The important distinction is:

> **Compute Optimized provides compute capability in addition to storage/data-transfer capabilities.**

This can be useful when processing data at the location where it is generated before transferring it to AWS.

### Scenario

Imagine a remote industrial site generating large amounts of data.

You could conceptually:

```text
IoT / Sensors
     ↓
Snowball Edge
     ↓
Process data locally
     ↓
Store useful results
     ↓
Transfer to AWS
```

This is particularly useful when sending all raw data over the network isn't practical.

### 🧠 Memory

> **Snowball Edge = Larger data transfer + optional edge compute**

# 7. AWS Snowmobile

## Definition

**Snowmobile** is designed for **extremely large-scale data transfers**.

Your screenshot shows:

> **100 PB of storage**

PB = **Petabyte**

And:

```text
1 PB = 1,024 TB
```

using the binary convention commonly used in computing contexts.

So 100 PB represents an enormous amount of storage.

---

# 8. Why Snowmobile?

Imagine an organization has an enormous data center containing huge amounts of data.

For example:

```text
100+ PB
```

Trying to move this over the internet could take an impractical amount of time.

Instead:

```text
Data Center
     ↓
Snowmobile
     ↓
Physical transportation
     ↓
AWS
```

Snowmobile is essentially a **large-scale physical data transfer solution**.

### 🧠 Memory

> **Snowmobile = Massive data transfer**

# 11. Snow Family vs Normal Network Transfer

### Normal transfer

```text
Data
 ↓
Internet / Private Network
 ↓
AWS
```

Good when the network can transfer the data within a reasonable time and cost.

### Snow Family

```text
Data
 ↓
Physical Snow Device
 ↓
Truck / Physical Transport
 ↓
AWS
```

Useful when network transfer is **too slow, difficult, or expensive**.

The exact device choice depends on the current AWS offerings, capacity requirements, and workload requirements; your slide's key learning objective is the **physical data transfer concept**.
