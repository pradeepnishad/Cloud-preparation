# 🪣 Introduction to Amazon S3 — Object Storage

The screenshot introduces **Amazon S3 (Simple Storage Service)** and, more specifically, the concept of **object storage**.

The core idea is:

> **S3 stores data as objects inside buckets.**

Think of it as:

```text
                 Amazon S3
                    │
                 Bucket
                    │
        ┌───────────┼───────────┐
        ↓           ↓           ↓
     Object 1    Object 2    Object 3
      image.jpg    report.pdf   video.mp4
```

---

# 1. What Is Object Storage?

## Definition

**Object storage** is a storage architecture that manages data as **objects**, rather than as traditional files in a filesystem or blocks in block storage.

The screenshot compares three storage architectures:

```text
File Storage
    ↓
Files + directories/hierarchy

Block Storage
    ↓
Blocks

Object Storage
    ↓
Objects
```

### In S3:

```text
Data
 +
Metadata
 +
Unique identifier
      ↓
   Object
```

---

# 2. Object Storage vs File Storage vs Block Storage

This distinction is very important.

### File Storage

Organizes data as:

```text
Folder
 ├── File 1
 ├── File 2
 └── File 3
```

Example: **EFS**

---

### Block Storage

Splits data into blocks:

```text
┌────┬────┬────┬────┐
│ B1 │ B2 │ B3 │ B4 │
└────┴────┴────┴────┘
```

Example: **EBS**

---

### Object Storage

Stores each item as an object:

```text
Object
├── Data
├── Metadata
└── Key
```

Example: **S3**

### 🧠 Memory

> **EBS → Blocks**
> **EFS → Files**
> **S3 → Objects**

---

# 3. What Is an S3 Object?

The screenshot says:

> **Objects contain your data. They are like files.**

An S3 object is the actual piece of data you store in S3.

For example:

```text
photo.jpg
report.pdf
backup.zip
video.mp4
```

Each one can be an S3 object.

---

# 4. What Does an S3 Object Contain?

According to the screenshot, an object can consist of:

```text
Object
│
├── Key
├── Value
├── Version ID
└── Metadata
```

Let's understand each.

---

## A. Key

### Definition

The **key** is the name/identifier of the object within a bucket.

Example:

```text
photos/profile.jpg
```

Here:

```text
photos/profile.jpg
        ↑
       Key
```

The key uniquely identifies the object within that bucket.

### Memory:

> **Key = Object's name/identifier**

---

# 5. Value

### Definition

The **value** is the actual data contained in the object.

For example:

```text
Object:
    Key   → photo.jpg
    Value → actual image data
```

If you upload:

```text
report.pdf
```

the value is the actual PDF data.

The screenshot describes the value as:

> **The data itself made up of a sequence of bytes.**

### Memory:

> **Value = Actual data**

---

# 6. Version ID

An S3 object can have a **Version ID when versioning is enabled**.

Suppose you have:

```text
report.pdf
```

You upload a new version.

S3 can maintain multiple versions:

```text
report.pdf
│
├── Version 1
├── Version 2
└── Version 3
```

This allows you to preserve previous versions rather than simply replacing the old one.

### Important:

The screenshot specifically says:

> **Version ID when versioning is enabled**

So remember:

```text
Versioning OFF
→ No object version history

Versioning ON
→ Objects can have versions
```

### Memory:

> **Version ID = Identifies a particular version of an object**

---

# 7. Metadata

### Definition

**Metadata** is additional information associated with the object.

Think:

```text
Object
│
├── Actual data
│
└── Information about the data
```

Examples of metadata can include information describing the object or how it should be handled.

### Memory:

> **Metadata = Data about the data**

---

# 8. What Is an S3 Bucket?

## Definition

An **S3 bucket is a container for objects**.

Think of it like:

```text
                 S3
                  │
               Bucket
                  │
       ┌──────────┼──────────┐
       ↓          ↓          ↓
    Object      Object      Object
```

For example:

```text
my-company-data
│
├── report.pdf
├── image.jpg
├── backup.zip
└── video.mp4
```

The bucket holds these objects.

---

# 9. Bucket and Object Relationship

This is one of the most important S3 concepts:

```text
Bucket
   ↓
contains
   ↓
Objects
```

For example:

```text
Bucket: company-data

company-data/
├── employee.csv
├── sales.csv
├── report.pdf
└── image.png
```

So:

> **Bucket = Container**

> **Object = Data stored inside the container**

---

# 10. S3 Folders

The screenshot says:

> **Buckets can also have folders which in turn hold objects.**

You can organize objects using key prefixes that appear like folders in the S3 console.

For example:

```text
company-data/
│
├── reports/
│    ├── january.pdf
│    └── february.pdf
│
└── images/
     ├── logo.png
     └── banner.jpg
```

Conceptually:

```text
Bucket
  ↓
Folder/prefix
  ↓
Object
```

For Cloud Practitioner, you can think of folders as organizational structures for objects. Technically, S3 uses object keys/prefixes rather than a traditional filesystem hierarchy.

---

# 11. Bucket Names Must Be Unique

The screenshot says:

> **S3 is a universal namespace, so bucket names must be unique.**

This is important.

You can't simply have everyone create a bucket called:

```text
my-bucket
```

because S3 bucket names need to be globally unique within the relevant S3 namespace.

For example:

```text
pradeep-test-bucket-2026
```

is much more likely to be unique than:

```text
test
```

### Memory:

> **S3 bucket name = globally unique name**

The screenshot compares this concept to having a **domain name**.

---

# 12. S3 Storage Capacity

The screenshot states:

> **S3 provides you with unlimited storage.**

For Cloud Practitioner, understand this as:

> **You don't need to provision a fixed storage capacity in advance; S3 is designed to scale massively as you store more objects.**

However, there is an important distinction:

### Total S3 storage

Designed to scale massively without you manually provisioning a fixed disk size.

### Individual object

The screenshot states:

> **An individual object can be from 0 bytes to 5 TB in size.**

So:

```text
S3
│
├── Object → 10 MB
├── Object → 2 GB
├── Object → 500 GB
└── Object → up to 5 TB
```

Don't confuse:

> **S3 storage capacity**

with

> **maximum size of one object.**

# 13. Why Use S3?

S3 is useful when you need to store large amounts of **objects/files** without managing the underlying storage infrastructure yourself.

Common examples include:

```text
Images
Videos
Documents
Backups
Logs
Data files
Static website files
Archives
```

### Scenario

Imagine you're building a social media application.

Users upload:

```text
Photos
Videos
Profile pictures
```

Instead of storing those files directly on an EC2 disk:

```text
User
 ↓
Application
 ↓
EC2 disk
```

you can store them in S3:

```text
User
 ↓
Application
 ↓
S3 Bucket
 ↓
Object
```

This separates application compute from object storage.

# 15. S3 Does Not Require You to Manage the Underlying Infrastructure

This is one of the major advantages.

With a traditional server:

```text
Server
 ↓
Disk
 ↓
Filesystem
 ↓
Storage management
```

With S3:

```text
Application
     ↓
    S3
     ↓
AWS manages underlying storage infrastructure
```

You don't need to decide:

> "How many physical disks should I buy?"

or:

> "How much physical storage should I install?"

AWS manages the underlying S3 infrastructure.

# 16. Scenario-Based Example

Suppose you're building a website where users upload profile pictures.

### Step 1

User uploads:

```text
profile.jpg
```

### Step 2

Your application sends it to S3:

```text
Application
     ↓
S3 API
     ↓
Bucket
```

### Step 3

S3 stores it as an object:

```text
Bucket: user-profile-data

Object:
    Key → users/123/profile.jpg
    Value → actual image data
    Metadata → additional information
```

Now the application can retrieve the object when required.

# 17. S3 Architecture

Put everything together:

```text
                    Amazon S3
                       │
                    Bucket
                       │
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
     Object 1       Object 2       Object 3
        │              │              │
   ┌────┴────┐    ┌────┴────┐    ┌────┴────┐
   │ Key     │    │ Key     │    │ Key     │
   │ Value   │    │ Value   │    │ Value   │
   │ Metadata│    │ Metadata│    │ Metadata│
   └─────────┘    └─────────┘    └─────────┘
```

And access looks like:

```text
User/Application
       ↓
 HTTPS / API
       ↓
      S3
       ↓
    Bucket
       ↓
    Object
```
