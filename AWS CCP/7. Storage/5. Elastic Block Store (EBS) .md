# 💾 Amazon Elastic Block Store (EBS)

## 1. Definition

**Amazon Elastic Block Store (EBS)** is a **persistent block storage service** designed primarily for use with Amazon EC2.

The simplest way to think about EBS is:

> **EBS is a virtual hard drive in AWS that you can attach to an EC2 instance.**

```text
        EC2 Instance
       ┌─────────────┐
       │     OS      │
       │ Application │
       └──────┬──────┘
              │
              ↓
        ┌─────────────┐
        │ EBS Volume  │
        │ Virtual Disk│
        └─────────────┘
```

---

# 2. What Does "Block Storage" Mean?

EBS stores data as **blocks** rather than as complete objects.

Conceptually:

```text
EBS Volume
┌────┬────┬────┬────┬────┐
│ B1 │ B2 │ B3 │ B4 │ B5 │
└────┴────┴────┴────┴────┘
```

The operating system uses these blocks to create and manage a filesystem.

For example:

```text
EBS
 ↓
Filesystem
 ↓
/home
/app
/logs
/etc
```

This is different from S3:

```text
EBS → Blocks → Disk-like storage

S3  → Objects → Object storage
```

---

# 3. Why Do We Use EBS?

EBS is useful when an EC2 instance needs **persistent disk storage**.

For example, an EC2 instance might need storage for:

* Operating system
* Applications
* Database files
* Logs
* Configuration
* Application data

### Scenario

You launch an Ubuntu EC2 instance:

```text
Ubuntu EC2
    │
    ↓
  EBS
    │
    ↓
Filesystem
    │
    ├── Application
    ├── Logs
    └── Data
```

Without storage, the EC2 instance wouldn't have the disk environment required for a normal operating system and applications.

---

# 4. What Does "Persistent" Mean?

**Persistent storage** means the data is designed to remain available independently of the lifecycle of the compute instance, subject to the volume's configuration and deletion behavior.

For example:

```text
EC2 Instance
     │
     ↓
EBS Volume
     │
     ↓
Data
```

If the EC2 instance is stopped, the EBS volume can retain its data.

This is an important difference from temporary/ephemeral storage.

### Simple memory:

> **Persistent = Data survives beyond the immediate compute activity.**

---

# 5. EBS Volume

An EBS **volume** is the actual block-storage resource you attach to an EC2 instance.

Example:

```text
AWS
 │
 ├── EC2 Instance
 │
 └── EBS Volume
       100 GB
```

You can choose an appropriate volume size and type based on your workload.

---

# 6. EBS Volume Types

Your source mentions several categories:

* **SSD**
* **IOPS SSD**
* **Throughput HDD**
* **Cold HDD**

The important Cloud Practitioner concept is that different EBS volume types are designed for different performance and workload requirements.

### General idea:

```text
SSD
↓
Low-latency / performance-oriented workloads

HDD
↓
Throughput-oriented or lower-cost workloads
```

You don't need to memorize every technical specification at the foundational level.

---

# 7. EBS SSD vs HDD

### SSD

Solid-state storage.

Generally appropriate when you need:

* Lower latency
* Faster random I/O
* Application/database workloads

### HDD

Hard-disk-based storage.

Generally appropriate for workloads where:

* Sequential throughput matters
* Cost efficiency is important
* Very high random I/O performance isn't required

### Memory:

> **SSD → Performance/low latency**

> **HDD → Throughput/cost-oriented workloads**

# 8. EBS and EC2 Relationship

This is extremely important.

```text
EC2 = Compute
EBS = Storage
```

Together:

```text
        EC2
    ┌───────────┐
    │   CPU     │
    │   RAM     │
    │   OS      │
    └─────┬─────┘
          │
          ↓
    ┌───────────┐
    │    EBS    │
    │  Storage  │
    └───────────┘
```

Think:

> **EC2 is the computer.**

> **EBS is the hard drive.**

---

# 9. Can EBS Be Used Without EC2?

EBS is primarily designed as block storage for EC2 and is tightly associated with EC2-based workloads.

For Cloud Practitioner, the simplest association to remember is:

> **EBS → EC2 block storage.**

---

# 10. EBS vs Instance Store

This is an important distinction when you study EC2 storage.

### EBS

```text
EC2
 ↓
EBS
 ↓
Persistent block storage
```

### Instance Store

```text
EC2
 ↓
Local physical storage
 ↓
Temporary/ephemeral
```

Instance store is physically associated with the host and is intended for temporary data; data is lost when the instance is stopped/terminated or otherwise loses the underlying host, depending on the lifecycle event.

So:

> **EBS = Persistent**

> **Instance Store = Temporary/ephemeral**

---

# 11. EBS Scenario

Imagine you're running a database on EC2:

```text
             EC2
       ┌───────────────┐
       │ Linux         │
       │ Database      │
       └───────┬───────┘
               │
               ↓
          EBS Volume
             500 GB
```

The database stores its data on the EBS volume.

If you stop the EC2 instance, the EBS volume can continue to retain the database data.

When you start the instance again:

```text
EC2 starts
   ↓
EBS attached
   ↓
Database data available
```

---

# 12. EBS and Availability Zones

A key AWS concept:

> **An EBS volume is associated with a specific Availability Zone.**

For example:

```text
Region
│
├── AZ-1
│    └── EC2
│         └── EBS
│
└── AZ-2
     └── EC2
```

An EBS volume generally needs to be in the same AZ as the EC2 instance to which it is attached.

If you need to move/copy data to another AZ, you can use mechanisms such as **EBS snapshots**.

---

# 13. EBS Snapshots

An **EBS snapshot** is a point-in-time backup of an EBS volume.

Conceptually:

```text
EBS Volume
    │
    ↓
Snapshot
    │
    ↓
Backup
```

You can use snapshots for things such as:

* Backup
* Recovery
* Creating new volumes
* Moving/copying volume data to another Availability Zone

### Scenario

You have:

```text
EC2
 ↓
EBS
 ↓
Database
```

You create:

```text
EBS
 ↓
Snapshot
```

If you later need to recover the volume, the snapshot can be used to create a new EBS volume.

### Memory:

> **EBS = Volume**

> **Snapshot = Backup/copy of the volume**

---

# 14. EBS vs EFS vs S3

This is one of the most important Cloud Practitioner comparisons.

|                     | **EBS**                                | **EFS**                    | **S3**                         |
| ------------------- | -------------------------------------- | -------------------------- | ------------------------------ |
| Storage type        | Block                                  | File                       | Object                         |
| Think of it as      | Virtual hard drive                     | Shared network filesystem  | Object repository              |
| Common use          | EC2 disk                               | Shared files               | Files, backups, media, objects |
| Access              | Block device                           | Network filesystem         | API/HTTPS                      |
| Multiple EC2 access | Supported models depend on volume type | Yes                        | Yes                            |
| Main association    | EC2                                    | Multiple compute resources | Applications/services          |

### 🧠 Simple memory:

> **EBS = Disk**

> **EFS = Shared Drive**

> **S3 = Objects**

---

# 15. How to Choose EBS

Ask:

### "Does my EC2 instance need a virtual hard drive?"

→ **EBS**

### "Do multiple EC2 instances need the same shared filesystem?"

→ **EFS**

### "Do I just need scalable storage for files/images/videos/backups?"

→ **S3**
