# 💰 Regional vs Zonal Reserved Instances

This screenshot explains the **scope** of a Reserved Instance (RI): whether the RI applies to an entire **AWS Region** or to a specific **Availability Zone (AZ)**.

> The source states that **the scope does not affect the price**.

---

## 1. Regional RI

### Definition

A **Regional RI** is purchased for an entire **AWS Region**.

Example:

```text
Region: ap-south-1

├── AZ 1
├── AZ 2
└── AZ 3
```

A Regional RI isn't tied to one specific Availability Zone.

### How it works

The RI discount can apply to eligible instance usage in **any AZ within that Region**, according to the source.

```text
Regional RI
     ↓
Region
 ┌───┼────┐
 ↓   ↓    ↓
AZ1  AZ2  AZ3
```

### Important point

The source says a Regional RI:

* **Does not reserve capacity**
* Provides discount flexibility across AZs in the Region
* Can provide instance-size flexibility within the instance family for supported **Amazon Linux/Unix, default-tenancy** RIs
* Can have purchases queued

### Example

You purchase a Regional RI in:

```text
ap-south-1
```

Your eligible instance usage can occur in:

```text
ap-south-1a
ap-south-1b
ap-south-1c
```

The discount can apply across the AZs rather than being locked to one AZ.

---

# 2. Zonal RI

### Definition

A **Zonal RI** is purchased for a **specific Availability Zone**.

Example:

```text
Region: ap-south-1

AZ: ap-south-1a
       ↑
   Zonal RI
```

### How it works

The RI discount applies to eligible instance usage in the **selected Availability Zone**.

```text
Region
├── AZ 1  ← RI applies here
├── AZ 2
└── AZ 3
```

There is **no AZ flexibility** according to the source.

---

# 3. Zonal RI Reserves Capacity

This is an important difference.

The screenshot states:

### Regional RI

> **Does not reserve capacity**

### Zonal RI

> **Reserves capacity in the specified Availability Zone**

So:

```text
Regional RI
→ Discount
→ No capacity reservation
```

```text
Zonal RI
→ Discount
→ Capacity reservation in specified AZ
```

---

# 4. Instance Size Flexibility

Another important difference from the screenshot:

### Regional RI

The source says the discount can apply to instance usage **within the instance family, regardless of size**, for supported Amazon Linux/Unix Reserved Instances with default tenancy.

So conceptually:

```text
Family: m4

RI
 ↓
m4.large
m4.xlarge
m4.2xlarge
...
```

There can be size flexibility within the family under the stated conditions.

### Zonal RI

The source says:

> **No instance size flexibility**

The discount applies to the **specified instance type and size only**.

Example:

```text
RI → m4.large
        ↓
applies to specified type/size
```

---

# 🔥 Regional vs Zonal RI

| Feature                   | Regional RI                             | Zonal RI                                |
| ------------------------- | --------------------------------------- | --------------------------------------- |
| Scope                     | **Region**                              | **Specific AZ**                         |
| AZ flexibility            | ✅ Yes                                   | ❌ No                                    |
| Reserves capacity         | ❌ No                                    | ✅ Yes                                   |
| Instance size flexibility | ✅ Supported in specified cases          | ❌ No                                    |
| Discount                  | Across eligible AZs in Region           | Selected AZ                             |
| Price                     | Source says scope does not affect price | Source says scope does not affect price |

# 💰 Reserved Instance (RI) Limits

This screenshot explains that AWS places **limits on how many Reserved Instances you can purchase within a month**.

> I'm following the limits and terminology shown in your source.

---

## 1. Monthly Purchase Limits

According to the screenshot, per month you can purchase:

* **20 Regional Reserved Instances per Region**
* **20 Zonal Reserved Instances per Availability Zone**

So the limit is scoped differently:

```text
Regional RI
→ 20 per Region per month
```

```text
Zonal RI
→ 20 per AZ per month
```

---

# 2. Regional RI Limits

The screenshot states that you **cannot exceed your running On-Demand Instance limit by purchasing Regional Reserved Instances**.

It gives the default On-Demand Instance limit as:

```text
20
```

### Example

Suppose your On-Demand limit is:

```text
20 instances
```

And you want to purchase:

```text
20 Regional RIs
```

You need to make sure your On-Demand limit is **at least as large as the RI quantity you intend to purchase**.

The source specifically says:

> Before purchasing RI, ensure your On-Demand limit is equal to or greater than the RI you intend to purchase.

### Memory

**Regional RI → Check your On-Demand instance limit first.**

---

# 3. Zonal RI Limits

The screenshot describes a different behavior for **Zonal RIs**.

It says you can **exceed your running On-Demand Instance limit by purchasing Zonal Reserved Instances**.

### Example from the source

Suppose:

```text
Running On-Demand instances = 20
```

Your limit is:

```text
20
```

You purchase:

```text
20 Zonal RIs
```

The source says you can then launch an additional:

```text
20 On-Demand Instances
```

that match the specifications of those Zonal RIs.

So conceptually:

```text
20 existing On-Demand
        +
20 capacity associated with Zonal RIs
        ↓
Additional eligible capacity
```
