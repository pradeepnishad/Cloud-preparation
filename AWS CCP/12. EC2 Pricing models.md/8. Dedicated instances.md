# 🖥️ EC2 Dedicated Instances

## 1. Definition

A **Dedicated Instance** is an EC2 instance that runs on **hardware dedicated to a single AWS customer**.

The key concept from your screenshot is:

> **Single tenant = dedicated hardware**

This is different from normal **multi-tenant** infrastructure, where workloads from multiple AWS customers can run on the same physical hardware.

---

# 2. Multi-Tenant vs Single-Tenant

### Multi-Tenant

Think of it like an **apartment building**:

```text
Physical Hardware
┌──────────────────────┐
│ Customer A           │
│ Customer B           │
│ Customer C           │
└──────────────────────┘
```

Multiple customers use the same underlying hardware.

They are separated through **virtual isolation**.

---

### Single-Tenant

Think of it like **everyone having their own house**:

```text
Physical Hardware
┌──────────────────────┐
│ Your AWS workloads   │
│ Your AWS workloads   │
└──────────────────────┘
```

The hardware is dedicated to one customer.

The screenshot describes this as **physical isolation**.

---

# 3. Virtual Isolation vs Physical Isolation

This is an important distinction.

### Multi-Tenant

```text
Multiple customers
       ↓
Same physical hardware
       ↓
Virtual isolation
```

The customers are logically separated using virtualization.

### Single-Tenant

```text
Single customer
       ↓
Dedicated hardware
       ↓
Physical isolation
```

---

# 4. Why Use Dedicated Instances?

The screenshot highlights:

### Regulatory requirements

Some organizations may have security or regulatory requirements concerning **sharing physical hardware with other AWS customers**.

For example:

```text
Enterprise
   ↓
Security/regulatory requirement
   ↓
Cannot share physical hardware
   ↓
Dedicated tenancy
```

The source also mentions enterprises and large organizations may have concerns or obligations about sharing hardware.

---

# 5. Dedicated Instance vs Dedicated Host

You have already learned **Dedicated Hosts**, so this distinction is very important.

### Dedicated Instance

```text
Dedicated Instance
       ↓
Your EC2 runs on
dedicated hardware
       ↓
You don't get the same
physical host-level control
```

### Dedicated Host

```text
Dedicated Host
       ↓
Entire physical server
dedicated to your account
       ↓
More visibility/control
over physical characteristics
```

Think:

> **Dedicated Instance = dedicated hardware**

> **Dedicated Host = dedicated physical server + host-level control/visibility**

# 🎯 Scenario

Suppose a large enterprise has a requirement that its workloads **must not share physical hardware with other AWS customers**.

They could use:

```text
EC2
 ↓
Dedicated tenancy
 ↓
Single-tenant hardware
 ↓
Physical isolation
```

If they additionally need **visibility/control over the physical host characteristics**, a **Dedicated Host** is the relevant option.
