# 💰 EC2 Reserved Instances (RI)

## 1. Definition

**Reserved Instances (RIs)** are designed for applications with **steady-state, predictable usage** or workloads that require reserved capacity.

Instead of paying the normal On-Demand rate, you make a **commitment for a specific term** in exchange for reduced pricing.

```text
On-Demand
→ Flexible, no long-term commitment

Reserved Instance
→ Commit for a term
→ Reduced pricing
```

---

# 2. When to Use Reserved Instances?

Use RIs when your workload is:

* **Steady**
* **Predictable**
* Running for a long period
* Expected to need consistent EC2 capacity

### Scenario

Suppose your company runs a production application 24/7.

```text
EC2
 │
 ├── Monday → Running
 ├── Tuesday → Running
 ├── Wednesday → Running
 ├── Thursday → Running
 └── ...
```

You expect to need the same capacity for years.

Instead of continuously using On-Demand pricing, you can commit to a **1-year or 3-year term**.

---

# 3. Term

Your source shows two commitment periods:

* **1 Year**
* **3 Years**

The source states:

> The longer the term, the greater the savings.

So generally:

```text
1 Year
   ↓
Lower commitment

3 Years
   ↓
Longer commitment
   ↓
Greater potential savings
```

### Important

Reserved Instances **do not automatically renew** according to your source.

When the reservation expires, the instance can continue running using **On-Demand pricing** without interruption.

---

# 4. RI Classes

Your source describes two RI classes:

### Standard RI

The source states:

> Up to 75% reduced pricing compared to On-Demand.

Standard RIs provide less flexibility but potentially greater savings.

### Convertible RI

The source states:

> Up to 54% reduced pricing compared to On-Demand.

Convertible RIs provide more flexibility because you can exchange the RI based on RI attributes for another RI of **greater or equal value**, according to the source.

### Simple comparison

|                   | Standard RI | Convertible RI |
| ----------------- | ----------- | -------------- |
| Flexibility       | Lower       | Higher         |
| Potential savings | Higher      | Lower          |
| Source example    | Up to 75%   | Up to 54%      |

🧠 **Memory:**

> **Standard = More savings, less flexibility**
> **Convertible = More flexibility, less savings**

---

# 5. Payment Options

Your source gives three payment options.

## A. All Upfront

You pay the full amount **at the beginning of the term**.

```text
Start
 ↓
Pay entire commitment
 ↓
Use RI
```

According to the source:

> Greater upfront payment → greater savings.

---

## B. Partial Upfront

You pay part of the cost at the beginning.

The remaining amount is billed at a **discounted hourly rate** during the term.

```text
Start
 ↓
Partial payment
 ↓
Discounted hourly payments
```

---

## C. No Upfront

You don't pay an upfront amount.

Instead, you are billed at a **discounted hourly rate** throughout the term, regardless of whether the Reserved Instance is actually being used.

### Important point

Your source specifically says:

> You are billed a discounted hourly rate for every hour within the term, regardless of whether the Reserved Instance is being used.

---

# 6. Payment Options Comparison

| Payment             | Upfront payment | During term            |
| ------------------- | --------------- | ---------------------- |
| **All Upfront**     | 100%            | No hourly RI payment   |
| **Partial Upfront** | Part            | Discounted hourly rate |
| **No Upfront**      | None            | Discounted hourly rate |

### Memory

> **More upfront → Greater savings**

# 🔥 On-Demand vs Reserved Instance

This is one of the most important comparisons.

|                 | On-Demand           | Reserved Instance  |
| --------------- | ------------------- | ------------------ |
| Commitment      | None                | 1 or 3 years       |
| Workload        | Short/unpredictable | Steady/predictable |
| Upfront payment | None                | Depends on option  |
| Pricing         | Standard On-Demand  | Discounted         |
| Flexibility     | High                | Lower              |
| Best concept    | Pay as you use      | Commit for savings |

### Example

**New application, unpredictable workload:**

```text
→ On-Demand
```

**Production application running continuously with predictable usage:**

```text
→ Reserved Instance
```

# 💰 Reserved Instances (RI) — RI Attributes

This screenshot explains the **4 RI Attributes** that affect which Reserved Instance applies and can affect its final price.

Think of RI attributes as the **configuration characteristics of the EC2 instance you're reserving**.

---

## 1. Instance Type

### Definition

The **instance type** identifies the EC2 compute configuration.

Example:

```text
m4.large
```

Break it down:

```text
m4 → Instance Family
large → Instance Size
```

So:

> **Instance Type = Instance Family + Instance Size**

For example:

```text
m4.large
│  │
│  └── Size
└───── Family
```

### Why it matters

Different instance types provide different combinations of:

* CPU
* Memory
* Networking
* Other compute characteristics

Therefore, the RI must correspond to the applicable instance type attributes.

---

# 2. Region

### Definition

The **Region** is the AWS geographic Region in which the Reserved Instance is purchased.

For example:

```text
ap-south-1
```

or:

```text
us-east-1
```

### Why it matters

AWS resources are generally **Region-specific**, and the RI is associated with the Region where it is purchased.

So:

```text
RI purchased in ap-south-1
        ↓
Applies to eligible usage in that Region
```

---

# 3. Tenancy

### Definition

**Tenancy determines whether your EC2 instance runs on shared (default) or single-tenant (dedicated) hardware.**

The screenshot identifies two choices:

```text
Default
   ↓
Shared hardware

Dedicated
   ↓
Single-tenant hardware
```

This connects directly to what you just learned about **EC2 tenancy**.

### Why it matters

Dedicated and default tenancy have different infrastructure characteristics and can affect the RI configuration and pricing.

---

# 4. Platform

### Definition

The **platform refers to the operating system**, such as:

* Windows
* Linux/Unix

For example:

```text
Linux/Unix
Windows
```

### Why it matters

Different operating systems can have different pricing because of applicable software licensing costs.

Therefore, the platform is an RI attribute.

---

# 🔥 The 4 RI Attributes

Memorize these four:

| # | RI Attribute      | Example              |
| - | ----------------- | -------------------- |
| 1 | **Instance Type** | `m4.large`           |
| 2 | **Region**        | `ap-south-1`         |
| 3 | **Tenancy**       | Default / Dedicated  |
| 4 | **Platform**      | Linux/Unix / Windows |

### 🧠 Memory Trick

**I → R → T → P**

> **Instance Type → Region → Tenancy → Platform**

Or simply:

> **What → Where → Hardware → OS**

```text
WHAT?      → Instance Type
WHERE?     → Region
HARDWARE?  → Tenancy
OS?        → Platform
```

---

# 🎯 Scenario

Suppose you purchase a Reserved Instance with:

```text
Instance Type → m4.large
Region        → ap-south-1
Tenancy       → Default
Platform      → Linux/Unix
```

These attributes describe the characteristics of the RI.

If you later want to use a different instance configuration, Region, tenancy, or platform, whether the RI can be changed or exchanged depends on the **RI class and applicable rules**.

---

# 📌 Final Summary

An RI's attributes help define **what kind of EC2 usage the reservation applies to**.

```text

      ├── Instance Type

```

**Instance Type = What machine?**
**Region = Where?**

**Platform = Which OS?**
