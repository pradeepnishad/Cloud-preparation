# AWS Provisioning Services

## 1. What is Provisioning?

### Definition

**Provisioning** is the **allocation or creation of resources and services for a customer**.

In AWS, provisioning services help **set up and then manage AWS services/resources**.

### Simple example

Suppose you need a web application environment:

```text
Application requirement
        ↓
Provision resources
        ↓
EC2 + S3 + Load Balancer + Auto Scaling
        ↓
Application environment ready
```

Instead of manually creating every resource, provisioning tools can automate or simplify this process.

# 2. AWS Elastic Beanstalk (EB)

### Definition

**Elastic Beanstalk is a Platform as a Service (PaaS) used to easily deploy web applications.**

According to the source, Elastic Beanstalk can provision various AWS services, including:

* EC2
* S3
* SNS
* CloudWatch
* EC2 Auto Scaling Groups
* Elastic Load Balancers

The source compares the experience to **Heroku**.

### Why use it?

You want to deploy a web application without manually setting up every underlying AWS resource.

### Scenario

You have a web application and want AWS to handle much of the environment setup.

```text
Your Web Application
        ↓
Elastic Beanstalk
        ↓
EC2 + Load Balancer
        ↓
Auto Scaling + CloudWatch + other AWS resources
```

### Memory

**Elastic Beanstalk → Easy Web-App Deployment**

# 3. AWS OpsWorks

### Definition

**AWS OpsWorks is a configuration management service.**

The source also describes it as providing managed instances of the open-source configuration-management software:

* **Chef**
* **Puppet**

### What is configuration management?

It helps maintain systems in a desired configuration.

For example:

```text
Server 1 ─┐
Server 2 ─┼──→ Desired Configuration
Server 3 ─┘
```

### Scenario

An organization has many servers and wants them configured consistently using configuration-management tools.

### Memory

**OpsWorks → Configuration Management → Chef/Puppet**

---

# 4. AWS CloudFormation

### Definition

**CloudFormation is an infrastructure modeling and provisioning service.**

You write **CloudFormation templates** using:

* JSON
* YAML

These templates describe the AWS infrastructure you want.

This is known as:

> **Infrastructure as Code (IaC)**

### Example

Instead of manually creating:

```text
VPC
 ↓
Subnet
 ↓
EC2
 ↓
Security Group
 ↓
Load Balancer
```

you define the infrastructure in a CloudFormation template.

### Why use it?

* Automate infrastructure provisioning
* Create repeatable environments
* Define infrastructure as code
* Reduce manual configuration

### Scenario

You need identical development, testing, and production infrastructure.

```text
CloudFormation Template
        ↓
Development
        ↓
Testing
        ↓
Production
```

### Memory

**CloudFormation → IaC → YAML/JSON → Provision Infrastructure**

# 5. AWS Quick Starts

### Definition

**AWS Quick Starts are pre-made packages that can launch and configure AWS compute, networking, storage, and other services required to deploy a workload on AWS.**

### Why use them?

Instead of designing and configuring everything from scratch, you can use a pre-built deployment package.

### Scenario

You want to deploy a particular workload on AWS and a Quick Start already provides the required architecture/configuration.

### Memory

**Quick Starts → Pre-made AWS deployments**

# 6. AWS Marketplace

### Definition

**AWS Marketplace is a digital catalogue of software listings from independent software vendors.**

You can use it to:

* Find software
* Buy software
* Test software
* Deploy software

### Important distinction

AWS Marketplace is **not simply an AWS-native software service**.

It provides access to software/products from independent vendors.

### Scenario

Your company needs a third-party security appliance or software product that is available through AWS Marketplace.

```text
AWS Marketplace
      ↓
Third-party software
      ↓
Deploy on AWS
```

### Memory

**Marketplace → Find & Deploy Third-Party Software**

# 7. AWS Amplify

### Definition

**AWS Amplify is a mobile and web-application framework that can provision multiple AWS services as the backend.**

It is designed to help developers build applications while integrating AWS backend capabilities.

### Scenario

A developer is building a web/mobile application and needs backend AWS services.

```text
Web/Mobile Application
          ↓
       Amplify
          ↓
   AWS Backend Services
```

### Memory

**Amplify → Web/Mobile Apps + AWS Backend**

## 1. AWS App Runner

### Definition

**AWS App Runner is a fully managed service that makes it easy for developers to quickly deploy containerized web applications and APIs at scale, without requiring prior infrastructure experience.**

### Why use it?

It simplifies deploying applications packaged as containers without requiring the developer to manage the underlying infrastructure directly.

### Scenario

You have a containerized API:

```text
Containerized Application
          ↓
     AWS App Runner
          ↓
   Running Web App / API
```

You don't need to manually build the underlying infrastructure for the application.

### Memory

> **App Runner → Easy deployment of containerized web apps/APIs**

---

# 2. AWS Copilot

### Definition

**AWS Copilot is a command-line interface (CLI) that enables customers to quickly launch and easily manage containerized applications on AWS.**

### Why use it?

It provides a simplified command-line experience for deploying and managing containerized applications.

### Scenario

You have a containerized application and want to deploy it to AWS using commands rather than manually configuring everything through the console.

```text
Developer
   ↓
AWS Copilot CLI
   ↓
AWS Container Services
   ↓
Application
```

### Memory

> **Copilot → CLI for containerized applications**

# 4. AWS Cloud Development Kit (CDK)

### Definition

**AWS CDK is an Infrastructure as Code (IaC) tool that allows you to use a programming language to define AWS infrastructure.**

The important relationship from the source is:

```text
Programming Language
        ↓
      AWS CDK
        ↓
CloudFormation Template
        ↓
   AWS Resources
```

CDK therefore provides a programming-language-based way to define infrastructure while **CloudFormation templates are generated as the means for IaC**.

### Why use it?

Instead of writing infrastructure directly in a CloudFormation YAML/JSON template, developers can define infrastructure using supported programming languages.

### Scenario

You want to create:

```text
VPC
 ├── Subnet
 ├── Security Group
 └── EC2
```

You can define the infrastructure using CDK, which generates the CloudFormation representation used to provision the resources.

### Memory

> **CDK → Programming language → CloudFormation → AWS infrastructure**

# 🔥 CloudFormation vs CDK

This distinction is important.

|                             | CloudFormation                 | AWS CDK                             |
| --------------------------- | ------------------------------ | ----------------------------------- |
| What is it?                 | IaC/provisioning service       | IaC development toolkit             |
| Define infrastructure using | YAML/JSON templates            | Programming languages               |
| Output                      | CloudFormation template itself | Synthesized CloudFormation template |
| Main idea                   | Write infrastructure template  | Write infrastructure using code     |
| Memory                      | **Template**                   | **Code → Template**                 |

### Simple example

```text
CloudFormation:

YAML/JSON
   ↓
CloudFormation
   ↓
AWS Resources
```

```text
CDK:

Python / TypeScript / Java / etc.
             ↓
            CDK
             ↓
   CloudFormation Template
             ↓
        AWS Resources
```
