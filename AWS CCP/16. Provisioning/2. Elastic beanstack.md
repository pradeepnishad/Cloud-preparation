# AWS Elastic Beanstalk

## 1. What is PaaS?

### Definition

**Platform as a Service (PaaS)** allows customers to **develop, run, and manage applications without dealing with much of the underlying infrastructure complexity**.

Instead of spending time building and maintaining the infrastructure needed to launch an application, you can focus more on the application itself.

### Simple idea

```text
You manage:
Application + Code
        ↓
     PaaS
        ↓
Provider manages much of the infrastructure
```

---

# 2. What is Elastic Beanstalk?

**AWS Elastic Beanstalk (EB) is a PaaS for deploying web applications with little-to-no knowledge of the underlying infrastructure.**

The source emphasizes that you can:

1. Choose a platform
2. Upload your code
3. Elastic Beanstalk sets up the environment
4. Your application runs

So instead of manually configuring all the infrastructure first, Beanstalk handles much of the environment setup.

### Simple flow

```text
Choose Platform
      ↓
Upload Code
      ↓
Elastic Beanstalk
      ↓
AWS Environment
      ↓
Web Application
```

---

# 3. Why Use Elastic Beanstalk?

The main purpose is to let developers **focus on writing application code rather than setting up infrastructure and deployment processes**.

The source specifically mentions reducing the need to handle:

* Infrastructure setup
* Automated deployment pipeline setup
* DevOps-related deployment tasks

### Scenario

Imagine you have a Python web application.

Without Beanstalk, you might need to configure:

```text
EC2
Load Balancer
Auto Scaling
Monitoring
Database
Deployment
```

With Elastic Beanstalk:

```text
Python Application
       ↓
Elastic Beanstalk
       ↓
AWS Environment
```

Beanstalk can set up much of the environment for you.

---

# 4. What Does Elastic Beanstalk Set Up?

The source says Elastic Beanstalk is powered by a **CloudFormation template** that sets up components such as:

### Elastic Load Balancer

Distributes incoming application traffic.

### Auto Scaling Groups

Automatically manages the number of EC2 instances according to the configured environment.

### RDS Database

Can be included as part of the environment setup.

### EC2 Instance

Runs your application using a preconfigured or custom platform.

### Monitoring

The source mentions:

* CloudWatch
* SNS

### Deployment methods

The source mentions:

* In-place deployments
* Blue/Green deployments

### Security

The source mentions security-related configuration such as password rotation.

### Docker

Elastic Beanstalk can run **Dockerized environments**.

# 6. Elastic Beanstalk and CloudFormation

This is an important relationship.

The source says:

> **Elastic Beanstalk is powered by a CloudFormation template.**

Think of it like:

```text
Developer
   │
   │ Application Code
   ↓
Elastic Beanstalk
   │
   ↓
CloudFormation
   │
   ├── EC2
   ├── Auto Scaling
   ├── Load Balancer
   ├── RDS
   └── Monitoring
```

So **Beanstalk provides the easier application deployment experience**, while CloudFormation is involved in provisioning the underlying AWS resources.

# 7. Scenario-Based Example

Suppose you're building an online shopping website using Python.

You don't want to manually configure every infrastructure component.

You select:

```text
Platform → Python
```

Then upload your application.

Elastic Beanstalk can create an environment containing resources such as:

```text
                 Internet
                    ↓
             Load Balancer
                    ↓         
            Auto Scaling Group
              ↓           ↓
            EC2          EC2
              \           /
               Application
                    ↓
                   RDS
```

You can then focus primarily on your application rather than manually building the entire infrastructure.

# 8. Elastic Beanstalk vs EC2

| EC2                                  | Elastic Beanstalk                                 |
| ------------------------------------ | ------------------------------------------------- |
| Virtual server                       | PaaS/application deployment service               |
| More infrastructure control          | More infrastructure abstraction                   |
| You manage more configuration        | AWS manages more environment setup                |
| You configure the server/application | You mainly provide application code/configuration |
| More flexibility                     | Easier application deployment                     |

### Memory

> **EC2 = Give me a server.**
> **Elastic Beanstalk = Give me an environment to run my web application.**

---

# 9. Elastic Beanstalk vs CloudFormation

| Elastic Beanstalk                     | CloudFormation                               |
| ------------------------------------- | -------------------------------------------- |
| Focuses on application deployment     | Focuses on infrastructure provisioning       |
| PaaS                                  | IaC/provisioning service                     |
| Upload application code               | Define infrastructure in templates           |
| Simplifies web-app deployment         | Can define almost any supported AWS resource |
| Uses CloudFormation behind the scenes | Direct infrastructure-as-code approach       |

### Memory

> **Beanstalk = Deploy my application**
> **CloudFormation = Define my infrastructure**
