# ☁️ AWS Cloud Computing — Common Compliance Programs

## 1. WHAT — What is Compliance?

**Compliance** means following required **laws, regulations, standards, and internal policies** to protect data, systems, and customers.

In cloud computing, compliance helps organizations prove that their cloud environment meets specific **security, privacy, and regulatory requirements**.

### Simple example
A company stores credit-card information in AWS.

It may need to comply with **PCI DSS** to ensure that cardholder data is properly protected.

> **Remember:** Compliance ≠ security itself.  
> Compliance provides requirements/standards that help an organization maintain security and meet legal obligations.

Compliance requirements depend on:

| Situation | Possible Compliance |
|---|---|
| 💳 Credit/debit card data | **PCI DSS** |

| 🔐 Cryptographic modules | **FIPS 140-2** |
| ☁️ Cloud security/privacy | **ISO/IEC 27001, 27017, 27018** |
| 🏢 Service organization's controls | **SOC 1 / SOC 2 / SOC 3** |
| 🇨🇦 Ontario healthcare data | **PHIPA** |
| 🏛️ US criminal justice information | **CJIS** |
| ☁️ Cloud provider security assessment | **CSA STAR** |

# 3. HOW — How Does Compliance Work in AWS?

AWS provides infrastructure and services that can support different compliance requirements.

However, **AWS being compliant does NOT automatically make your application compliant.**

This is an important concept related to the:

### 🔐 Shared Responsibility Model

**AWS is responsible for:**
- Physical infrastructure
- Data centers
- Hardware
- Underlying networking
- Physical security
- Certain infrastructure-level controls

**Customer is responsible for:**
- Data
- IAM permissions
- Encryption configuration
- Application security
- Operating system configuration
- Network configuration
- Security policies
- Compliance of their workload

### Example

You deploy a database containing healthcare information.

AWS may provide HIPAA-eligible services, but **you still have to configure and operate your application securely and according to HIPAA requirements.**

# 4. Important Compliance Programs

## 🔵 ISO/IEC

**ISO/IEC 27001**

An international standard for an **Information Security Management System (ISMS)**.

Focus:
- Information security
- Risk management
- Security controls
- Security processes

### Related standards

**ISO/IEC 27017**
→ Provides guidance for **cloud security controls**.

**ISO/IEC 27018**
→ Focuses on protecting **Personally Identifiable Information (PII)** in cloud environments.

**ISO/IEC 27701**
→ Focuses on **privacy information management** and protection of personal information.

### Exam memory

> **27001 → Security**  
> **27017 → Cloud Security**  
> **27018 → PII in Cloud**  
> **27701 → Privacy**

---

# 5. SOC — System and Organization Controls

SOC reports evaluate controls at a **service organization**.

### SOC 1
Focuses primarily on controls relevant to **financial reporting**.

Think:

> 💰 **SOC 1 → Financial reporting**

### SOC 2

Focuses on controls related to security and other **Trust Services Criteria**.

Common areas include:
- Security
- Availability
- Processing integrity
- Confidentiality
- Privacy

Think:

> 🔐 **SOC 2 → Security & controls**

### SOC 3

Similar subject matter to SOC 2 but designed as a **general-use report** that can be distributed more broadly.

Think:

> 🌐 **SOC 3 → Public/general distribution**

### Easy memory trick

**1 = Finance**  
**2 = Detailed controls**  
**3 = Public/general**

---

# 6. PCI DSS

### Payment Card Industry Data Security Standard

Used when organizations **store, process, or transmit payment card information**.

Example:

A company runs an online shopping website and processes credit-card payments.

→ **PCI DSS is relevant.**

### Remember:

> 💳 **PCI DSS → Payment Cards**

---

# 7. FIPS 140-2

**Federal Information Processing Standard 140-2**

A US/Canadian government standard concerning the security requirements of **cryptographic modules**.

Think:

> 🔑 **FIPS → Cryptography**

It is particularly important when government or regulated environments require validated cryptographic implementations.

---

# 8. HIPAA

### Health Insurance Portability and Accountability Act

A **US federal law** concerning protected health information.

It provides requirements around protecting:

> 🏥 **Protected Health Information (PHI)**

Example:

A healthcare company stores patient medical records in AWS.

→ HIPAA requirements may apply.

### Memory trick

> **HIPAA → Healthcare / Patient Data**

---

# 9. PHIPA

### Personal Health Information Protection Act

A privacy law in **Ontario, Canada** concerning protected health information.

Think:

> 🇨🇦 **PHIPA → Ontario healthcare information**

---

# 10. GDPR

### General Data Protection Regulation

A major **EU privacy regulation** governing personal data and privacy.

It can apply to organizations that:
- Offer goods/services to people in the EU
- Process data associated with EU residents

Important concepts include:
- Personal data protection
- Privacy
- Data subject rights
- Data processing responsibilities

### Memory trick

> 🇪🇺 **GDPR → EU Privacy**

---

# 11. FedRAMP

### Federal Risk and Authorization Management Program

A US government program that provides a standardized approach for **security assessment and authorization of cloud services** used by US federal agencies.

Think:

> 🇺🇸🏛️ **FedRAMP → US Government Cloud**

---

# 12. CJIS

### Criminal Justice Information Services

CJIS security requirements apply to organizations that access certain information from the **FBI's CJIS systems**.

Think:

> 👮 **CJIS → Criminal Justice Information**

---

# 13. CSA STAR

### Cloud Security Alliance — Security, Trust, Assurance and Risk

CSA STAR provides a framework/registry for demonstrating and assessing the **security posture of cloud providers**.

Think:

> ☁️ **CSA STAR → Cloud Security Assessment**
