# 🔐 In-Transit vs At-Rest Encryption — AWS Notes

## 1. WHAT is Encryption?

**Encryption** protects data by converting readable information (**plaintext**) into an unreadable form (**ciphertext**) using an encryption algorithm and key.

There are two important states of data:

1. **Data in transit** → data is moving between locations.
2. **Data at rest** → data is stored on storage systems or inside databases.

---

# 2. WHAT is Encryption In-Transit?

**Encryption in transit** protects data **while it is moving between two or more locations/systems**.

### Simple example

```text
Client
   │
   │ 🔐 Encrypted data
   ↓
Network / Internet
   │
   │ 🔐 Encrypted data
   ↓
Server
```

The goal is to prevent someone who intercepts the communication from reading or modifying the data.

### Examples from the material

- **TLS**
- **SSL**

---

# 3. WHERE is Encryption In-Transit Used?

It is used when data travels between:

- Client ↔ Server
- Application ↔ Application
- Browser ↔ Web server
- Services communicating over a network

### Example

When you access a website using:

```text
https://example.com
```

HTTPS uses **TLS** to protect communication between your browser and the server.

---

# 4. HOW does Encryption In-Transit Work?

A secure communication protocol establishes an encrypted connection between communicating applications.

Simplified:

```text
Client                         Server
  │                              │
  │──── Establish secure ───────>│
  │        connection             │
  │                              │
  │════ 🔐 Encrypted data ═══════>│
  │<════ 🔐 Encrypted data ═══════│
```

The data remains protected while travelling across the network.

---

# 5. WHAT is TLS?

**TLS = Transport Layer Security**

TLS is an encryption protocol used to provide **data integrity between two or more communicating computer applications**.

### Important versions

| Version | Status |
|---|---|
| TLS 1.0 | ❌ Deprecated |
| TLS 1.1 | ❌ Deprecated |
| **TLS 1.2** | ✅ Current best practice |
| **TLS 1.3** | ✅ Current best practice |

### 🎯 Exam point

> **TLS 1.2 and TLS 1.3 → current best practice** according to your material.

---

# 6. WHAT is SSL?

**SSL = Secure Sockets Layer**

SSL is an encryption protocol for providing **data integrity between two or more communicating computer applications**.

However, the SSL versions mentioned in the material are **deprecated**:

- SSL 1.0 ❌
- SSL 2.0 ❌
- SSL 3.0 ❌

### 🧠 Important

You will often hear people say:

> "SSL certificate"

But modern secure web communication uses **TLS**, not the old SSL protocols.

---

# 7. WHAT is Encryption At-Rest?

**Encryption at rest** protects data when it is **stored** on storage systems or inside databases.

```text
Application
     │
     ↓
┌───────────────┐
│ 🔐 Encrypted  │
│    Storage    │
└───────────────┘
     │
     ↓
   Database
```

Even if someone gains access to the underlying storage, the stored data is protected by encryption.

---

# 8. WHERE is Encryption At-Rest Used?

Encryption at rest is used for data stored in:

- 💾 Storage
- 🗄️ Databases
- 📁 Files
- ☁️ Cloud storage

The slide lists these algorithms:

- **AES**
- **RSA**

---

# 9. HOW does Encryption At-Rest Work?

When data is written to storage:

```text
Plaintext
    ↓
Encryption Algorithm
    +
Encryption Key
    ↓
🔐 Ciphertext
    ↓
Storage / Database
```

When authorized users need the data:

```text
Encrypted Data
      ↓
Decryption
      +
Key
      ↓
Original Data
```

---

# 10. In-Transit vs At-Rest

| Feature | 🔄 In-Transit | 💾 At-Rest |
|---|---|---|
| Protects | Moving data | Stored data |
| Location | Network | Storage / Database |
| Main concern | Network interception | Unauthorized access to stored data |
| Examples from slide | TLS, SSL | AES, RSA |
| Example | Client → Server | Data stored in database |

### 🧠 Easy memory trick

> **Transit = Traveling 🚗**  
> **Rest = Sleeping 🛏️**

If data is **moving → In Transit**.

If data is **stored → At Rest**.

---

# 11. Real-World Example

Imagine you're using a banking application.

### Step 1 — Data at rest

Your account information is stored in a database.

```text
Database
   ↓
🔐 Encrypted data
```

➡️ **Encryption at rest**

---

### Step 2 — Data in transit

You request your account balance.

```text
Phone
  │
  │ 🔐 TLS
  ↓
Bank Server
  │
  ↓
Database
```

➡️ Communication between your phone and bank server is **encrypted in transit**.

---

### Complete picture

```text
       🔄 IN TRANSIT
Phone ═══════════════> Server
       🔐 TLS

                         │
                         ↓

                    💾 AT REST
                  ┌─────────────┐
                  │ 🔐 Database │
                  └─────────────┘
```

---

# 12. 🎯 AWS / Exam-Focused Points

### Remember these:

- **In-transit → data moving**
- **At-rest → data stored**
- **TLS → protects communication in transit**
- **SSL → old/deprecated protocol**
- **TLS 1.0 & 1.1 → deprecated**
- **TLS 1.2 & 1.3 → current best practice**
- **SSL 1.0, 2.0, 3.0 → deprecated**
- **At-rest examples in the material → AES, RSA**

### ⚠️ Common exam trap

Don't confuse:

**Encryption at rest**  
→ protecting stored data

with

**Encryption in transit**  
→ protecting data while it is travelling.
