# 🔐 Hashing & Salting — TOL Format

## 1. WHAT?

### What is Hashing?

**Hashing** is a process where a function accepts an **arbitrary-size input** and maps it to a **fixed-size data structure/value**.

In simple words:

> **Hashing converts data of any size into a fixed-size hash value.**

Example:

```text
Input
"John Smith"
     ↓
 Hash Function
     ↓
   Hash
   "01"
```

### Two important properties

#### 🔹 1. One-way process
Hashing is described as a **one-way process**.

```text
Input → Hash
```

You generally don't reverse the hash to obtain the original input.

#### 🔹 2. Deterministic

A deterministic hash function **always returns the same output for the same input**.

```text
"John Smith"
      ↓
 Hash Function
      ↓
    Hash 01

"John Smith"
      ↓
 Hash Function
      ↓
    Hash 01
```

> **Same input → Same hash**

# 2. WHERE?

The slide focuses mainly on **password storage and authentication**.

### 🔐 Password Hashing

Instead of storing a user's password directly in a database as plaintext:

```text
❌ Database

Username: John
Password: MyPassword123
```

the password can be hashed:

```text
Username: John
Password Hash: 8f7a91...
```

This means the actual password doesn't reside in the database in plaintext.

### During Login

When the user enters their password:

```text
User enters password
        ↓
    Hash it
        ↓
Compare with stored hash
        ↓
     Match?
    ↙       ↘
  YES       NO
   ↓         ↓
 Login     Reject
```

If the hashes match, the user can successfully log in.

# 3. HOW?

## 🔹 Hashing Process

```text
Password
    ↓
Hash Function
    ↓
Fixed-size Hash
    ↓
Store Hash in Database
```

When authenticating:

```text
Entered Password
       ↓
  Hash Function
       ↓
New Hash
       ↓
Compare with stored hash
       ↓
   ┌───────┐
   │ Match?│
   └───────┘
      ↓
   Yes → Login
```

# 🧂 Salting

### What is a Salt?

A **salt** is a **random string** that is not known to the attacker and is accepted by the hash function to help mitigate the **deterministic nature of hashing functions**.

The important idea:

> **Salt + Password → Hash**

Instead of simply:

```text
Password → Hash
```

we use:

```text
Random Salt + Password
          ↓
     Hash Function
          ↓
        Hash
```

### Why Salt?

Hashing is deterministic.

So without salting:

```text
Password A → Hash X
Password A → Hash X
```

The same password produces the same hash.

Adding a random salt makes the resulting hash different:

```text
Password + Salt 1 → Hash A
Password + Salt 2 → Hash B
```

This makes precomputed/dictionary-based attacks more difficult.

# 🔐 Hashing vs Encryption

This is **very important** because you just learned encryption.

| Feature | Hashing | Encryption |
|---|---|---|
| Purpose | Store/verify data such as passwords | Protect data |
| Direction | **One-way** | Reversible through decryption |
| Output | Fixed-size hash | Ciphertext |
| Key required? | Not necessarily | Yes |
| Example from slide | MD5, SHA256, BCrypt | AES, RSA |

### 🧠 Easy memory

**Encryption → Lock & Unlock 🔐**

**Hashing → Fingerprint 👆**

You don't normally recover the original password from the hash; you hash the entered password and **compare the results**.

# 🎯 EXAM FOCUS

### ⭐ Must remember

**Hashing**
> Maps arbitrary-size input to a fixed-size data structure/value.

**One-way**
> Hashing is not designed to be reversed back to the original input.

**Deterministic**
> Same input → same output.

**Password hashing**
> Store the hash instead of the plaintext password.

**Authentication**
> Hash the entered password → compare with stored hash.

**Salt**
> Random string added to the hashing process to mitigate the deterministic nature of hashing.

# ⚠️ Common Exam Trap

### Hashing ≠ Encryption

If the question says:

> "The password should not be stored in plaintext and needs to be verified during login."

Think:

**➡️ Hashing**

If the question says:

> "Data needs to be encrypted and later recovered/decrypted."

Think:

**➡️ Encryption**
