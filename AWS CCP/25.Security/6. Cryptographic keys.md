# 🔑 Cryptographic Keys — TOL Format

## 1. WHAT?

### What is a Cryptographic Key?

A **cryptographic key** is a **variable used together with an encryption algorithm to encrypt or decrypt data**.

In simple words:

> **Key = the value that controls how encryption/decryption is performed.**

Think of it like a lock and key:

```text
Data + Encryption Algorithm + Key
                  ↓
             Ciphertext
```

The key is what allows the cryptographic algorithm to perform the required encryption or decryption.

---

# 2. WHERE?

Cryptographic keys are used wherever data needs to be **encrypted or decrypted**, including:

- 🔐 Protecting sensitive data
- 🌐 Secure communications
- 💾 Encrypting stored data
- ☁️ Cloud environments
- 🔑 Authentication and security systems

In AWS, key management is commonly associated with **AWS Key Management Service (KMS)**, although the uploaded slide specifically focuses on the concept of cryptographic keys and the two encryption types.

```text

   Symmetric            Asymmetric
```

# 🔵 Symmetric Encryption

### What?

**Symmetric encryption uses the same key for encoding and decoding.**

The **same key** is used for both encryption and decryption.

### How?

```text
             SAME KEY
                │
                ↓
Plaintext → ENCRYPT → Ciphertext
                         │
                         ↓
                     DECRYPT
                         │
                         ↓
                     Plaintext
```

The same key is involved in both operations.

### Example from the slide:

**AES — Advanced Encryption Standard**

### Key Point

> **Symmetric = SAME key**

### Example

Imagine:

```text
Message: "Hello World"
        ↓
     🔑 Key A
        ↓
   Encryption
        ↓
   "8f$1hF42"
        ↓
     🔑 Key A
        ↓
   Decryption
        ↓
"Hello World"
```

# 🟠 Asymmetric Encryption

### What?

**Asymmetric encryption uses two keys.**

One key is used to **encode/encrypt**, and another key is used to **decode/decrypt**.

The slide gives **RSA (Rivest–Shamir–Adleman)** as an example.

### How?

```text
       Key 1                    Key 2
         ↓                        ↓
Plaintext → ENCRYPT → Ciphertext → DECRYPT → Plaintext
```

So unlike symmetric encryption:

> **Two different keys are used.**

### Example from the slide:

**RSA — Rivest–Shamir–Adleman**

---

# ⚔️ Symmetric vs Asymmetric

| Feature | Symmetric | Asymmetric |
|---|---|---|
| Number of keys | **1** | **2** |
| Encryption key | Same key | One key |
| Decryption key | Same key | Other key |
| Example from slide | **AES** | **RSA** |
| Basic idea | Same key | Two keys |

### 🧠 Easy Memory Trick

**Symmetric = Same**

> **S**ymmetric → **S**ame key

**Asymmetric = Apart**

> **A**symmetric → **A** different/another key
