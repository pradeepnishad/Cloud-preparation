# ☁️ Amazon EC2 — Elastic Compute Cloud

The screenshot introduces **Amazon EC2**, one of the fundamental AWS compute services.

> **Amazon EC2 allows you to launch virtual machines (VMs) in the AWS Cloud.**

Think of EC2 as:

> **Renting a virtual server from AWS that you can configure according to your workload.**

---

# 1. What Is a Virtual Machine?

A **Virtual Machine (VM)** is a software-based representation/emulation of a physical computer.

Instead of having:

```text
Physical Computer
├── CPU
├── RAM
├── Disk
└── Operating System
```

you can have:

```text
Physical AWS Server
        │
        ├── VM 1
        ├── VM 2
        ├── VM 3
        └── VM 4
```

Each VM behaves like an individual computer/server.

### Simple analogy

Imagine one large physical building divided into apartments:

```text
Physical Server
┌─────────────────────────────┐
│ VM 1 │ VM 2 │ VM 3 │ VM 4  │
└─────────────────────────────┘
```

Each customer gets their own virtual environment while the underlying physical infrastructure is shared.

---

# 2. What Is Server Virtualization?

**Server virtualization** allows one physical server to run multiple virtual machines.

A virtualization layer, commonly called a **hypervisor**, manages the physical hardware and provides virtual machines to workloads.

Conceptually:

```text
             Physical Server
        ┌─────────────────────┐
        │ CPU │ RAM │ Storage  │
        └──────────┬──────────┘
                   ↓
               Hypervisor
          ┌────────┼────────┐
          ↓        ↓        ↓
         VM1      VM2      VM3
```

This allows physical resources to be used by multiple virtual machines.

# 3. Why Use Virtual Machines?

Virtualization makes it possible to create and manage servers more flexibly.

The screenshot highlights that virtualization allows you to:

* **Create**
* **Copy**
* **Resize**
* **Migrate**

servers/VMs.

For example:

```text
Create VM
   ↓
Run application
   ↓
Need more resources?
   ↓
Resize VM
```

Instead of physically replacing a server, you can modify the virtual machine configuration.

# 4. What Is an EC2 Instance?

This is an important AWS term.

When you launch a virtual machine in EC2, AWS calls it an:

> **EC2 instance**

So:

```text
Virtual Machine
      ↓
When launched in EC2
      ↓
EC2 Instance
```

For example:

```text
EC2 Instance
├── Operating System
├── CPU
├── RAM
├── Networking
└── Storage
```

### Exam memory:

> **Instance = a running EC2 virtual machine.**

# 6. What Is an AMI?

The screenshot introduces an important term:

> **AMI = Amazon Machine Image**

An **AMI is a predefined/template configuration used to launch an EC2 instance.**

Think of an AMI as a **starting blueprint for your virtual machine**.

For example:

```text
AMI
 ↓
Operating system + configuration
 ↓
Launch EC2 instance
```

You can choose an AMI containing an operating system such as:

```text
Windows
Ubuntu
Amazon Linux
```

---

# 7. AMI vs EC2 Instance

Don't confuse these two.

### AMI

```text
AMI = Template/image used to launch a VM
```

### EC2 Instance

```text
Instance = Running VM created from an AMI
```

Think about a photograph:

```text
AMI → Blueprint/template

EC2 Instance → Actual running machine
```

Example:

```text
Ubuntu AMI
     ↓
Launch
     ↓
EC2 Instance
```

---

# 8. What Does an AMI Affect?

The screenshot says that your AMI affects options such as:

* Operating System
* CPU
* Memory
* Network bandwidth
* Storage configuration

A useful clarification is that **AMI and instance type are different choices**:

```text
AMI
 ↓
Primarily provides the machine image/software starting point

Instance Type
 ↓
Determines compute characteristics such as CPU and memory
```

For example:

```text
Ubuntu AMI
      +
t3.micro instance type
      ↓
Ubuntu EC2 instance
```

---

# 9. Instance Type

An **EC2 instance type** determines the compute resources available to your instance.

For example, different instance types can provide different amounts of:

```text
CPU
Memory
Network performance
Other workload-specific capabilities
```

Conceptually:

```text
          EC2 Instance
                │
        ┌───────┴────────┐
        ↓                ↓
      AMI          Instance Type
        ↓                ↓
      OS          CPU / RAM / etc.
```

So when launching EC2, think:

> **AMI = What software/image do I start with?**

> **Instance type = What compute capacity do I get?**

---

# 10. Storage — EBS

The screenshot mentions:

> **Elastic Block Store (EBS)**

Amazon EBS provides **block storage volumes** that can be attached to EC2 instances.

Think of EBS as the virtual disk for your EC2 instance.

```text
EC2 Instance
      │
      ↓
   EBS Volume
      │
      ↓
   Data / Files
```

You can attach multiple EBS volumes to an EC2 instance where supported.

For example:

```text
EC2
├── EBS Volume 1 → OS
├── EBS Volume 2 → Application data
└── EBS Volume 3 → Logs
```

# 14. EC2 and Shared Responsibility

This connects directly to the topic you just studied.

With EC2:

### AWS manages:

```text
Physical Data Center
       ↓
Physical Hardware
       ↓
Physical Networking
       ↓
Underlying Virtualization
```

### Customer manages:

```text
EC2 Instance
       ↓
Guest OS
       ↓
OS Configuration/Patching
       ↓
Applications
       ↓
Data
```

So:

> **EC2 gives you significant control, but that also means more customer responsibility.**

# 15. Is EC2 a Physical Server?

No.

For the customer, EC2 is presented as a **virtual server/instance**.

Behind the scenes, AWS operates the physical infrastructure.

```text
You see:

EC2 Instance
     ↓
Virtual Server


AWS operates:

Physical Server
     ↓
Virtualization
     ↓
Multiple workloads
```

This is the key benefit of cloud virtualization.

# 16. EC2 and Other AWS Services

The screenshot describes EC2 as the **backbone of AWS** and gives examples of services such as S3, RDS, DynamoDB and Lambda.

For your Cloud Practitioner study, don't interpret this as meaning that every AWS service is simply "an EC2 server you manage." AWS services abstract their underlying infrastructure from you to varying degrees.

The important concept is:

> **EC2 is AWS's fundamental virtual-server compute service, while many other AWS services provide higher-level managed capabilities.**

For example:

```text
EC2
↓
Virtual server
↓
You manage more of the environment

Lambda
↓
Serverless compute
↓
AWS manages the underlying servers
```
