# 1. What is a Relational Database?

### Definition

A **relational database** stores data in **tables**, where data is organized into:

* Tables
* Rows
* Columns
* Relationships between tables

It normally uses **SQL (Structured Query Language)** to work with the data.

### Example

A customer table:

| Customer_ID | Name    | City   |
| ----------- | ------- | ------ |
| 101         | Pradeep | Mumbai |
| 102         | Rahul   | Delhi  |

An orders table:

| Order_ID | Customer_ID | Product |
| -------- | ----------- | ------- |
| 5001     | 101         | Laptop  |
| 5002     | 102         | Phone   |

The `Customer_ID` can connect the two tables.

### Why use a relational database?

Relational databases are useful when:

* Data has a structured format.
* You need relationships between data.
* You need SQL queries.
* You have transactional workloads.
* Data consistency is important.

### Example

An e-commerce application could use a relational database for:

```text
Customers
    ↓
Orders
    ↓
Products
    ↓
Payments
```

# 2. What is Amazon RDS?

### Definition

**Amazon RDS (Relational Database Service)** is a **managed relational database service** provided by AWS.

Instead of manually setting up and maintaining database servers, AWS manages much of the underlying infrastructure for you.

Think:

```text
Traditional:

You
 ↓
Server
 ↓
Operating System
 ↓
Database
 ↓
Data


Amazon RDS:

You
 ↓
RDS
 ↓
Database
 ↓
Data
```

AWS takes care of much of the underlying infrastructure management.

---

## Why use RDS?

Without RDS, you could launch an EC2 instance and install MySQL yourself.

You would then have to deal with things such as:

* Server management
* OS maintenance
* Database installation
* Patching
* Backups
* Infrastructure management

With RDS, AWS provides a **managed database platform**, allowing you to focus more on the database and application.

# 4. Amazon Aurora

### Definition

**Amazon Aurora is a fully managed relational database designed to be compatible with MySQL and PostgreSQL.**

Think:

```text
                Aurora
               /      \
          MySQL      PostgreSQL
        compatible   compatible
```

### Why use Aurora?

According to the screenshot, Aurora is useful when you want:

* High availability
* Scalability
* Security
* Managed relational database functionality
* MySQL or PostgreSQL compatibility

### Scenario

Suppose you're building a large e-commerce application.

You need:

```text
Customers
Orders
Products
Payments
```

You want a relational database, but you don't want to manage the underlying database infrastructure yourself.

You could use **Aurora**.

# 5. Aurora Serverless

### Definition

**Aurora Serverless** is the serverless/on-demand version of Aurora.

The important idea is that database capacity can be adjusted based on workload rather than you continuously managing fixed database capacity.

The screenshot describes it as:

> The serverless on-demand version of Aurora.

### When would you use it?

When database traffic is:

* Variable
* Unpredictable
* Intermittent

For example:

```text
Morning
↓
Low traffic

Afternoon
↓
High traffic

Night
↓
Very low traffic
```

A serverless approach can be useful for workloads with changing demand.

### Scenario

Imagine a college examination-result website.

Most of the year:

```text
100 users
```

On result day:

```text
500,000 users
```

The database workload changes dramatically.

A serverless database architecture can be useful for this type of variable workload.

# 6. RDS on VMware

### Definition

The screenshot also mentions **RDS on VMware**.

It allows supported RDS database engines to be deployed in an **on-premises data center using VMware for server virtualization**.

The key idea is:

```text
Your Data Center
       ↓
     VMware
       ↓
   RDS database
```

### Why use it?

It is useful when an organization wants:

* Databases managed through RDS
* But still wants/needs the database infrastructure to run in its own data center
* VMware as the virtualization platform

### Scenario

An enterprise has:

```text
Company Data Center
        ↓
      VMware
        ↓
Existing applications
```

The organization wants database management capabilities associated with RDS while keeping the deployment in its own data center.

# 🔥 RDS vs Aurora vs Aurora Serverless

| Service               | Think about                                              |
| --------------------- | -------------------------------------------------------- |
| **Amazon RDS**        | Managed relational databases                             |
| **Aurora**            | AWS relational database compatible with MySQL/PostgreSQL |
| **Aurora Serverless** | Aurora with serverless/on-demand capacity                |
| **RDS on VMware**     | RDS database deployment on VMware/on-premises            |

---

# 🧠 Important distinction: RDS vs Database Engine

This is very important.

**RDS is the managed service/platform.**

The **database engine** is the actual database technology running within it.

Think:

```text
                 Amazon RDS
                     │
       ┌─────────────┼──────────────┐
       ↓             ↓              ↓
     MySQL       PostgreSQL     SQL Server
       │             │              │
       └─────────────┼──────────────┘
                     ↓
              Managed by AWS
```

Aurora is also an AWS-managed relational database engine.

# Relational Database vs NoSQL

Connect this with the previous screenshot you studied:

| Relational               | NoSQL                                    |
| ------------------------ | ---------------------------------------- |
| Tables                   | Flexible data models                     |
| Rows/columns             | Key-value/document/etc.                  |
| SQL                      | NoSQL-specific APIs/query models         |
| Structured relationships | Flexible structures                      |
| RDS                      | DynamoDB                                 |
| Aurora                   | DocumentDB                               |
| MySQL                    | Keyspaces/Cassandra-compatible workloads |

### Simple memory

> **RDS → Relational**
> **DynamoDB → Key-value + Document**
> **DocumentDB → MongoDB-compatible document database**
> **Keyspaces → Cassandra-compatible NoSQL**
> **Aurora → AWS relational database**
