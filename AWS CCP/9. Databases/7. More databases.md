# 🗄️ Other AWS Database Services

This screenshot covers database services that are **specialized for particular workloads**, rather than being general relational or NoSQL databases.

The services shown are:

1. **Amazon Redshift** → Data warehouse
2. **Amazon ElastiCache** → In-memory cache
3. **Amazon Neptune** → Graph database
4. **Amazon Timestream** → Time-series database
5. **Amazon Quantum Ledger Database (QLDB)** → Ledger database
6. **AWS Database Migration Service (DMS)** → Database migration

---

# 1. Amazon Redshift

### Definition

**Amazon Redshift is a cloud data warehouse designed for analyzing very large amounts of data.**

The screenshot describes it as a **petabyte-size data warehouse**.

A data warehouse is primarily used for **OLAP — Online Analytical Processing**.

### What does OLAP mean?

OLAP is about **analyzing data**, rather than processing individual day-to-day transactions.

For example:

```text
Sales Database
       ↓
   Redshift
       ↓
Analyze:
- Total sales
- Monthly revenue
- Best-selling products
- Customer trends
- Year-over-year growth
```

### Why use Redshift?

Use Redshift when you need to:

* Analyze huge amounts of data
* Generate reports
* Perform analytics
* Run complex queries over large datasets
* Find business trends

### Scenario

An e-commerce company has **10 TB of historical sales data**.

Management asks:

> "What were our sales for each product in each region over the last 5 years?"

That's an **analytics/data warehouse** workload.

→ **Amazon Redshift**

### 🧠 Exam memory

> **Redshift = Data Warehouse = Analytics = OLAP**

# 2. Amazon ElastiCache

### Definition

**Amazon ElastiCache is a managed in-memory caching service.**

The screenshot specifically mentions:

* Redis
* Memcached

The basic idea is:

> Keep frequently accessed data in memory so applications can retrieve it faster.

### Why use a cache?

Imagine your application repeatedly requests:

```text
Popular product → Product information
```

Without caching:

```text
Application
    ↓
Database
    ↓
Data
```

Every request hits the database.

With caching:

```text
Application
    ↓
ElastiCache
    ↓
Data returned quickly
```

This can reduce database workload and improve application response time.

### Scenario

An e-commerce website has a product that thousands of users request every minute.

Instead of repeatedly querying the database, frequently accessed information can be cached.

→ **ElastiCache**

### 🧠 Exam memory

> **ElastiCache = In-memory cache = Faster application**

And remember:

> **Redis / Memcached → ElastiCache**

# 3. Amazon Neptune

### Definition

**Amazon Neptune is a managed graph database service.**

A graph database represents data as **nodes and relationships/connections**.

Think:

```text
Person A
   │
   ├── Friend of ──→ Person B
   │
   └── Works with ─→ Person C
```

The important thing isn't just the individual data points.

It's the **relationships between them**.

### Why use Neptune?

Use it when you need to understand complex relationships between data.

### Scenario 1 — Social media

```text
Pradeep
   ↓ follows
Rahul
   ↓ follows
Amit
```

A graph database can represent these relationships naturally.

### Scenario 2 — Fraud detection

```text
Account A
    ↓
Phone Number X
    ↓
Account B
    ↓
Credit Card Y
```

You can analyze connections to identify suspicious relationships.

### 🧠 Exam memory

> **Neptune = Graph = Relationships**

If the question says:

**"Need to understand connections between data"**

→ **Amazon Neptune**

# 4. Amazon Timestream

### Definition

**Amazon Timestream is a managed time-series database.**

A time-series database is designed for data where **time is an important part of every measurement**.

Examples:

```text
10:00 → CPU = 40%
10:01 → CPU = 45%
10:02 → CPU = 52%
10:03 → CPU = 48%
```

The data changes **over time**.

### Why use Timestream?

Use it when you need to measure and analyze how something changes over time.

### Scenario

Imagine monitoring 10,000 servers.

Every minute you collect:

```text
Server 1
CPU → 50%
Memory → 70%
Temperature → 45°C
Timestamp → 10:05
```

This is a time-series workload.

Other examples:

* IoT sensor data
* Application metrics
* Infrastructure monitoring
* Device telemetry

### 🧠 Exam memory

> **Timestream = Time-series data = Things changing over time**

# 5. Amazon Quantum Ledger Database — QLDB

### Definition

**Amazon Quantum Ledger Database (QLDB) is a managed ledger database designed to maintain a transparent and immutable history of transactions.**

The key concepts are:

* **Ledger**
* **History**
* **Immutable**
* **Transparent**
* **Cryptographically verifiable**

### What does "immutable" mean?

It means the historical record is designed so that previous transactions cannot simply be altered or deleted without the change being detectable.

Think:

```text
Transaction 1
      ↓
Transaction 2
      ↓
Transaction 3
      ↓
Transaction 4
```

You maintain a trustworthy history of what happened.

### Why use QLDB?

Use it when you need a **trusted history of transactions or changes**.

### Scenario

A financial organization needs to maintain the history of account transactions:

```text
Account created
      ↓
₹10,000 deposited
      ↓
₹2,000 withdrawn
      ↓
₹5,000 deposited
```

The organization wants a verifiable history of those changes.

→ **QLDB**

### 🧠 Exam memory

> **QLDB = Ledger = Immutable transaction history**

# 6. AWS Database Migration Service — DMS

### Definition

**AWS Database Migration Service (AWS DMS) is a service used to migrate databases and data between supported environments.**

This is different from the other services in your screenshot.

The others are **database services**.

DMS is primarily a **database migration service**.

### What can DMS migrate?

Your screenshot highlights migrations:

```text
On-premises database
        ↓
       AWS
```

or:

```text
AWS Account A
      ↓
AWS Account B
```

or:

```text
One database engine
      ↓
Another database engine
```

### Why use DMS?

Organizations may already have databases running on:

* On-premises servers
* Another AWS environment
* Another database engine

DMS helps move the database/data to the target environment.

### Scenario

A company has:

```text
On-Premises
MySQL
   ↓
   DMS
   ↓
AWS
RDS
```

The company wants to migrate its database to AWS.

→ **AWS DMS**

### 🧠 Exam memory

> **DMS = Database Migration Service = Move databases**
