# 🌊 Streaming

## 1. What is Streaming?

**Streaming** is a way of processing **continuous streams of events/messages**, where **multiple consumers can read the same events**.

The key difference from a traditional queue is that events can **remain in the stream for a period of time**, allowing consumers to read and process them.

### Simple idea

```text
              ┌── Consumer A
              │
Producer → Stream ── Consumer B
              │
              └── Consumer C
```

Multiple consumers can read the same stream of events.

---

## 2. Key Characteristics

### Multiple consumers

Unlike a simple queue where a message is generally consumed by one consumer, streaming allows **multiple consumers to read events**.

For example:

```text
Event: User purchased a product

        ↓
   Kinesis Stream
    ↙     ↓      ↘
Analytics  S3   Database
```

Different consumers can process the same event for different purposes.

### Events remain in the stream

Events **live in the stream for a period of time**.

This means consumers can process the events and perform more complex operations on the data.

### Real-time

Streaming is designed for **real-time or near-real-time processing** of continuously arriving data.

# 3. Amazon Kinesis

**Amazon Kinesis** is AWS's fully managed solution for:

* Collecting streaming data
* Processing streaming data
* Analyzing streaming data

The basic architecture from your source is:

```text
Producers
   ↓
Kinesis Data Streams
   ↓
Consumers
```

### Producers can include:

* EC2 instances
* Mobile applications
* Clients
* Traditional applications

### Consumers can include:

* Amazon Redshift
* Amazon DynamoDB
* Amazon S3
* Amazon EMR

---

# 4. Shards

Your diagram shows the Kinesis stream divided into **shards**:

```text
Kinesis Data Stream

 ┌──────────┐
 │ Shard 1  │
 ├──────────┤
 │ Shard 2  │
 ├──────────┤
 │    ...   │
 ├──────────┤
 │ Shard N  │
 └──────────┘
```

Think of shards as **units within a Kinesis data stream used to organize and process streaming data**.

# 5. Scenario Example

Imagine an e-commerce application generating events:

```text
Customer clicks
Customer searches
Customer adds item
Customer purchases
```

These events continuously enter Kinesis:

```text
Website / Mobile App
        ↓
Kinesis Data Streams
        ↓
 ┌──────┼────────┐
 ↓      ↓        ↓
S3   DynamoDB  Redshift
```

Different consumers can use the same streaming data for different purposes.

For example:

* **S3** → store data
* **DynamoDB** → application-related processing
* **Redshift** → analytics
* **EMR** → big-data processing

# 6. Queueing vs Streaming

This is **very important for AWS exams**.

| Queueing                                     | Streaming                          |
| -------------------------------------------- | ---------------------------------- |
| Amazon SQS                                   | Amazon Kinesis                     |
| Messages                                     | Events/streaming data              |
| Consumer generally pulls messages            | Consumers can read the stream      |
| Messages generally deleted after consumption | Events remain for a period of time |
| Simple asynchronous communication            | Continuous data processing         |
| Usually one consumer processes a message     | Multiple consumers can read events |
| Good for decoupling workloads                | Good for real-time streaming       |

### 🧠 Easy memory

**SQS → Queue → Message → Consume**

**Kinesis → Stream → Events → Multiple Consumers → Real-time**
