# 📬 Queueing

## 1. What is a Messaging System?

A **messaging system** provides **asynchronous communication** between processes/applications using **messages or events**.

There are generally two sides:

* **Producer / Sender** → sends the message
* **Consumer / Receiver** → receives and processes the message

### Simple idea

```text
Producer
   ↓
Message
   ↓
Messaging System
   ↓
Consumer
```

The important concept is **decoupling**.

The producer doesn't necessarily need to communicate directly with the consumer at the exact same time.

---

# 2. What is a Queueing System?

A **queueing system** is a type of messaging system where messages are placed into a **queue** and are generally **deleted after they are consumed**.

```text
Producer
   ↓
 ┌─────────────┐
 │   Queue     │
 │ Message 1   │
 │ Message 2   │
 │ Message 3   │
 └─────────────┘
        ↓
    Consumer
```

The consumer **pulls** messages from the queue and processes them.

### Key characteristics from your source:

* **Asynchronous**
* **Simple communication**
* **Not real-time**
* Consumer has to **pull** messages
* **Not reactive**
* Messages are generally removed after consumption

---

# 3. Amazon SQS

**Amazon Simple Queue Service (SQS)** is a **fully managed queuing service**.

It allows you to:

* Decouple applications
* Decouple microservices
* Scale distributed systems
* Build serverless applications
* Pass messages between producers and consumers

### Basic architecture

```text
Producer
   ↓
  SQS Queue
   ↓
Consumer
```

The producer puts a message into SQS.

The consumer retrieves the message and processes it.

---

# 4. Why Use SQS?

Suppose you have a website where users sign up.

When a user registers:

```text
User
 ↓
Website
 ↓
SQS Queue
 ↓
Email Service
 ↓
"Welcome to our application!"
```

Instead of making the website wait for the email service to immediately send the email, the website can place an email task into the queue.

The email service can process it afterward.

This creates **decoupling** between the application and email service.

# 6. Queueing vs Direct Communication

### Without queue

```text
Application A ─────────→ Application B
```

A directly depends on B being available.

### With queue

```text
Application A
     ↓
    SQS
     ↓
Application B
```

A can put the work into the queue, and B can process it later.

This is the **decoupling** benefit.
