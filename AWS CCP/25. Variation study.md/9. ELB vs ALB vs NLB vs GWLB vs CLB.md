# ⚖️ ELB vs ALB vs NLB vs GWLB vs CLB

First, **ELB = Elastic Load Balancing**.

ELB is the AWS service/category that provides different types of load balancers.

```text
                    ELB
                     │
        ┌────────────┼────────────┐
        ↓            ↓            ↓
       ALB          NLB          GWLB
    Layer 7       Layer 3/4    Gateway
        │
       CLB
    Legacy/Classic
```

---

# 1. 🟠 Application Load Balancer — ALB

### Layer 7 — HTTP/S

ALB operates at the **Application Layer (Layer 7)**.

It understands **HTTP/HTTPS requests**, so it can make routing decisions based on information inside the request.

### Example

You could route:

```text
example.com/users
       ↓
      ALB
       ↓
   User Server

example.com/products
       ↓
      ALB
       ↓
 Product Server
```

The slide specifically mentions:

> Create rules to change routing based on information found in an HTTP/S request.

### ALB can also attach to AWS WAF

So:

```text
Internet
   ↓
  ALB
   ↓
  WAF protection
   ↓
Application
```

### 🧠 Remember

**ALB = Application = HTTP/S = Layer 7**

---

# 2. 🔵 Network Load Balancer — NLB

NLB operates at:

### **Layer 3 and Layer 4**

The slide highlights:

- TCP
- UDP
- TLS

NLB is designed when you need **extreme performance**.

The slide says it can handle:

> **Millions of requests per second**

while maintaining:

> **Ultra-low latencies**

It's also optimized for:

> **Sudden and volatile traffic patterns**

### Example

Imagine your application suddenly receives:

```text
10,000 requests/sec
       ↓
100,000 requests/sec
       ↓
1,000,000 requests/sec
```

NLB is designed for these kinds of **high-performance network traffic** scenarios.

### Important point

The slide also mentions:

> A single static IP address per Availability Zone

That's an important NLB characteristic for exam questions.

### 🧠 Remember

**NLB = Network = TCP/UDP/TLS = Layer 3/4 = Extreme performance**

---

# 3. 🟣 Gateway Load Balancer — GWLB

GWLB is different from ALB/NLB.

Its purpose is to deploy a **fleet of third-party virtual network appliances**.

The slide specifically mentions:

> Appliances that support **GENEVE**

Think of things like network/security appliances sitting between your traffic and applications.

```text
Traffic
   ↓
 GWLB
   ↓
┌───────────────────┐
│ Virtual Appliances│
│                   │
│ Security / Network│
│ Appliances        │
└───────────────────┘
   ↓
Application
```

### 🧠 Remember

**GWLB = Gateway = virtual network appliances**

And from your slide:

**GENEVE → GWLB**

---

# 4. ⚫ Classic Load Balancer — CLB

This is the **old/legacy** load balancer.

The slide says it supports:

### Layer 3, 4 and 7

It was intended for applications built within the:

> **EC2-Classic network**

The important point is that **CLB is legacy**.

The slide also notes:

> Doesn't use Target Groups

and:

> Retires on Aug 15, 2022

So for your exam memory:

**CLB = Old/Classic/Legacy**

# 🔥 The Big Comparison

| Load Balancer | Layer | Main Traffic / Purpose | Remember |
|---|---|---|---|
| **ALB** | Layer 7 | HTTP/S | Application routing |
| **NLB** | Layer 3 & 4 | TCP/UDP/TLS | Extreme performance |
| **GWLB** | Gateway | Network appliances | GENEVE |
| **CLB** | Layer 3, 4 & 7 | Legacy applications | Old/Classic |
