# AWS Config vs AWS AppConfig

## 1. AWS Config 🔧

### What is it?
**AWS Config = monitors and evaluates the configuration of AWS resources.**

Think:

> **"Are my AWS resources configured correctly according to my rules?"**

For example, you can create a rule:

> "All EC2 instances must have EBS encryption enabled."

AWS Config checks your EC2 instances against that requirement.

### What can it do?

**AWS Config can:**
- Record resource configurations
- Track configuration changes
- Check resources against compliance rules
- Detect configuration drift
- Identify non-compliant resources
- Trigger remediation in some cases

### Example

You have:

```text
EC2
 ├── Encryption: YES ✅
 ├── Port 22: restricted ✅
 └── Required tags: YES ✅
```

Someone changes the configuration:

```text
EC2
 ├── Encryption: NO ❌
 ├── Port 22: Open ❌
 └── Required tags: YES ✅
```

AWS Config can detect that the resource is now **non-compliant**.

### Exam keyword

> **AWS Config = Resource configuration + compliance + drift**

---

# 2. AWS AppConfig ⚙️

This one is completely different.

### What is it?

**AWS AppConfig = safely deploy configuration changes to applications.**

Think:

> **"I have an application. How can I change its configuration without breaking it?"**

For example, your application has:

```text
MAX_LOGIN_ATTEMPTS = 5
```

You want to change it to:

```text
MAX_LOGIN_ATTEMPTS = 3
```

Instead of modifying and redeploying the entire application, **AppConfig can manage and deploy that configuration change safely.**

---

## AppConfig can provide

### Validation

You can validate a configuration before deploying it.

```text
New configuration
       ↓
    Validate
       ↓
   Valid? ✅
       ↓
    Deploy
```

If it's invalid:

```text
New configuration
       ↓
    Validate
       ↓
   Invalid ❌
       ↓
    Reject
```

### Controlled deployment

AppConfig can also help deploy configuration changes gradually and monitor them.

For example:

```text
1000 users
   ↓
Deploy new configuration
   ↓
10% users
   ↓
Monitor
   ↓
No problem?
   ↓
100% users
```

This reduces the risk of breaking the application.

---

# 🔥 The easiest way to remember

| AWS Config | AWS AppConfig |
|---|---|
| **AWS resource configuration** | **Application configuration** |
| Checks compliance | Deploys config changes |
| Detects configuration drift | Safely changes application settings |
| EC2, S3, IAM, etc. | Web/app configuration |
| Governance/compliance | Application deployment |
| **"Is my resource configured correctly?"** | **"Can I safely change my application's configuration?"** |

### 🧠 Memory trick

**CONFIG → Infrastructure**

**APPCONFIG → Application**

That's the main distinction you need for the AWS Practitioner exam.

---

## 🎯 Exam-style question

**A company wants to continuously check whether its EC2 instances comply with its organization's security configuration requirements. Which AWS service should it use?**

✅ **AWS Config**

---

**Another question:**

**A company wants to safely deploy configuration changes to its application without deploying a new version of the application. Which service should it use?**

✅ **AWS AppConfig**

---

### One-line revision

> **AWS Config = "Is my AWS infrastructure configured correctly?"**  
> **AWS AppConfig = "Can I safely change my application's configuration?"**

This is the key takeaway from the slide.
