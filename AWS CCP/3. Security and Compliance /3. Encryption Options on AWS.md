# 🔐 Encryption Options on AWS

## 1. Definition

**Encryption** is the process of converting readable data (**plaintext**) into an unreadable form (**ciphertext**) so that unauthorized people cannot understand it.

> **Encryption protects data by making it unreadable without the appropriate key.**

Example:


Plaintext
   ↓
Encryption + Key
   ↓
Ciphertext
   ↓
Decryption + Key
   ↓
Plaintext


AWS provides multiple encryption options to protect data **at rest** and **in transit**.

---

# 2. Types of Encryption

There are two major categories you need to know:

### 🔒 Encryption at Rest

Protects data while it is **stored**.

Examples:

* Data stored in Amazon S3
* EBS volumes
* RDS databases
* Backups


Data
 ↓
Storage
 ↓
🔒 Encrypted


---

### 🌐 Encryption in Transit

Protects data while it is **moving between systems**.

For example:


User
  ↓
🔒 HTTPS / TLS
  ↓
AWS Application


Commonly achieved using **TLS/SSL**, such as HTTPS.

---

# 3. Why Use Encryption?

Encryption helps protect sensitive information from unauthorized access.

It can protect:

* Customer information
* Passwords
* Financial information
* Business data
* Application data
* Backups
* Files

It is particularly important for organizations with **security, regulatory, or compliance requirements**.

---

# 4. AWS Key Management Service (AWS KMS)

One of the most important AWS services related to encryption is **AWS Key Management Service (AWS KMS)**.

### Definition

**AWS KMS** is a managed service that allows you to **create and control cryptographic keys** used to protect your data.

Simple:

> **KMS = AWS service for managing encryption keys.**


             AWS KMS
                ↓
          Encryption Key
                ↓
      ┌─────────┼─────────┐
      ↓         ↓         ↓
     S3        EBS       RDS
      ↓         ↓         ↓
   Encrypted  Encrypted  Encrypted
     Data       Data       Data


KMS can integrate with many AWS services.

---

# 5. AWS Encryption Options

There are generally three important approaches to understand.

## A. AWS-owned / service-managed encryption

AWS services can provide encryption capabilities where AWS manages the encryption keys and much of the key-management process.

This is convenient when you don't need detailed control over the keys.

---

## B. AWS KMS keys

You can use **AWS KMS** to manage encryption keys and control how they are used.

Benefits include:

* Centralized key management
* Access control through IAM/key policies
* Integration with AWS services
* Auditing of key usage
* Ability to control key lifecycle

---

## C. Customer-provided / customer-managed keys

For workloads requiring greater control, you can use **customer-managed KMS keys**.

This gives you more control over things such as:

* Key policies
* Permissions
* Rotation settings
* Key lifecycle
* Auditing

The trade-off is:

> **More control → more responsibility.**

---

# 6. Symmetric vs Asymmetric Encryption

You may also encounter these terms.

### Symmetric encryption

Uses the **same key** for encryption and decryption.


        Same Key
       ↙       ↘
Encrypt       Decrypt
   ↓             ↓
Ciphertext → Plaintext


It is commonly used for efficiently encrypting data.

### Asymmetric encryption

Uses a **key pair**:

* Public key
* Private key


Public Key
    ↓
Encryption
    ↓
Ciphertext
    ↓
Private Key
    ↓
Decryption


The two keys are mathematically related but different.

For your Cloud Practitioner foundation, the main thing is to understand the **concept**, rather than getting deep into cryptographic mathematics.

---

# 7. How to Use Encryption on AWS

Encryption is generally enabled/configured at the AWS service level.

For example:

### S3

You can configure objects to be encrypted when stored.


Application
     ↓
     S3
     ↓
Encrypted Object


### EBS

You can encrypt EBS volumes attached to EC2 instances.


EC2
 ↓
Encrypted EBS Volume
 ↓
Encrypted Data


### RDS

You can enable encryption for supported RDS databases.


Application
     ↓
    RDS
     ↓
Encrypted Database


The exact encryption options differ by service.

---

# 8. When Should You Use Encryption?

You should consider encryption whenever you're storing or transmitting sensitive information.

Especially for:

* Personally sensitive/customer data
* Financial data
* Credentials/secrets
* Business-critical information
* Regulated data
* Backup data
* Data that must meet compliance requirements

A good security architecture generally considers **both at-rest and in-transit encryption**.

---

# 9. Scenario-Based Example

Imagine you're building an online banking application.

You have:


Customer
   ↓
HTTPS/TLS
   ↓
Application
   ↓
Encrypted RDS
   ↓
Encrypted backups


### In transit

The customer's information is protected while travelling between the customer and application using **TLS/HTTPS**.

### At rest

The database and backups are encrypted while stored.

### Keys

AWS KMS can be used to manage the encryption keys.

So:


Customer
   ↓
🔒 TLS
   ↓
Application
   ↓
🔒 RDS encryption
   ↓
🔒 Backup encryption


This provides multiple layers of data protection.

---

# 10. Encryption and Shared Responsibility

This connects directly to the previous topic.

AWS provides encryption capabilities and secure infrastructure, but **the customer is responsible for configuring and using security controls appropriately**.

For example:


AWS
 ↓
Provides KMS
 ↓
Provides encryption capabilities

Customer
 ↓
Chooses appropriate encryption
 ↓
Configures permissions
 ↓
Manages customer-controlled keys
 ↓
Protects access to keys


Therefore:

> **AWS provides the security tools; customers are responsible for using/configuring them appropriately according to their requirements.**

| More control over encryption keys | Customer-managed KMS key  |

### Very important distinction

**Encryption ≠ Authentication**


Encryption
→ Protects confidentiality of data

Authentication
→ Determines who you are

Authorization
→ Determines what you are allowed to do


For example:

> IAM authentication identifies the user, while encryption protects the data.
