# 🔐 AWS Root User

## 1. Definition

The **AWS root user** is the identity created when you first create an AWS account.

It has **complete access to all AWS resources and services in that AWS account**.

Simple definition:

> **Root user = the original AWS account identity with unrestricted access to the account.**

---

## 2. What Is the Root User?

When you create an AWS account, you provide an email address and password.

That account identity is the **root user**.


Create AWS Account
       ↓
Root User
       ↓
Full access to AWS account


The root user is **different from an IAM user**.

### Root user


AWS Account
    ↓
Root User
    ↓
Full account-level access


### IAM user


AWS Account
    ↓
IAM
    ↓
IAM User
    ↓
Specific permissions


IAM users should normally be used for everyday AWS work instead of the root user.

---

# 3. Why Is the Root User Important?

The root user has permissions that are extremely powerful and, for some account-level tasks, may be required.

However:

> **You should NOT use the root user for normal daily AWS activities.**

If an attacker gains access to the root account credentials, the consequences can be extremely serious because of the level of access available.

---

# 4. How Should You Secure the Root User?

The first thing you should do after creating an AWS account is **secure the root user**.

### 🔒 1. Enable MFA

Enable **Multi-Factor Authentication (MFA)** for the root user.


Password
   +
MFA
   ↓
Root User


Even if someone obtains the password, they would also need the additional authentication factor.

---

### 🔑 2. Use a strong password

The root account should have a strong, unique password.

---

### 🚫 3. Don't use it for everyday tasks

Instead:


Root User
   ↓
Account-level tasks only


For normal work:


IAM Identity Center / IAM
   ↓
Appropriate user/role
   ↓
AWS resources


---

### 🗝️ 4. Don't create root access keys unless absolutely necessary

Root access keys provide programmatic access with extremely powerful permissions.

For normal automation or CLI/API access, use appropriate **IAM roles or other controlled identities** instead.

---

# 5. When Should You Use the Root User?

Use the root user **only for tasks that specifically require root-level account access**.

Examples can include certain:

* Account-level settings
* Account closure
* Root-user credential management
* Certain billing/account operations
* Tasks that explicitly require root-user credentials

For ordinary tasks such as:

* Launching EC2
* Creating S3 buckets
* Managing applications
* Managing databases
* Configuring normal AWS resources

you should use appropriate IAM identities/roles instead.

---

# 6. Scenario-Based Example

Imagine you create a new AWS account.


AWS Account
     ↓
Root User


You need to set up your environment.

### ❌ Bad approach

Use the root user to:


Launch EC2
Create S3
Create databases
Deploy applications
Manage users


every day.

### ✅ Better approach


Root User
    ↓
Secure with MFA
    ↓
Perform only necessary account-level tasks


Then:


IAM Identity / Role
        ↓
Required permissions
        ↓
EC2 / S3 / RDS / etc.


This follows the security principle of **least privilege**.

---

# 7. Root User vs IAM User

| Root User                            | IAM User                                      |
| ------------------------------------ | --------------------------------------------- |
| Created with AWS account             | Created through IAM                           |
| Extremely powerful                   | Permissions can be controlled                 |
| Full account access                  | Specific permissions                          |
| Not for daily use                    | Can be used when appropriate                  |
| Should have MFA                      | Should also use strong authentication/MFA     |
| Used for limited account-level tasks | Used for normal AWS access depending on setup |

---

# 8. Root User vs IAM Role

This distinction becomes important later.

### Root user

Represents the **AWS account owner identity**.

### IAM role

Provides **temporary permissions** that can be assumed by users, applications, AWS services, or other trusted entities.

For example:


EC2
 ↓
IAM Role
 ↓
Permission to access S3


The application doesn't need to store long-term AWS access keys.

→ **Root user**

### "Should not be used for everyday tasks"

### "Secure the root user with MFA"

### "Use an identity with only required permissions"

→ **Least privilege**
