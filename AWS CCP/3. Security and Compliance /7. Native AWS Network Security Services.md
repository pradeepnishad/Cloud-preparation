# 🔐 Native AWS Network Security Services

## 1. Definition

**Native AWS Network Security Services** are AWS-built services and features used to **protect network traffic, control access to resources, and detect or prevent network-based threats** within an AWS environment.

Simple definition:

> **AWS network security = controlling who can communicate with your resources, what traffic is allowed, and how suspicious traffic is detected or blocked.**

A basic security flow looks like:


Internet
   ↓
AWS Network Security Controls
   ↓
VPC
   ↓
Application Resources
   ↓
EC2 / RDS / etc.


---

# 2. Main AWS Network Security Services

For your Cloud Practitioner foundation, focus on these:

| Service / Feature        | Main purpose                                        |
| ------------------------ | --------------------------------------------------- |
| **Security Groups**      | Control inbound/outbound traffic for resources      |
| **Network ACLs (NACLs)** | Control traffic at subnet level                     |
| **AWS WAF**              | Protect web applications from common web attacks    |
| **AWS Shield**           | Protect against DDoS attacks                        |
| **AWS Firewall Manager** | Centrally manage firewall/security policies         |
| **AWS Network Firewall** | Managed network firewall for VPCs                   |
| **Amazon GuardDuty**     | Threat detection and suspicious activity monitoring |

Let's understand the important ones.

# 3. Security Groups

## Definition

A **Security Group** acts as a **virtual firewall for AWS resources**, such as EC2 instances.

It controls:

* Inbound traffic
* Outbound traffic

Example:


Internet
   ↓
Security Group
   ↓
EC2


You can specify rules such as:


Allow TCP 443 → HTTPS
Allow TCP 22  → SSH


### Why use it?

To control which network traffic can reach your resource.

### Scenario

You have a web server:


Internet
   ↓
Security Group
   ↓
EC2


You allow:


HTTPS → 443


but don't allow unnecessary ports.

### Important exam point

> **Security Groups are associated with resources/ENIs and are stateful.**

If traffic is allowed in one direction, the response traffic is automatically allowed.

---

# 4. Network ACLs (NACLs)

## Definition

A **Network Access Control List (NACL)** is a network-level security control that controls traffic **at the subnet level**.


VPC
 │
 ├── Subnet A
 │      ↓
 │    NACL
 │      ↓
 │    EC2
 │
 └── Subnet B


### Why use it?

To control traffic entering or leaving a subnet.

### Important difference

| Security Group              | NACL                              |
| --------------------------- | --------------------------------- |
| Resource level              | Subnet level                      |
| Stateful                    | **Stateless**                     |
| Supports allow rules        | Supports allow and deny rules     |
| Rules evaluated for traffic | Rules evaluated in numbered order |

### Exam shortcut:

> **Security Group → resource**

> **NACL → subnet**

---

# 5. AWS WAF

## Definition

**AWS WAF (Web Application Firewall)** helps protect web applications from common web-based attacks.

It can inspect HTTP/HTTPS requests and allow or block them based on rules.


User
 ↓
HTTP/HTTPS Request
 ↓
AWS WAF
 ↓
Application


It can help protect against threats such as:

* SQL injection
* Cross-site scripting (XSS)
* Malicious HTTP requests
* Unwanted traffic patterns

### Scenario

A company hosts an online store.

An attacker sends suspicious SQL injection requests:


Attacker
   ↓
Malicious HTTP request
   ↓
AWS WAF
   ↓
🚫 Block


### Memory:

> **WAF → Web Application Firewall**

---

# 6. AWS Shield

## Definition

**AWS Shield** is a managed service that helps protect AWS applications against **DDoS (Distributed Denial of Service) attacks**.

DDoS attack:


Thousands/millions of requests
          ↓
       Application
          ↓
      Overwhelmed


AWS Shield helps protect against these attacks.

There are two levels:

* **AWS Shield Standard**
* **AWS Shield Advanced**

For Cloud Practitioner, remember the basic distinction:

> **Shield → DDoS protection**

---

# 7. AWS Network Firewall

## Definition

**AWS Network Firewall** is a managed, stateful network firewall that provides protection for traffic flowing through your Amazon VPC.

It provides more advanced network traffic inspection and filtering than basic security controls.

Conceptually:


Network Traffic
      ↓
AWS Network Firewall
      ↓
Allow / Block / Inspect
      ↓
VPC Resources


### When to use it?

When you need more advanced centralized network traffic filtering and inspection within a VPC.

For the Cloud Practitioner level, remember:

> **Network Firewall → managed firewall for VPC network traffic.**

---

# 8. Amazon GuardDuty

## Definition

**Amazon GuardDuty** is a threat detection service that continuously analyzes relevant AWS data sources to identify potentially malicious or unauthorized activity.


AWS Environment
      ↓
GuardDuty
      ↓
Analyze activity
      ↓
Potential threat detected
      ↓
Finding / Alert


### Important distinction

GuardDuty is primarily for **detecting threats**, not acting as your basic network firewall.

### Memory:

> **GuardDuty → Detect threats**

---

# 9. AWS Firewall Manager

## Definition

**AWS Firewall Manager** helps centrally configure and manage firewall and security policies across AWS accounts and resources.

This becomes particularly useful in organizations using **AWS Organizations** with multiple accounts.


                 Firewall Manager
                       ↓
          ┌────────────┼────────────┐
          ↓            ↓            ↓
       Account A    Account B    Account C
          ↓            ↓            ↓
      Security      Security     Security
       Policy        Policy       Policy


### Memory:

> **Firewall Manager → Manage security policies centrally across accounts.**

# 10. How These Services Work Together

Imagine an AWS-hosted web application:


                         INTERNET
                            │
                            ↓
                       AWS Shield
                       DDoS protection
                            │
                            ↓
                         AWS WAF
                    Web request filtering
                            │
                            ↓
                    Load Balancer / App
                            │
                            ↓
                     Security Group
                    Resource protection
                            │
                            ↓
                           EC2
                            │
                            ↓
                           RDS


And at the network level:


             VPC
              │
           NACL
              │
           Subnet
              │
     Network Firewall
              │
          Resources


Meanwhile:


AWS Environment
      ↓
  GuardDuty
      ↓
Threat detection


Each tool addresses a different security problem.

# 11. When Should You Use Which?

| Requirement                                        | Service                  |
| -------------------------------------------------- | ------------------------ |
| Control traffic to EC2                             | **Security Group**       |
| Control traffic at subnet level                    | **NACL**                 |
| Protect web application                            | **AWS WAF**              |
| Protect against DDoS                               | **AWS Shield**           |
| Advanced VPC network firewall                      | **AWS Network Firewall** |
| Detect suspicious/malicious activity               | **GuardDuty**            |
| Centrally manage security policies across accounts | **Firewall Manager**     |

# 12. Scenario-Based Example

Suppose you're running an online shopping website.

You want to protect it from several types of threats.

### Problem 1: DDoS attack


Massive traffic
     ↓
AWS Shield
     ↓
DDoS protection


### Problem 2: Malicious web request


HTTP Request
     ↓
AWS WAF
     ↓
Malicious request → 🚫


### Problem 3: Unauthorized network connection to EC2


Network traffic
     ↓
Security Group
     ↓
Unauthorized port → 🚫


### Problem 4: Suspicious activity in AWS


AWS activity
     ↓
GuardDuty
     ↓
Threat detection
     ↓
Finding


### Problem 5: Organization has 50 AWS accounts


50 AWS accounts
       ↓
Firewall Manager
       ↓
Central security policies


This is why you shouldn't think of AWS security as **one service**. Different services solve different security problems.
