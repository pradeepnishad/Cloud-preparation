# 🚌 Amazon EventBridge — Event Bus

## 1. What is an Event Bus?

An **event bus** receives events from a source and **routes those events to targets based on rules**.

Simple flow:

```text
Source
  ↓
Event Bus
  ↓
Rules
  ↓
Target
```

The important idea is:

**Event Bus = receive events → evaluate rules → route events**

---

# 2. Amazon EventBridge

**Amazon EventBridge** is a **serverless event bus service** used for application integration by streaming real-time event data to applications.

It allows different AWS services and applications to communicate through **events**, without needing to be directly connected.

```text
AWS Services / Applications
          ↓
     EventBridge
          ↓
        Rules
          ↓
       Targets
```

---

# 3. How EventBridge Works

### Step 1 — Producer generates an event

AWS services or partner applications can generate events.

For example:

```text
EC2 state changed
       ↓
Event
```

### Step 2 — Event enters an Event Bus

The event is sent to an EventBridge event bus.

```text
Event → Event Bus
```

### Step 3 — Rules inspect the event

Rules determine **which events should be captured and where they should be sent**.

For example:

```text
Rule:
If EC2 instance enters "stopped" state
        ↓
Send event to Lambda
```

### Step 4 — Event is sent to a Target

The matching event is routed to a target.

```text
Event Bus
    ↓
  Rule
    ↓
 Lambda
```

# 4. EventBridge Event Buses

Your screenshot identifies **three types**.

### ① Default Event Bus

Every AWS account has a **default event bus**.

AWS services can emit events to it.

```text
AWS Services
     ↓
Default Event Bus
```

---

### ② Custom Event Bus

A **custom event bus** can be used for your own application events and can be scoped for multiple accounts or other AWS accounts.

Think:

```text
Application
     ↓
Custom Event Bus
```

---

### ③ SaaS Event Bus

A **SaaS event bus** is used for events coming from supported **third-party SaaS providers**.

Your screenshot shows examples of partner sources.

```text
Third-party SaaS
       ↓
SaaS Event Bus
       ↓
     Rules
       ↓
    Targets
```

---

# 5. Rules

A **rule determines what events to capture and pass to targets**.

Think of a rule as:

> **IF this event happens → THEN send it here.**

Example:

```text
IF:
EC2 instance state = stopped

THEN:
Send event → Lambda
```

Another example:

```text
IF:
New object/event occurs

THEN:
Send event → processing service
```

---

# 6. Targets

**Targets are AWS services or other destinations that consume the events.**

The screenshot shows EventBridge routing events to targets such as:

* Lambda
* Other AWS services

The important concept for the exam is:

```text
Event → Rule → Target
```

---

# 7. Partner Sources

EventBridge can also receive events from **third-party applications/SaaS providers**.

Your screenshot describes partner sources as:

> Third-party apps that can emit events to an event bus.

So EventBridge can act as an integration point between AWS and external SaaS applications.

---

# 8. Scenario Example

Imagine an application where you want something to happen whenever an EC2 instance changes state.

```text
EC2
 ↓
"Instance stopped" event
 ↓
EventBridge
 ↓
Rule:
"Match EC2 stopped events"
 ↓
Lambda
 ↓
Take action
```

The EC2 service doesn't need to directly call the Lambda function.

**EventBridge handles the event routing.**

# 🆚 EventBridge vs SNS vs SQS vs Kinesis

This is worth remembering because these services can look similar.

| Service            | Main purpose                               |
| ------------------ | ------------------------------------------ |
| **SQS**            | Queue messages for asynchronous processing |
| **SNS**            | Pub/Sub notification and fanout            |
| **Kinesis**        | Streaming data/events                      |
| **EventBridge**    | Event bus + rules-based event routing      |
| **Step Functions** | Orchestrate multi-step workflows           |

### 🧠 Memory trick

**SQS → Queue**

**SNS → Notify/Fanout**

**Kinesis → Stream**

**EventBridge → Events + Rules + Routing**

**Step Functions → Workflow**
