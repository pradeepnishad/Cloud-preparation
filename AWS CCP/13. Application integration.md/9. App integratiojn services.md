# ☁️ AWS Application Integration Services

This screenshot summarizes the major AWS services used to help **applications communicate, exchange messages, process events, coordinate workflows, and expose APIs**.

A useful way to organize them is:

```text
Messaging → Streaming → Workflows → Events → APIs
```

---

# 1. Amazon SNS — Simple Notification Service

### Definition

**Amazon SNS** is a **pub-sub messaging system**.

It allows a publisher to send a message that can then be delivered to multiple subscribers.

### How it works

```text
Publisher
    ↓
  SNS Topic
    ↓
 ┌──┼─────────┐
 ↓  ↓         ↓
SQS Lambda   Email
```

SNS can send notifications through formats such as:

* Email
* HTTP/HTTPS webhooks
* SMS
* SQS
* Lambda

### Why use it?

When you want **one message/event to reach multiple subscribers**.

### Scenario

A payment succeeds:

```text
Payment Service
      ↓
     SNS
   ↙ ↓  ↘
Email SQS Lambda
```

### Memory

**SNS = Send/Notify**

---

# 2. Amazon SQS — Simple Queue Service

### Definition

**Amazon SQS** is a **queuing messaging service**.

Messages are placed into a queue, and another application **pulls** messages from the queue for processing.

```text
Producer
   ↓
 SQS Queue
   ↓
Consumer
```

### Why use it?

To **decouple applications** and handle work asynchronously.

### Common use

Background jobs.

Example:

```text
Website
   ↓
SQS
   ↓
Worker
   ↓
Process Job
```

### Scenario

A website receives 10,000 image-processing requests.

Instead of processing everything immediately:

```text
Requests → SQS → Workers → Process images
```

### Memory

**SQS = Queue**

---

# 3. AWS Step Functions

### Definition

**Step Functions** is a **state machine service** used to coordinate multiple AWS services into **serverless workflows**.

Think of it as a **visual flowchart for application logic**.

```text
Start
  ↓
Lambda
  ↓
Check Result
 ↙     ↘
Success  Failure
 ↓        ↓
Lambda   Retry
 ↓
End
```

### Why use it?

When an application has **multiple logical steps** that must happen in a particular sequence.

### Scenario

An order-processing system:

```text
Receive Order
      ↓
Validate Order
      ↓
Process Payment
      ↓
Update Database
      ↓
Send Notification
      ↓
Complete
```

Step Functions can coordinate these steps.

### Memory

**Step Functions = Workflow**

---

# 4. Amazon EventBridge

### Definition

**EventBridge** is a **serverless event bus** that connects applications, AWS services, and third-party services.

It receives events and routes them based on **rules**.

```text
Event Source
     ↓
EventBridge
     ↓
   Rule
     ↓
 Target
```

### Why use it?

For **event-driven application integration**.

### Scenario

```text
EC2 instance changes state
          ↓
      EventBridge
          ↓
    Rule matches event
          ↓
        Lambda
```

### Memory

**EventBridge = Event Routing**

---

# 5. Amazon Kinesis

### Definition

**Amazon Kinesis** is a **real-time streaming data service**.

Producers send data into a stream, and multiple consumers can read/process that data.

```text
Producer  →  Kinesis Stream  →  Consumer
Producer  →        ↑         →  Consumer
Producer  →        │         →  Consumer
```

### Why use it?

For **real-time data processing and analytics**.

The screenshot gives examples such as:

* Real-time analytics
* Click streams
* IoT device data

### Scenario

Thousands of IoT devices continuously send temperature readings:

```text
IoT Devices
     ↓
  Kinesis
     ↓
Real-time Processing
     ↓
Analytics / Storage
```

### Memory

**Kinesis = Streaming**

---

# 6. Amazon MQ

### Definition

**Amazon MQ** is a **managed message broker service** based on **Apache ActiveMQ**.

It is useful when applications already use traditional message brokers/protocols and you want AWS to manage the broker infrastructure.

### Why use it?

When you need a managed message broker and compatibility with **ActiveMQ-based applications**.

### Memory

**Amazon MQ = Managed Message Broker**

---

# 7. Amazon MSK — Managed Streaming for Apache Kafka

### Definition

**Amazon MSK** is a **fully managed Apache Kafka service**.

Kafka is an open-source platform used for building **real-time streaming data pipelines and applications**.

### Why use it?

For large-scale, robust **real-time streaming architectures** using Kafka.

### Scenario

```text
Applications
     ↓
   Kafka/MSK
     ↓
Streaming Processing
     ↓
Analytics / Databases
```

### Kinesis vs MSK

| Kinesis                 | MSK                                               |
| ----------------------- | ------------------------------------------------- |
| AWS streaming service   | Managed Apache Kafka                              |
| AWS-native streaming    | Kafka ecosystem                                   |
| Real-time streaming     | Real-time streaming                               |
| Simpler AWS integration | Useful when Kafka compatibility/ecosystem matters |

### Memory

**MSK = Managed Kafka**

---

# 8. Amazon API Gateway

### Definition

**API Gateway** is a fully managed AWS service for developers to **create, publish, maintain, monitor, and secure APIs**.

It acts as a **front door** for applications to access backend services.

```text
Client
  ↓
API Gateway
  ↓
Backend Services
```

### Why use it?

To expose backend functionality through APIs without directly exposing every backend component.

### Scenario

A mobile application needs customer information:

```text
Mobile App
    ↓
API Gateway
    ↓
Lambda / Database
    ↓
Response
```

### Memory

**API Gateway = API Front Door**

---

# 9. AWS AppSync

### Definition

**AWS AppSync** is a **fully managed GraphQL service**.

GraphQL allows applications to query data from different data sources through a unified API.

### Why use it?

When an application needs a **GraphQL API** that can retrieve data from multiple sources.

### Scenario

A mobile application needs:

```text
User information
     +
Orders
     +
Products
```

Instead of interacting separately with multiple backend sources, AppSync can provide a GraphQL interface.

### Memory

**AppSync = Managed GraphQL**

# 🧠 All Services — Quick Revision

| Service            | Remember it as                    |
| ------------------ | --------------------------------- |
| **SNS**            | Pub/Sub & notifications           |
| **SQS**            | Queue & asynchronous jobs         |
| **Step Functions** | Workflow / state machine          |
| **EventBridge**    | Event bus & routing               |
| **Kinesis**        | Real-time streaming               |
| **Amazon MQ**      | Managed message broker / ActiveMQ |
| **MSK**            | Managed Apache Kafka              |
| **API Gateway**    | API front door                    |
| **AppSync**        | Managed GraphQL                   |

### The easiest exam memory

```text
SNS         → Notify
SQS         → Queue
Step Func.  → Workflow
EventBridge → Events
Kinesis     → Stream
Amazon MQ   → Message Broker
MSK         → Kafka
API Gateway → APIs
AppSync     → GraphQL
```

### Key distinction

**SNS vs SQS**

```text
SNS → Push messages to subscribers
SQS → Consumer pulls messages from queue
```

**Kinesis vs EventBridge**

```text
Kinesis     → continuous streaming data
EventBridge → events + rules + routing
```

**SQS vs Step Functions**

```text
SQS            → holds work/messages
Step Functions → coordinates workflow steps
```

**API Gateway vs AppSync**

```text
API Gateway → API management/front door
AppSync     → GraphQL API
```
