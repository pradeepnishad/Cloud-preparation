# 📢 Pub/Sub — Publish/Subscribe

## 1. What is Pub/Sub?

**Publish/Subscribe (Pub/Sub)** is a messaging pattern commonly used in **messaging systems**.

In Pub/Sub, publishers **do not send messages directly to subscribers**.

Instead:

```text
Publisher
    ↓
 Event Bus
    ↓
Subscriber
```

The **event bus** receives and categorizes messages into groups/topics, and subscribers subscribe to the groups they are interested in.

---

## 2. How does Pub/Sub work?

### Step 1 — Publisher sends an event

A **publisher** creates a message/event.

```text
Publisher → Event Bus
```

The publisher doesn't need to know who will receive it.

### Step 2 — Event Bus categorizes the message

The event bus organizes messages into appropriate groups/subscriptions.

### Step 3 — Subscriber subscribes

Subscribers subscribe to the groups they are interested in.

```text
                 ┌→ Subscriber A
Publisher → Event Bus → Subscriber B
                 └→ Subscriber C
```

### Step 4 — Message is pushed

When a new message matches a subscription, it is **automatically and immediately pushed** to the subscribers.

Subscribers **do not pull** the messages.

---

# 3. Why use Pub/Sub?

The major benefit is **decoupling**.

The publisher doesn't need to know:

* Who the subscribers are
* How many subscribers exist
* Where they are
* How they process the message

This allows publishers and subscribers to operate independently.

---

# 4. Scenario Example

### 💬 Real-time chat system

Suppose a user sends:

> "Hello!"

The chat application publishes this event:

```text
User → Publisher
          ↓
       Event Bus
       ↙   ↓   ↘
    User A User B User C
```

The subscribers receive the event immediately.

The publisher doesn't need to directly communicate with each individual user.

# 5. Webhooks

Your source also mentions **web-hook systems** as a use case.

A webhook can be used to automatically notify another system when an event occurs.

For example:

```text
Order Created
      ↓
   Event Bus
      ↓
   Webhook
      ↓
External Application
```

---

# 6. Important Characteristics

From your source:

* **Publishers don't know who their subscribers are.**
* Subscribers **do not pull** messages.
* Messages are **automatically and immediately pushed** to subscribers.
* **Messages and events** can be used interchangeably in the Pub/Sub context.

# 🆚 Pub/Sub vs Queueing vs Streaming

| Feature            | Queueing                                  | Streaming                   | Pub/Sub                          |
| ------------------ | ----------------------------------------- | --------------------------- | -------------------------------- |
| Example            | SQS                                       | Kinesis                     | EventBridge/SNS-style pattern    |
| Main idea          | Queue messages                            | Continuous events           | Publish events to subscribers    |
| Communication      | Asynchronous                              | Continuous                  | Event-driven                     |
| Consumer behavior  | Pull                                      | Read stream                 | Messages pushed to subscribers   |
| Multiple consumers | Usually message processed by one consumer | Multiple consumers can read | Multiple subscribers can receive |
| Main use           | Decouple workloads                        | Real-time data              | Event notification/distribution  |

### 🧠 Memory trick

**Queue → "Someone needs to process this."**

**Stream → "Keep processing this continuous data."**

**Pub/Sub → "Tell everyone who's interested."**

### 🎯 Exam Focus

If you see:

> **Publisher doesn't know the subscribers**

→ **Pub/Sub**

> **Messages automatically pushed to subscribers**

→ **Pub/Sub**

> **Real-time event notification**

→ **Pub/Sub**

> **Simple asynchronous queue**

→ **SQS**

> **Continuous streaming data**

→ **Kinesis**

**Summary:**
**Pub/Sub = Publisher → Event Bus → Subscribers, where subscribers receive matching events automatically without the publisher needing to know who they are.**
