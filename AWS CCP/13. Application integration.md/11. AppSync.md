# AWS AppSync

## 1. Definition

**AWS AppSync is a fully managed GraphQL service** that helps applications access and work with data from multiple data sources through GraphQL APIs.

Simple idea:

> **AppSync = Managed GraphQL API layer between your application and your data sources.**

It can also support **real-time APIs using GraphQL subscriptions**.

---

## 2. How AppSync works

Basic architecture:

```text
Application
    ↓
Amplify SDK
    ↓
AWS AppSync
    ↓
GraphQL API
    ↓
Resolvers
   ↙     ↘
DynamoDB  Lambda
```

### Resolver

A **resolver** is attached to a specific field in your GraphQL schema.

It determines **how the data for that field is obtained or changed**.

For example:

```text
Query → getProject
              ↓
          Resolver
              ↓
          DynamoDB
```

The resolver connects the GraphQL operation to the appropriate data source.

### Data Source

A **data source** is where AppSync gets or sends data.

The screenshots list:

* DynamoDB Table
* Amazon OpenSearch
* AWS Lambda Function
* HTTP Endpoint
* Amazon EventBridge
* Relational Database (RDS HTTP Endpoint)

---

# 3. API Types

### GraphQL APIs

A single GraphQL API can access **multiple data sources**.

For example:

```text
             AppSync
           /    |    \
     DynamoDB Lambda  HTTP
```

The application can interact through one GraphQL API rather than directly communicating with every backend.

### Merged APIs

A collection of GraphQL APIs can act as **one API**.

Useful when multiple teams manage their own APIs but you want applications to interact with them as a single API.

---

# 4. Caching

AppSync provides caching options:

### None

No caching.

Resolvers fetch data directly from the data sources.

### Full Request Caching

Caches all requests.

Useful when the same requests are repeatedly made.

### Per-Resolver Caching

Caching is applied to a specific operation or field defined in a resolver.

**Important from the source:** caching requires you to provision an on-demand instance, so the caching capability described here is **not serverless**.

---

# 5. Authorization

The screenshots list these AppSync authorization types:

* **API Key**
* **AWS IAM**
* **Amazon Cognito User Pools**

These determine **who is allowed to access the GraphQL API**.

For example:

```text
User
 ↓
Authentication / Authorization
 ↓
AppSync
 ↓
GraphQL API
```

# 6. Resolver Runtimes

### VTL

**Velocity Template Language**, used for AppSync resolver templates.

# 7. Real-Time APIs

One important feature:

**AppSync supports real-time APIs through GraphQL subscriptions.**

For example, imagine a chat application:

```text
User A
   ↓
AppSync
   ↓
Subscription
 ↙     ↘
User B  User C
```

When relevant data changes, subscribed clients can receive updates.

---

# 8. When would you use AppSync?

Use AppSync when an application needs a **GraphQL API**, especially when:

* Data comes from multiple sources.
* You want a managed GraphQL backend.
* Different clients need different portions of data.
* You need real-time updates through GraphQL subscriptions.
* You want authorization integrated with the API.

### Scenario

Imagine an e-commerce application:

```text
Mobile App
     ↓
  AppSync
   ↓ ↓ ↓
DynamoDB Lambda OpenSearch
```

The mobile application can use GraphQL queries to request the data it needs, while AppSync resolvers determine which backend data source provides that information.

## AppSync vs API Gateway

| AppSync                                       | API Gateway                                            |
| --------------------------------------------- | ------------------------------------------------------ |
| GraphQL service                               | API management service                                 |
| GraphQL APIs                                  | REST/HTTP/WebSocket APIs                               |
| Uses resolvers                                | Uses routes/integrations                               |
| Can connect to multiple data sources          | Routes requests to backend integrations                |
| GraphQL subscriptions for real-time use cases | Supports API communication through supported API types |

### Exam Memory

**AppSync → GraphQL**

Remember:

> **AppSync = Fully managed GraphQL + Resolvers + Data Sources + Real-time subscriptions**

And the key flow:

**Application → AppSync → Resolver → Data Source**
