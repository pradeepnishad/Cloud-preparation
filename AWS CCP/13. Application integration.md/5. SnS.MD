# 📢 Amazon SNS — Simple Notification Service

Based on your screenshot:

## 1. What is Amazon SNS?

**Amazon Simple Notification Service (SNS)** is a **fully managed Pub/Sub messaging service** used to **decouple**:

* Microservices
* Distributed systems
* Serverless applications

Simple architecture:

```text
Publishers
    ↓
 SNS Topic
    ↓
Message Filtering / Fanout
    ↓
Subscribers
```

---

## 2. How SNS works

### Step 1 — Publisher sends a message

Publishers can include:

* AWS SDK
* AWS CLI
* CloudWatch
* Other AWS services

They publish a message to an **SNS Topic**.

```text
AWS Service
    ↓
SNS Topic
```

### Step 2 — SNS Topic

The **SNS Topic** acts as the central point for distributing messages.

The publisher doesn't need to communicate directly with each subscriber.

### Step 3 — Message filtering & fanout

SNS can distribute the message to multiple subscribers.

```text
                 ┌→ Lambda
                 │
Publisher → SNS ─┼→ SQS
                 │
                 ├→ Email
                 │
                 └→ HTTP/S
```

This is called **fanout** — one published message can be delivered to multiple destinations.

---

# 3. SNS Subscribers

According to your screenshot, subscribers can include:

### AWS Lambda

SNS can trigger a Lambda function when a message arrives.

### Amazon SQS

SNS can publish messages into an SQS queue.

This is particularly useful when multiple applications need to receive the same event independently.

### Email

SNS can send notifications through email.

### HTTP/S

SNS can send notifications to an HTTP/HTTPS endpoint.

---

# 4. What is Decoupling?

Suppose you have an application that needs to notify several systems:

```text
Order Created
     ↓
Application
   ↙ ↓ ↘
Email  Analytics  Inventory
```

Without SNS, your application may need to communicate directly with each system.

With SNS:

```text
Order Created
     ↓
   SNS Topic
   ↙   ↓    ↘
Email SQS Lambda
```

The application only needs to publish the event to SNS.

**SNS handles distributing it to the subscribers.**

This reduces dependencies between components.

---

# 5. Real-World Scenario

Imagine an e-commerce application.

A customer places an order:

```text
Customer places order
        ↓
     SNS Topic
    ↙    ↓     ↘
 Lambda  SQS   Email
    ↓     ↓      ↓
Process  Queue  Notification
order   work
```

One event can therefore trigger multiple independent actions.

---

# 6. SNS vs SQS

This distinction is **very important**.

| SNS                                        | SQS                                            |
| ------------------------------------------ | ---------------------------------------------- |
| Pub/Sub                                    | Queue                                          |
| Push-based                                 | Pull-based                                     |
| One message can go to multiple subscribers | Message is generally processed by one consumer |
| Notification/distribution                  | Decoupling/work queue                          |
| Fanout                                     | Queue processing                               |
| SNS Topic                                  | SQS Queue                                      |

### Easy memory:

**SNS → Send/Notify**

**SQS → Store/Queue**

---

# 7. SNS + SQS Together

A very common architecture is:

```text
             ┌→ SQS Queue A → Consumer A
             │
Publisher → SNS Topic
             │
             └→ SQS Queue B → Consumer B
```

SNS provides **fanout**, while SQS allows each application to **process messages asynchronously**.

For example, an order event can be sent to multiple SQS queues, with different applications processing each queue independently.

## 🎯 Exam Focus

If the question says:

> **Pub/Sub messaging**

→ **Amazon SNS**

> **Send one message to multiple subscribers**

→ **SNS**

> **Fanout**

→ **SNS**

> **Push notifications/messages to subscribers**

→ **SNS**

> **Queue messages for asynchronous processing**

→ **SQS**

> **SNS + multiple SQS queues**

→ **Fanout architecture**

### 🧠 Memory

**SNS = Publish → Topic → Push → Subscribers**

**SQS = Queue → Store → Consumer pulls**

### Summary

**Amazon SNS is a fully managed Pub/Sub service where publishers send messages to an SNS Topic, and SNS distributes those messages to one or more subscribers such as Lambda, SQS, Email, or HTTP/S.**
