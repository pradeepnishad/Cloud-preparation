# 💻 EC2 Capacity Reservations

## 1. Definition

**Capacity Reservation is an EC2 feature that allows you to reserve compute capacity for a specific EC2 instance type in a specific Region and Availability Zone (AZ).**

The main problem it solves is:

> **What if you need to launch a specific EC2 instance type, but AWS doesn't currently have enough capacity for that instance type in your chosen AZ?**

---

# 2. Why is Capacity Reservation Needed?

EC2 instances run on physical AWS infrastructure.

For a particular instance type/family, there is a **finite amount of available server capacity within an Availability Zone**.

For example:

```text
Region
  │
  └── Availability Zone
        │
        ├── Available c4.2xlarge capacity
        ├── Available c4.2xlarge capacity
        └── Available c4.2xlarge capacity
```

If AWS runs out of that particular capacity:

```text
You:
"I want to launch c4.2xlarge"

AWS:
"No available capacity of that type in this AZ."
```

A Capacity Reservation can help by **reserving that capacity ahead of time**.

---

# 3. How Capacity Reservation Works

You request a reservation for:

```text
Instance Type
      +
Region
      +
Availability Zone
```

For example:

```text
Instance Type → c4.2xlarge
Region        → ap-south-1
AZ            → ap-south-1a
```

AWS reserves capacity matching those requirements.

Conceptually:

```text
AWS AZ
┌─────────────────────────┐
│                         │
│ Available capacity      │
│                         │
│ ┌─────────────────────┐ │
│ │ Capacity Reserved   │ │
│ │ c4.2xlarge          │ │
│ └─────────────────────┘ │
│                         │
└─────────────────────────┘
```

---

# 4. Capacity Reservation Is About Capacity, Not Discount

This is **very important**.

A Capacity Reservation primarily guarantees **capacity availability**.

It does **not automatically give you a discount**.

The screenshot says:

> The reserved capacity is charged at the selected instance type's **On-Demand rate**, whether an instance is running in it or not.

So:

```text
Capacity Reservation
        ↓
Reserve capacity
        ↓
Pay On-Demand rate
```

Even if you aren't currently running an instance using that reservation, the reserved capacity is still charged according to the source.

---

# 5. Regional Reserved Instance + Capacity Reservation

The screenshot also mentions:

> You can use your Regional Reserved Instances with your Capacity Reservations to benefit from billing discounts.

This is an important distinction.

### Capacity Reservation

Provides:

> **Capacity**

### Regional Reserved Instance

Provides:

> **Pricing discount**

Together:

```text
Regional RI
    ↓
Billing discount

Capacity Reservation
    ↓
Capacity assurance

        ↓

Discount + Reserved Capacity
```

# 6. Scenario

Imagine you're running an important production application.

You need:

```text
20 × specific EC2 instance type
```

in:

```text
Specific Availability Zone
```

You are concerned that when you need additional instances, AWS might not have enough available capacity.

You can create a **Capacity Reservation** ahead of time.

```text
Before workload starts:

Capacity Reservation
        ↓
Reserve EC2 capacity
        ↓
Production workload
        ↓
Launch matching EC2 instances
```

This helps ensure the required capacity is available in that AZ.

---

# 7. Capacity Reservation vs Reserved Instance

This is a very important distinction because the names are similar.

|                    | Capacity Reservation                                         | Reserved Instance                               |
| ------------------ | ------------------------------------------------------------ | ----------------------------------------------- |
| Main purpose       | **Reserve capacity**                                         | **Get discounted pricing**                      |
| Scope              | Specific Region + AZ                                         | Regional or Zonal depending on RI               |
| Pricing            | On-Demand rate                                               | Discounted pricing                              |
| Capacity guarantee | ✅ Yes                                                        | Regional RI: ❌ / Zonal RI: can reserve capacity |
| Commitment         | Capacity reservation can be configured with an end condition | 1 or 3-year RI term                             |
| Main idea          | "Make sure capacity exists"                                  | "Reduce compute cost through commitment"        |

### Memory trick

> **Capacity Reservation → Capacity**

> **Reserved Instance → Discount**

And from your previous topic:

> **Zonal RI → Discount + Capacity reservation**

---

# 8. Important Configuration

The screenshot shows that when creating a Capacity Reservation, you specify characteristics such as:

* Instance type
* Platform
* Availability Zone
* Tenancy
* Quantity

For example:

```text
Instance Type → c4.2xlarge
Platform      → Linux/Unix
AZ            → ca-central-1a
Tenancy       → Default
Quantity      → 1
```

The EC2 instances need to match the applicable reservation criteria to use the reserved capacity.

# 🎯 Exam Scenarios

### Q1. You need to ensure EC2 capacity is available in a specific AZ.

→ **Capacity Reservation**

### Q2. You want discounted EC2 pricing for predictable long-term usage.

→ **Reserved Instance**

### Q3. You want capacity reserved but don't necessarily need a pricing discount.

→ **Capacity Reservation**

### Q4. Which pricing rate is charged for a Capacity Reservation according to your source?

→ **On-Demand rate**

### Q5. Can Regional RIs be used with Capacity Reservations?

→ **Yes**, according to the source, allowing the RI discount to apply while the Capacity Reservation provides capacity.
