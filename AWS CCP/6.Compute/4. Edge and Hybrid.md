# 1. What Is Edge Computing?

## Definition

**Edge computing** means moving computing workloads **closer to where the data is generated or where the users/devices are located**, rather than processing everything in a distant central cloud location.

The screenshot describes it as pushing workloads outside your main network to run close to the destination location.

Examples include computing on:

* Phones
* IoT devices
* External/edge servers
* Locations closer to end users

### Simple idea

Traditional cloud:

```text
User
  ↓
Internet
  ↓
AWS Region
  ↓
Application
```

Edge computing:

```text
User
  ↓
Nearby Edge Location
  ↓
Application
```

The main goal is usually:

> **Reduce latency by processing closer to the user/device.**

---

# 2. Why Use Edge Computing?

The farther data has to travel, the more network latency can be introduced.

For applications requiring very fast responses:

```text
User
 ↓
Long distance
 ↓
Cloud
 ↓
Response
```

may not be ideal.

With edge computing:

```text
User
 ↓
Nearby computing location
 ↓
Response
```

the distance can be reduced.

### Useful for:

* IoT
* Real-time applications
* Gaming
* Video processing
* Industrial applications
* Applications requiring very low latency

### Scenario

Imagine an IoT device generating data continuously.

Instead of:

```text
IoT Device
    ↓
Internet
    ↓
Distant AWS Region
    ↓
Process data
```

you could process some data closer to the device:

```text
IoT Device
    ↓
Edge location
    ↓
Process data
```

### Memory:

> **Edge = Compute closer to the user/device.**

---

# 3. What Is Hybrid Computing?

## Definition

The screenshot defines hybrid computing as being able to run workloads on both:

```text
On-premises data center
        +
AWS VPC
```

So you don't have to move everything to AWS at once.

```text
             Hybrid Environment
                    │
          ┌─────────┴─────────┐
          ↓                   ↓
   On-Premises             AWS VPC
   Data Center
```

These environments can work together depending on the architecture and connectivity.

---

# 4. Why Use Hybrid Computing?

Organizations may already have:

* Existing servers
* Applications
* Databases
* VMware environments
* Specialized hardware
* Legacy applications

Moving everything to the cloud immediately may not be practical.

Hybrid computing allows:

```text
Existing infrastructure
        +
AWS Cloud
```

### Scenario

A company keeps an existing database in its data center but runs a new application component in AWS.

```text
On-Premises
   │
   │ Connectivity
   │
   ↓
AWS VPC
   ↓
Cloud application
```

This is a **hybrid architecture**.

### Memory:

> **Hybrid = On-premises + Cloud working together.**

---

# 5. AWS Outposts

## Definition

**AWS Outposts** is an AWS service that extends AWS infrastructure and services into your own data center or on-premises location.

The screenshot describes it as:

> **A physical rack of servers that you can put in your data center.**

Conceptually:

```text
             Your Data Center
┌─────────────────────────────────┐
│                                 │
│        AWS Outposts Rack        │
│                                 │
│     AWS infrastructure          │
│          ↓                      │
│       EC2 / AWS services        │
│                                 │
└─────────────────────────────────┘
```

It allows you to use AWS APIs and supported AWS services in your own physical location.

---

# 6. Why Use AWS Outposts?

You might need:

* Very low latency to on-premises systems
* Local data processing
* Consistent AWS infrastructure
* AWS services close to your existing systems
* Hybrid architecture

### Scenario

Suppose a manufacturing company has machines inside its factory.

It wants AWS compute capabilities **inside the factory** because sending every piece of data to a distant AWS Region would introduce unwanted latency.

Outposts can provide AWS infrastructure in the company's own facility.

```text
Factory
│
├── Existing systems
├── IoT devices
└── AWS Outposts
       ↓
    AWS services
```

### Memory:

> **Outposts = AWS infrastructure in your data center.**

---

# 7. AWS Wavelength

## Definition

**AWS Wavelength** allows you to build and deploy applications in **telecommunications/5G network locations**.

The screenshot highlights telecom providers such as:

* Verizon
* Vodafone Business

The main purpose is to provide **very low latency for applications accessed through 5G networks**.

---

# 8. Why Use AWS Wavelength?

Imagine a mobile application requiring extremely fast communication.

Traditional:

```text
5G User
   ↓
Mobile Network
   ↓
Internet
   ↓
AWS Region
   ↓
Application
```

Wavelength brings AWS compute closer to the telecommunications network:

```text
5G User
   ↓
5G Network
   ↓
Wavelength Zone
   ↓
Application
```

This can reduce the network distance between the mobile user and the application.

### Possible use cases:

* 5G applications
* Connected vehicles
* AR/VR
* Real-time gaming
* Industrial IoT
* Other ultra-low-latency applications

### Memory:

> **Wavelength = AWS compute at telecom/5G locations.**

---

# 9. AWS Outposts vs AWS Wavelength

This distinction is important.

| Service            | Main idea                                  |
| ------------------ | ------------------------------------------ |
| **AWS Outposts**   | AWS infrastructure in your own data center |
| **AWS Wavelength** | AWS infrastructure at telecom/5G locations |

### Easy memory:

```text
Outposts
   ↓
Your Data Center

Wavelength
   ↓
5G / Telecom Network
```

# 10. VMware Cloud on AWS

## Definition

**VMware Cloud on AWS** allows organizations to run/manage VMware-based workloads using AWS infrastructure.

The screenshot specifically highlights:

> **Manage on-premises virtual machines using VMware as EC2 instances**

The important idea is that organizations already using VMware can extend or migrate VMware workloads to AWS.

Conceptually:

```text
On-Premises
VMware
   ↓
VMware-based workloads
   ↓
AWS
   ↓
AWS infrastructure
```

---

# 11. Why Use VMware Cloud on AWS?

Many enterprises already have large VMware environments.

They may have:

```text
VMware
 ├── VM 1
 ├── VM 2
 ├── VM 3
 └── VM 4
```

Instead of completely redesigning all those workloads for AWS, VMware Cloud on AWS provides a way to continue using VMware technologies on AWS infrastructure.

### Scenario

A company has hundreds of VMware virtual machines on-premises.

It wants to move some workloads to AWS but wants to continue using VMware management and virtualization technologies.

VMware Cloud on AWS can support that type of migration/hybrid strategy.

### Memory:

> **VMware Cloud on AWS = VMware workloads on AWS infrastructure.**

---

# 12. AWS Local Zones

## Definition

**AWS Local Zones** are AWS infrastructure locations positioned closer to end users in specific geographic areas.

The screenshot describes them as:

> **Edge data centers located outside of an AWS Region so you can use AWS closer to the end destination.**

Their purpose is to provide selected AWS capabilities closer to users/workloads when the nearest main AWS Region may be too far away.

### Architecture

```text
Main AWS Region
      │
      │
      ↓
AWS Local Zone
      │
      ↓
Users / Applications
```

This can help with workloads that require **low latency**.

---

# 13. Why Use AWS Local Zones?

The screenshot specifically highlights:

> **Faster computing, storage and databases in populated areas that are outside of an AWS Region.**

For example:

```text
Users
  ↓
Large metropolitan area
  ↓
Local Zone
  ↓
AWS workload
```

Instead of sending traffic all the way to a distant Region.

### Scenario

Suppose your users are concentrated in a city that is relatively far from the nearest AWS Region.

A Local Zone can provide supported AWS resources closer to those users.

### Memory:

> **Local Zones = AWS infrastructure closer to users in specific locations.**

| **AWS Wavelength**  | Telecom/5G locations                    | Ultra-low-latency 5G applications           |

### Memory trick:

**Outposts → Your place**

**Wavelength → Telecom/5G place**

**Local Zone → Near users**

---

# 15. Edge vs Hybrid

Don't confuse these two concepts.

### Edge Computing

Focuses on:

> **Where computation happens relative to the user/device.**

```text
User
 ↓
Nearby compute
```

Main goal:

**Lower latency / local processing**

---

### Hybrid Computing

Focuses on:

> **Using both on-premises infrastructure and cloud infrastructure.**

```text
On-Premises
     ↕
AWS
```

Main goal:

**Combine existing infrastructure with cloud resources.**
