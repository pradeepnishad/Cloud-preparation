The main topics are:

1. **Nitro System**
2. **Bare Metal Instances**
3. **Bottlerocket**
4. **High Performance Computing (HPC)**
5. **AWS ParallelCluster**

---

# 1. The AWS Nitro System

## Definition

The **AWS Nitro System** is a combination of:

> **Dedicated hardware + lightweight hypervisor**

It is designed to provide **high performance, security, and faster innovation** for EC2.

The screenshot states that **all new EC2 instance types use the Nitro System**.

Think of it as the technology underneath many modern EC2 instances:

```text
                 EC2
                  │
           AWS Nitro System
                  │
       ┌──────────┼──────────┐
       ↓          ↓          ↓
  Nitro Cards  Security   Nitro
                Chips    Hypervisor
```

---

## Components of the Nitro System

### 1. Nitro Cards

The screenshot describes Nitro Cards as specialized hardware for:

* VPC/networking
* EBS
* Instance storage
* Controller functions

Instead of making the main CPU perform all these infrastructure tasks, dedicated hardware handles important functions.

---

### 2. Nitro Security Chips

These are integrated into the motherboard.

Their purpose is to help protect the underlying hardware resources.

Think:

```text
Nitro Security Chip
        ↓
Hardware protection
```

---

### 3. Nitro Hypervisor

The **Nitro Hypervisor** is a lightweight hypervisor responsible for things such as:

* Memory allocation
* CPU allocation

Because the hypervisor is lightweight, more of the underlying hardware capability can be available to workloads.

The screenshot connects this with:

> **Bare-metal-like performance**

---

## Why Use the Nitro System?

The main benefits presented in the screenshot are:

* Higher performance
* Enhanced security
* Efficient resource management
* Faster innovation

### Simple memory:

> **Nitro = AWS hardware + lightweight virtualization + security**

---

# 2. Bare Metal Instances

## Definition

A **bare metal instance** is an EC2 instance where the workload runs directly on the physical server hardware rather than through a traditional hypervisor layer in the same way as virtualized instances.

The screenshot describes it as:

> Launching an EC2 instance with no hypervisor so workloads can run directly on hardware for maximum performance and control.

Conceptually:

### Normal virtualized EC2

```text
Application
    ↓
Guest OS
    ↓
Virtual Machine
    ↓
Hypervisor
    ↓
Physical Hardware
```

### Bare Metal

```text
Application
    ↓
Operating System
    ↓
Physical Hardware
```

---

## Why Use Bare Metal?

Bare metal is useful when workloads require:

* Very high performance
* Maximum control over hardware
* Low-level hardware access
* Workloads that benefit from avoiding virtualization overhead

Think:

> **Bare metal = Direct access to physical hardware.**

---

## Scenario

Imagine you're running an extremely compute-intensive application where even small amounts of virtualization overhead matter.

Instead of:

```text
Application → VM → Hypervisor → Hardware
```

you want:

```text
Application → Hardware
```

A bare metal instance can be appropriate for such workloads.

### Source-specific note

The screenshot specifically states **M5 and R5 EC2 instances run as bare metal**. For your notes based on this course slide, retain that statement as presented.

# 3. Bottlerocket

## Definition

**Bottlerocket** is a **Linux-based, open-source operating system purpose-built by AWS for running containers**.

It can run containers on:

* Virtual machines
* Bare metal hosts

Think:

```text
Bottlerocket
     ↓
Container-focused OS
     ↓
Containers
```

It isn't a general-purpose desktop operating system like Ubuntu or Windows.

It is designed specifically around container workloads.

---

## Why Use Bottlerocket?

If your main workload is containers, you may want an operating system specifically optimized for running them.

For example:

```text
Bottlerocket
      ↓
Container Runtime
      ↓
Containers
      ↓
Applications
```

### Scenario

A company runs hundreds of containerized microservices and wants an OS designed specifically for container workloads.

Bottlerocket can be considered for that type of environment.

### Memory:

> **Bottlerocket = AWS Linux OS designed for containers.**

---

# 4. What Is High Performance Computing (HPC)?

## Definition

**High Performance Computing (HPC)** involves using a large collection/cluster of computers working together to provide very high computational capacity.

The screenshot describes it as:

> A cluster of hundreds or thousands of servers with fast connections between them to boost computing capacity.

Instead of:

```text
One powerful computer
      ↓
Solve problem
```

HPC can use:

```text
          HPC Cluster
               │
    ┌──────────┼──────────┐
    ↓          ↓          ↓
 Server 1   Server 2   Server 3
    ↓          ↓          ↓
    └──────────┼──────────┘
               ↓
          Combined
        computational
           capacity
```

---

# 5. Why Do We Need HPC?

Some problems are simply too computationally intensive for a normal computer.

For example:

* Scientific simulations
* Engineering simulations
* Large mathematical calculations
* Research workloads
* Large-scale computational workloads

The screenshot's key idea is:

> **Use HPC when a normal computer would take too long or cannot handle the workload.**

---

# 6. HPC Scenario

Imagine scientists need to perform a complex simulation.

A normal computer:

```text
Problem
   ↓
1 Computer
   ↓
Several weeks
```

An HPC cluster:

```text
Problem
   ↓
100s/1000s of computers
   ↓
Parallel computation
   ↓
Much greater computational capacity
```

The exact performance improvement depends on the workload and architecture; HPC doesn't automatically make every workload faster.

---

# 7. AWS ParallelCluster

## Definition

**AWS ParallelCluster is an AWS-supported open-source cluster management tool that makes it easier to deploy and manage HPC clusters on AWS.**

Think:

```text
AWS ParallelCluster
        ↓
Deploy HPC Cluster
        ↓
Manage HPC Cluster
        ↓
Run HPC Workloads
```

Instead of manually configuring a large cluster of compute resources, ParallelCluster helps automate the deployment and management of the cluster.

---

# 8. Why Use AWS ParallelCluster?

Imagine you need:

```text
HPC Cluster
│
├── Compute Node 1
├── Compute Node 2
├── Compute Node 3
├── Compute Node 4
└── ...
```

Manually configuring hundreds of compute nodes could be complicated.

ParallelCluster helps simplify:

```text
Cluster configuration
       ↓
ParallelCluster
       ↓
AWS infrastructure
       ↓
HPC cluster
```

### Scenario

A research organization needs an HPC environment for scientific simulations.

Instead of manually building every component, they can use **AWS ParallelCluster** to deploy and manage the HPC cluster.

---

# 9. Nitro vs Bare Metal vs HPC

Don't mix these concepts.

| Concept             | Main purpose                                             |
| ------------------- | -------------------------------------------------------- |
| **Nitro System**    | AWS hardware + lightweight hypervisor technology for EC2 |
| **Bare Metal**      | Run workloads directly on physical hardware              |
| **Bottlerocket**    | Container-focused Linux OS                               |
| **HPC**             | Large-scale high-performance computation                 |
| **ParallelCluster** | Deploy/manage HPC clusters                               |

---

You can visualize the screenshot like this:

They address different parts of the infrastructure stack.
