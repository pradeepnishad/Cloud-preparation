# 🌐 Cloud-Native Networking Services

This diagram shows the **basic networking building blocks in AWS** and how they fit together.

The main concepts are:

1. Region
2. Availability Zone (AZ)
3. VPC
4. Subnet
5. Route Table
6. Internet Gateway (IGW)
7. Security Group
8. Network ACL (NACL)
9. NAT Gateway

---

# 1. AWS Region

### Definition

A **Region** is a geographical location where AWS has infrastructure.

Examples:

```text
Mumbai Region
Singapore Region
London Region
Tokyo Region
```

### Why use Regions?

You choose a Region where you want your AWS resources to run.

Reasons can include:

* Location of your users
* Latency
* Compliance requirements
* Availability
* Service availability

### Scenario

If most of your application's users are in India, you might choose an AWS Region close to them to reduce network latency.

### 🧠 Remember

> **Region = Geographical location**

---

# 2. Availability Zone (AZ)

### Definition

An **Availability Zone is an isolated location within an AWS Region**, consisting of one or more data centers with redundant power, networking, and connectivity.

For your current foundational notes, think of it as:

> **AZ = isolated infrastructure location inside a Region**

Example:

```text
AWS Region
│
├── AZ 1
├── AZ 2
└── AZ 3
```

### Why use AZs?

Multiple AZs allow you to design applications with **redundancy and high availability**.

### Scenario

Instead of putting your entire application in one AZ:

```text
AZ 1
└── EC2
```

you could use:

```text
AZ 1              AZ 2
└── EC2            └── EC2
```

If one AZ experiences a failure, the other can potentially continue serving the application.

### 🧠 Remember

> **Region = geographical area**
> **AZ = isolated infrastructure location inside a Region**

---

# 3. VPC — Virtual Private Cloud

### Definition

A **VPC is a logically isolated virtual network in AWS where you can launch AWS resources.**

Think of it as your own virtual network inside AWS.

```text
AWS Region
└── VPC
    ├── Subnet
    ├── Subnet
    ├── Route Tables
    └── Security controls
```

### Why use a VPC?

A VPC gives you control over networking, including:

* IP address ranges
* Subnets
* Routing
* Network connectivity
* Security controls

### Scenario

You create a VPC:

```text
10.0.0.0/16
```

and put your application resources inside it.

### 🧠 Remember

> **VPC = Your virtual network in AWS**

---

# 4. Subnet

### Definition

A **subnet is a logical partition of an IP network into smaller network segments.**

A subnet exists **inside a VPC**.

Example:

```text
VPC
10.0.0.0/16
│
├── Public Subnet
│   10.0.1.0/24
│
└── Private Subnet
    10.0.2.0/24
```

### Why use subnets?

Subnets help you:

* Organize resources
* Separate workloads
* Control routing
* Design public/private network architectures

### Scenario

You might put:

```text
Public Subnet
└── Web server

Private Subnet
└── Database
```

### 🧠 Remember

> **VPC = large virtual network**
> **Subnet = smaller network inside the VPC**

---

# 5. Route Table

### Definition

A **route table contains rules that determine where network traffic from a subnet is directed.**

Think of it as a **traffic-routing map**.

Example:

```text
Destination        Target

10.0.0.0/16   →    local
0.0.0.0/0     →    Internet Gateway
```

The `0.0.0.0/0` route means traffic destined for addresses outside the VPC can be sent toward the Internet Gateway.

### Why use route tables?

They determine where network packets should go.

For example:

```text
EC2
 ↓
Route Table
 ↓
Internet Gateway
 ↓
Internet
```

### Important

A subnet is associated with a route table, and the routes determine how traffic from that subnet is handled.

### 🧠 Remember

> **Route Table = Where should the traffic go?**

---

# 6. Internet Gateway — IGW

### Definition

An **Internet Gateway (IGW) enables communication between resources in a VPC and the Internet**, when the appropriate routing and resource configuration are in place.

Think:

```text
VPC
 ↓
Internet Gateway
 ↓
Internet
```

### Why use an IGW?

You need an Internet Gateway for a VPC to have a path to/from the public Internet.

### Scenario

A public web server needs to communicate with users on the Internet.

A simplified path is:

```text
User
 ↓
Internet
 ↓
IGW
 ↓
Route Table
 ↓
Public Subnet
 ↓
EC2
```

### Important distinction

**Having an IGW attached to a VPC does NOT automatically make every subnet or EC2 instance public.**

The subnet needs an appropriate route, and the resource needs appropriate public addressing/configuration.

### 🧠 Remember

> **IGW = Gateway between VPC and Internet**

---

# 7. Security Group

### Definition

A **Security Group acts as a virtual firewall for AWS resources such as EC2 instances.**

The screenshot describes it as:

> **Firewall at the instance level**

### What does it control?

It controls network traffic based on rules such as:

* Protocol
* Port
* Source/destination

Example:

```text
Inbound

TCP 443
Source: Internet
        ↓
    EC2 Security Group
        ↓
       EC2
```

This allows HTTPS traffic when the corresponding rule is configured.

### Important characteristic

Security Groups are **stateful**.

If permitted traffic is allowed in a connection, the corresponding response traffic is automatically allowed.

### 🧠 Remember

> **Security Group = Resource/instance-level firewall**

---

# 8. Network ACL — NACL

### Definition

A **Network ACL (NACL) acts as a firewall at the subnet level.**

The screenshot specifically emphasizes:

> **NACL = firewall at the subnet level**

### Why use NACLs?

They allow you to control traffic entering or leaving a subnet.

Unlike Security Groups, NACLs are **stateless**.

That means inbound and outbound traffic are evaluated separately.

### Example

```text
Internet
   ↓
NACL
   ↓
Subnet
   ↓
EC2
```

### Security Group vs NACL

| Feature      | Security Group           | NACL                   |
| ------------ | ------------------------ | ---------------------- |
| Level        | Resource/instance        | Subnet                 |
| Stateful     | Yes                      | No                     |
| Rules        | Allow                    | Allow/deny             |
| Main purpose | Resource traffic control | Subnet traffic control |

### 🧠 Remember

> **SG → Security around the resource**
> **NACL → Network security around the subnet**

---

# 9. NAT

The diagram shows **NAT** inside the VPC.

### Definition

**NAT (Network Address Translation) allows resources in a private subnet to initiate connections to external networks, such as the Internet, without requiring those resources to have public IP addresses.**

In AWS, this is commonly implemented using a **NAT Gateway**.

Simplified:

```text
Private EC2
    ↓
Route Table
    ↓
NAT Gateway
    ↓
Internet Gateway
    ↓
Internet
```

### Why use NAT?

Suppose a private EC2 instance needs to:

* Download software updates
* Access an external API
* Download packages

But you don't want the EC2 instance to have a public IP address.

A NAT Gateway can provide the outbound path.

### Important

NAT is generally for **outbound-initiated connectivity** from private resources.

It does not make a private EC2 instance directly reachable from the public Internet.

### 🧠 Remember

> **NAT = Private resources can go out without becoming publicly reachable**

# 🧠 The AWS Networking Hierarchy

Memorize this structure:

```text
AWS
 │
 └── Region
      │
      ├── Availability Zone
      │      │
      │      └── Subnet
      │
      └── VPC
             │
             ├── Subnets
             │
             ├── Route Tables
             │
             ├── Internet Gateway
             │
             ├── NAT Gateway
             │
             ├── Security Groups
             │
             └── NACLs
```

One correction to the simplified visual: **a VPC spans all Availability Zones in a Region, while a subnet belongs to a single AZ**. That's an important AWS networking concept to keep straight.

# 🎯 Cloud Practitioner Exam Associations

| If the question says...                             | Think...              |
| --------------------------------------------------- | --------------------- |
| Geographical location                               | **Region**            |
| Isolated location inside Region                     | **Availability Zone** |
| Logically isolated AWS network                      | **VPC**               |
| Smaller network inside VPC                          | **Subnet**            |
| Determines traffic destination                      | **Route Table**       |
| Connect VPC to Internet                             | **Internet Gateway**  |
| Firewall at resource/instance level                 | **Security Group**    |
| Firewall at subnet level                            | **NACL**              |
| Private resources access Internet without public IP | **NAT Gateway**       |

### Final memory trick

> **Region = Where**
> **AZ = Isolated location**
> **VPC = Network**
> **Subnet = Network segment**
> **Route Table = Where traffic goes**
> **IGW = Internet connection**
> **SG = Resource firewall**
> **NACL = Subnet firewall**
> **NAT = Private-to-external outbound access**
