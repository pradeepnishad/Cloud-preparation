# ☁️ AWS SDK — Complete Explanation

Since you just learned **AWS API → AWS CLI → PowerShell**, the next piece is **AWS SDK**.

The simplest definition is:

> **AWS SDK (Software Development Kit) is a collection of libraries/tools that allows developers to interact with AWS services programmatically from a programming language.**

For example, instead of manually using the AWS Console:

```text
Console
   ↓
Click EC2
   ↓
Create instance
```

or using CLI:

```bash
aws ec2 describe-instances
```

you can write a program:

```python
import boto3

ec2 = boto3.client("ec2")

response = ec2.describe_instances()

print(response)
```

Your Python program communicates with AWS through the AWS APIs.

---

# 1. What is an SDK?

**SDK = Software Development Kit.**

An SDK provides tools and libraries that make it easier to build software that interacts with a platform/service.

Think of it as:

> **A ready-made programming interface that saves you from manually constructing API requests.**

Without an SDK, your application might have to manually deal with:

```text
HTTP requests
Authentication
Request signing
Headers
Endpoints
Serialization
Responses
Error handling
```

An SDK handles much of this for you.

# 4. What is Boto3?

**Boto3** is the AWS SDK for Python.

For example:

```python
import boto3

s3 = boto3.client("s3")

response = s3.list_buckets()

print(response)
```

Let's understand this.

---

## `import boto3`

```python
import boto3
```

Loads the AWS SDK for Python.

---

## Create an S3 client

```python
s3 = boto3.client("s3")
```

You're creating a client that can communicate with Amazon S3.

Conceptually:

```text
Python
  ↓
Boto3
  ↓
S3 Client
  ↓
S3 API
```

---

## Call an operation

```python
s3.list_buckets()
```

This tells the SDK:

> Ask Amazon S3 for the buckets associated with this account/context.

# 5. SDK vs CLI

This is one of the most important distinctions.

### AWS CLI

You interact using commands:

```bash
aws ec2 describe-instances
```

### AWS SDK

You interact using programming code:

```python
ec2.describe_instances()
```

Both communicate with AWS APIs.

```text
                  AWS API
                     ↑
             ┌───────┴───────┐
             │               │
          AWS CLI          AWS SDK
             │               │
        CLI commands      Program code
```

# 6. SDK vs AWS API

Don't confuse these.

### AWS API

The underlying interface provided by AWS services.

### AWS SDK

A programming library that makes using those APIs easier.

Think:

```text
AWS API
= Communication interface

AWS SDK
= Developer-friendly tool for using that interface
```


# 14. Authentication

Your application needs permission to interact with AWS.

The SDK needs credentials/configuration that AWS can use to authenticate the request.

For example, locally you might configure AWS credentials using the AWS CLI configuration mechanism, and Boto3 can use that configuration.

For applications running inside AWS, you generally want to use **IAM roles/temporary credentials** rather than embedding long-term access keys in your source code.

For example:

```text
EC2
 ↓
IAM Role
 ↓
Temporary credentials
 ↓
Boto3
 ↓
S3
```

This is an important security practice.

---

# 15. Why Should You NOT Put Access Keys in Code?

Avoid doing this:

```python
aws_access_key = "MY_SECRET_KEY"
aws_secret_key = "MY_SECRET_KEY"
```

Especially don't commit credentials to GitHub.

Instead, use appropriate AWS credential mechanisms such as:

```text
IAM roles
Environment/configuration
AWS CLI credential configuration
Temporary credentials
```

The exact mechanism depends on where your application runs.

# 21. SDK vs Terraform

This distinction will become important later for you.

### SDK

You write application code to interact with AWS.

```python
ec2.describe_instances()
```

You are essentially telling your program:

> "Perform this operation."

### Terraform

You describe the desired infrastructure state:

```hcl
resource "aws_instance" "web" {
  # configuration
}
```

You are saying:

> "I want this infrastructure to exist in this desired state."

So:

```text
SDK
→ Programmatic AWS interaction

Terraform
→ Infrastructure as Code
```

They can complement each other.

# 22. SDK vs AWS CLI — Practical Example

Suppose you want to list S3 buckets.

### CLI

```bash
aws s3 ls
```

You manually execute a command.

### Python SDK

```python
import boto3

s3 = boto3.client("s3")

response = s3.list_buckets()

for bucket in response["Buckets"]:
    print(bucket["Name"])
```

Now the result can become part of a larger application.

For example:

```text
Python Application
      ↓
Boto3
      ↓
S3
      ↓
Bucket information
      ↓
Database
      ↓
Web dashboard
```

That is something the SDK is particularly suited for.
