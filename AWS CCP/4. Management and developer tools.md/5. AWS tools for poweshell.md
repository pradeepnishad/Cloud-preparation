* A **scripting language**

* Windows
* Windows Server
* Azure
* AWS
* Active Directory
* Virtual machines
* Networking
* Applications
* Services
* Files
* Cloud resources

# 2. What is a Command-Line Shell?

A **shell** is an interface through which you interact with an operating system by entering commands.

Instead of clicking through a GUI:

```text
GUI
 ↓
Click Settings
 ↓
Click Network
 ↓
Click Adapter
 ↓
View configuration
```

you can use a command:

```powershell
Get-NetIPConfiguration
```

The shell interprets the command and asks the operating system to perform the requested operation.

### Common shells

```text
Windows
 ├── Command Prompt (cmd)
 └── PowerShell

Linux
 ├── Bash
 ├── Zsh
 └── Fish
```

For your **Cloud/AVD career**, PowerShell is particularly useful because of your Windows and Azure/AVD background.

---

# 3. PowerShell is also a Scripting Language

This is an important distinction.

You can execute individual commands:

```powershell
Get-Service
```

But you can also put many commands together into a script.

For example:

```powershell
Get-Service |
Where-Object {$_.Status -eq "Running"}
```

Or create a `.ps1` script:

```text
check-server.ps1
```

The script could:

```text
Check CPU
   ↓
Check memory
   ↓
Check disk
   ↓
Check services
   ↓
Generate report
```

Instead of manually doing all those tasks.

# 5. PowerShell and Objects — VERY IMPORTANT

This is one of the biggest differences between PowerShell and traditional shells.

The screenshot says:

> Unlike most shells, which accept and return text, PowerShell accepts and returns **.NET objects**.

Let's understand this.

---

## Traditional command-line approach

A traditional shell commonly works heavily with text.

Conceptually:

```text
Command
  ↓
Text output
  ↓
You parse the text
```

For example:

```text
ServiceName    Status
------------   ------
Spooler        Running
```

If you want to programmatically work with that output, you may need to parse the text.

---

# PowerShell

PowerShell works with **objects**.

For example:

```powershell
Get-Service
```

doesn't simply return a block of text.

It returns objects representing Windows services.

Conceptually:

```text
Service Object
├── Name
├── Status
├── DisplayName
├── StartType
└── Other properties
```

You can therefore work directly with those properties.

For example:

```powershell
Get-Service | Where-Object {$_.Status -eq "Running"}
```

Here:

```text
Get-Service
     ↓
Service objects
     ↓
Where-Object
     ↓
Filter based on Status
```

---

# 6. What is a .NET Object?

You don't need deep .NET knowledge yet.

Think of an object as:

> **A structured piece of data containing properties and sometimes methods.**

For example, imagine a server object:

```text
Server
├── Name = AVDHOST01
├── IP = 10.0.1.10
├── CPU = 35%
├── Memory = 62%
└── Status = Running
```

Instead of treating all of this as plain text, PowerShell can work with the individual properties.

For example:

```powershell
$server.Name
```

could give:

```text
AVDHOST01
```

# 7. PowerShell Commands — Cmdlets

The screenshot introduces an important term:

> **Cmdlet**

A **cmdlet** is a specialized PowerShell command designed to perform a particular operation.

Cmdlets generally follow:

```text
Verb-Noun
```

Examples:

```powershell
Get-Service
Get-Process
Get-ComputerInfo
Get-ChildItem
New-Item
Remove-Item
Start-Service
Stop-Service
Set-Location
```

The screenshot gives:

```powershell
New-S3Bucket
```

This is an AWS PowerShell cmdlet for creating an S3 bucket.

---

# 8. Verb-Noun Naming

PowerShell's naming convention makes commands easier to understand.

### Get

Retrieve something:

```powershell
Get-Service
Get-Process
Get-VM
```

### New

Create something:

```powershell
New-Item
New-S3Bucket
```

### Set

Modify something:

```powershell
Set-Location
```

### Remove

Delete something:

```powershell
Remove-Item
```

### Start

Start something:

```powershell
Start-Service
```

### Stop

Stop something:

```powershell
Stop-Service
```

So if you see:

```text
Verb-Noun
```

you can often understand what the command is intended to do.

---

# 9. PowerShell Pipeline

One of the most powerful PowerShell concepts is the **pipeline**.

It uses:

```text
|
```

called the **pipe**.

The pipeline passes the output of one command to another command.

Example:

```powershell
Get-Service | Where-Object {$_.Status -eq "Running"}
```

Think of it as:

```text
Get-Service
     ↓
Service Objects
     ↓
    |
     ↓
Where-Object
     ↓
Filter
     ↓
Running Services
```

This becomes extremely powerful for automation.

# 10. AWS Tools for PowerShell

The screenshot also introduces:

> **AWS Tools for PowerShell**

These tools allow you to interact with **AWS APIs using PowerShell cmdlets**.

The architecture is:

```text

     ↓

     ↓

     ↓

```

For example:

```powershell

```

Conceptually:

```text
PowerShell command
       ↓
AWS cmdlet
       ↓
AWS API request
       ↓
Amazon S3
       ↓
Bucket created
```

Different interfaces can communicate with those APIs:

```text
                    AWS API
                       ↑
          ┌────────────┼────────────┐
          │            │            │

          │                         │
          │                     PowerShell
          │
      GUI/Browser
```

AWS Tools for PowerShell essentially gives you **PowerShell-based commands for interacting with AWS services**.

# 12. Example — Creating an S3 Bucket

The screenshot shows:

```powershell
New-S3Bucket -BucketName website-example -Region us-west-2
```

Let's break it down.

### `New-S3Bucket`

The cmdlet.

```text
New → create
S3Bucket → S3 bucket
```

### `-BucketName`

Parameter specifying the bucket's name.

### `website-example`

The value supplied to that parameter.

### `-Region`

Specifies the AWS Region.

### `us-west-2`

The Region value.

So the command means:

> Create an S3 bucket named `website-example` in the `us-west-2` AWS Region.

---

# 13. PowerShell vs AWS CLI

You'll encounter both.

### AWS CLI

```bash
aws s3 mb s3://website-example --region us-west-2
```

### AWS PowerShell

```powershell
New-S3Bucket -BucketName website-example -Region us-west-2
```

Both ultimately interact with AWS services through AWS APIs.

The difference is the interface and command syntax.
