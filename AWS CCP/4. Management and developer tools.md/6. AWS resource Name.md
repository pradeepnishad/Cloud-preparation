# Amazon Resource Names (ARNs)

These two slides are explaining **ARNs**, one of the important AWS fundamentals for identifying resources and controlling access with IAM.

---

# 1. What is an ARN?

**ARN = Amazon Resource Name**

An ARN is a **unique identifier for an AWS resource**.

In simple words:

> **An ARN tells AWS exactly which resource you are talking about.**

For example, an AWS account might have:

```text
S3 Bucket: my-bucket
```

There could be many buckets called similar things across AWS accounts, so AWS uses an ARN to uniquely identify the resource.

Example:

```text
arn:aws:s3:::my-bucket
```

---

# 2. Why do we need ARNs?

Imagine you have:

```text
AWS Account
│
├── S3 bucket: production-data
├── S3 bucket: development-data
├── EC2 instance: i-1234567890abcdef0
└── IAM user: Bob
```

When AWS services or IAM policies need to refer to a **specific resource**, they need an unambiguous identifier.

That's where ARN comes in.

For example, an IAM policy could say:

> Allow this user to access this particular S3 bucket.

The policy can identify the bucket using its ARN.

---

# 3. ARN Basic Structure

The common ARN structure shown in your slide is:

```text
arn:partition:service:region:account-id:resource-id
```

There are some variations:

```text
arn:partition:service:region:account-id:resource-id

arn:partition:service:region:account-id:resource-type/resource-id

arn:partition:service:region:account-id:resource-type:resource-id
```

The exact structure depends on the AWS service.

---

# 4. Break Down an ARN

Let's use this example:

```text
arn:aws:elasticloadbalancing:us-east-1:123456789012:loadbalancer/app/my-webserver-alb/31e9d2ce26...
```

Break it down:

```text
arn
 │
 ├── partition
 │
 ├── service
 │
 ├── region
 │
 ├── account-id
 │
 └── resource
```

Let's understand each part.

---

# 5. `arn`

The first part is always:

```text
arn
```

It indicates:

> This is an Amazon Resource Name.

So:

```text
arn:...
```

means we're dealing with an ARN.

---

# 6. Partition

The second component identifies the AWS partition.

Examples from your slide:

```text
aws
aws-cn
aws-us-gov
```

### `aws`

Normal AWS Regions.

Examples:

```text
us-east-1
ap-south-1
eu-west-1
```

### `aws-cn`

AWS China Regions.

### `aws-us-gov`

AWS GovCloud (US).

So:

```text
arn:aws:...
```

means the resource belongs to the standard AWS partition.

---

# 7. Service

The next part identifies the AWS service.

Examples:

```text
ec2
s3
iam
```

For example:

```text
arn:aws:ec2:...
```

means the ARN refers to an EC2 resource.

```text
arn:aws:s3:...
```

means S3.

```text
arn:aws:iam:...
```

means IAM.

---

# 8. Region

The Region identifies where the resource exists, when that service/resource uses a Region in its ARN.

Examples:

```text
us-east-1
ca-central-1
ap-south-1
```

For example:

```text
arn:aws:ec2:us-east-1:...
```

means the EC2 resource is in:

```text
US East (N. Virginia)
```

---

## Important exception

**Not every ARN contains a Region.**

Your S3 example demonstrates this:

```text
arn:aws:s3:::my-bucket
```

Notice:

```text
service = s3

region = empty

account-id = empty
```

This is because S3 bucket ARNs have a different format.

So don't memorize:

> Every ARN must contain a Region and Account ID.

Instead remember:

> **ARN structure varies by AWS service.**

---

# 9. Account ID

The account ID identifies the AWS account that owns the resource, where applicable.

AWS Account IDs are normally:

```text
12 digits
```

Example:

```text
123456789012
```

So:

```text
arn:aws:iam::123456789012:...
```

means:

```text
Partition = aws
Service   = iam
Account   = 123456789012
```

---

# 10. Resource ID

The final portion identifies the actual resource.

Depending on the service, it could be:

* A resource name
* A resource ID
* A path
* A resource type + ID
* A combination

Your slide gives examples:

```text
user/Bob
```

and:

```text
instance/i-1234567890abcdef0
```

---

# 11. Example — IAM User ARN

Suppose the IAM user is:

```text
Bob
```

An ARN can look like:

```text
arn:aws:iam::123456789012:user/Bob
```

Break it down:

```text
arn
 ↓
aws
 ↓
iam
 ↓
(no region)
 ↓
123456789012
 ↓
user/Bob
```

Meaning:

> IAM user `Bob` in AWS account `123456789012`.

---

# 12. Example — EC2 ARN

Conceptually:

```text
arn:aws:ec2:us-east-1:123456789012:instance/i-1234567890abcdef0
```

Breakdown:

```text
arn
│
├── aws                  → Partition
├── ec2                  → Service
├── us-east-1            → Region
├── 123456789012         → Account ID
└── instance/
    └── i-1234567890...  → Resource
```

So you can identify:

> A specific EC2 instance in a specific account and Region.

---

# 13. S3 ARN — Special Example

Your slide shows:

```text
arn:aws:s3:::my-bucket
```

This is an important one to remember.

Breakdown:

```text
arn
 ↓
aws
 ↓
s3
 ↓
(empty region)
 ↓
(empty account ID)
 ↓
my-bucket
```

### Why does it look different?

Because **S3 bucket ARNs have a service-specific format**.

Don't try to force every ARN into:

```text
arn:partition:service:region:account-id:resource
```

Some services omit certain fields.

---

# 14. ARN Paths

Your second slide introduces **paths in ARNs**.

A resource ARN can contain a path.

For example:

```text
arn:aws:iam::123456789012:user/Development/product_1234/*
```

The path is:

```text
user/Development/product_1234/*
```

Think of it like a directory structure.

```text
user
└── Development
    └── product_1234
        ├── resource1
        ├── resource2
        └── resource3
```

---

# 15. Wildcard `*`

The second slide says that ARN paths can contain a wildcard:

```text
*
```

A wildcard means:

> Match multiple resources according to the pattern.

For example:

```text
arn:aws:iam::123456789012:user/Development/product_1234/*
```

can be used as a pattern rather than identifying only one exact resource.

---

# 16. Why are Wildcards Useful?

Imagine you have many resources:

```text
Development
├── product_1234
├── product_1235
├── product_1236
└── product_1237
```

Instead of writing separate resource references for every matching resource, an IAM policy can use an appropriate wildcard pattern.

This is particularly useful in **IAM policies**.

---

# 17. S3 ARN Path Example

Your slide gives:

```text
arn:aws:s3:::my_corporate_bucket/Development/*
```

This represents a path/pattern under the bucket:

```text
my_corporate_bucket
└── Development
    ├── file1
    ├── file2
    ├── file3
    └── ...
```

The `*` represents matching objects under that path according to the policy/resource pattern.

### Important AWS detail

S3 doesn't actually have traditional folders in the same way a filesystem does. What looks like folders is generally represented through **object keys/prefixes**.

For example:

```text
Development/report.pdf
```

is an S3 object key with the prefix:

```text
Development/
```

---

# 18. ARN vs Resource Name

This distinction is important.

Suppose:

```text
S3 bucket name:
my-bucket
```

That's the **resource name**.

The ARN is:

```text
arn:aws:s3:::my-bucket
```

So:

```text
Resource name
      ↓
my-bucket

ARN
      ↓
arn:aws:s3:::my-bucket
```

The ARN provides the AWS-specific fully qualified identifier.

---

# 19. ARN vs Account ID

Don't confuse these.

### Account ID

```text
123456789012
```

Identifies the AWS account.

### ARN

```text
arn:aws:iam::123456789012:user/Bob
```

Identifies a particular AWS resource.

So:

> **Account ID identifies the account. ARN identifies a resource.**

---

# 20. Where Will You Use ARNs?

You'll encounter ARNs heavily in:

### IAM Policies

For example:

```json
{
  "Effect": "Allow",
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::my-bucket/*"
}
```

The `Resource` tells IAM **which resource the permission applies to**.

---

### AWS CLI

Some AWS commands accept resource identifiers/ARNs depending on the service.

---

### AWS SDKs

Applications may work with ARNs when referring to resources.

---

### AWS Services

Services can use ARNs to reference resources.

For example:

```text
SNS topic
Lambda function
S3 bucket
IAM role
EC2 resource
Load balancer
```

---

# 21. How to Find an ARN

As your slide mentions, the **AWS Management Console** commonly provides an option to copy a resource's ARN.

For example:

```text
AWS Console
     ↓
Open resource
     ↓
Find ARN
     ↓
Copy ARN
```

This is often easier than manually constructing one.

---

# 22. Why ARNs Matter for IAM

This is probably the **most important reason to learn ARNs for Cloud Practitioner**.

IAM needs to know:

> "What resource does this permission apply to?"

For example:

```text
User
 ↓
IAM Policy
 ↓
Action: s3:GetObject
 ↓
Resource:
arn:aws:s3:::company-data/*
```

Meaning conceptually:

> Allow the specified action on objects matching that S3 resource pattern.

So ARNs are closely connected to:

```text
IAM
 ↓
Policies
 ↓
Permissions
 ↓
Resources
```

# 🧠 ARN Memory Trick

Remember:

> **ARN = Where + What + Whose**

More precisely:

```text
ARN
│
├── Where?
│    └── Partition + Region
│
├── What?
│    └── Service + Resource
│
└── Whose?
     └── Account ID
```

And memorize the basic pattern:

```text
arn : partition : service : region : account-id : resource
```

For example:

```text
arn:aws:ec2:us-east-1:123456789012:instance/i-1234567890abcdef0
```

Think:

```text
ARN
 ↓
AWS
 ↓
EC2
 ↓
us-east-1
 ↓
123456789012
 ↓
specific instance
```

### The one sentence to remember:

> **An ARN is AWS's unique, fully qualified identifier used to unambiguously identify a resource, especially when referencing resources in IAM policies and other AWS operations.**
