# ☁️ AWS CLI — Detailed Guide

## 1. Definition

**AWS CLI = AWS Command Line Interface.**

It is a command-line tool that allows you to **interact with AWS services by entering commands in a terminal/shell** instead of using the AWS Management Console.

Simple definition:

> **AWS CLI lets you manage AWS resources from the command line.**

For example, instead of opening the S3 console and clicking **Create bucket**, you can use:

```bash
aws s3 mb s3://my-example-bucket
```

The basic flow is:

```text
You
 ↓
AWS CLI command
 ↓
AWS API
 ↓
AWS Service
 ↓
AWS Resource
```

This connects directly to what you learned about **AWS APIs**.

---

# 2. What is the AWS CLI actually doing?

The AWS CLI is essentially a **command-line interface to AWS APIs**.

For example:

```bash
aws s3 ls
```

You type a command.

The CLI interprets it and makes the appropriate API request to AWS.

Conceptually:

```text
aws s3 ls
    ↓
AWS CLI
    ↓
S3 API request
    ↓
Amazon S3
    ↓
Response
    ↓
Terminal
```

You don't normally have to manually construct the HTTP request yourself.

---

# 3. Why use AWS CLI?

The Management Console is great for manually managing resources.

But imagine you need to:

```text
Create 50 EC2 instances
Create 20 S3 buckets
Stop 100 instances
Check resources across accounts
Automate a deployment
```

Doing that manually through the GUI is inefficient.

CLI allows you to perform these operations quickly and repeatedly.

Think about the same operation in two different ways.

### Console

```text
Open AWS
   ↓
Open S3
   ↓
Create bucket
   ↓
Enter name
   ↓
Choose options
   ↓
```

### CLI


The CLI is especially useful when you need **repeatability and automation**.

# 5. AWS CLI Command Structure

A typical AWS CLI command looks like:

```bash
aws <service> <operation> [options]
```

For example:

```bash
aws s3 ls
```

Break it down:

```text
aws
 ↓
AWS CLI

s3
 ↓
AWS service

ls
 ↓
Operation
```

Another example:

```bash
aws ec2 describe-instances
```

```text
aws
 ↓
AWS CLI

ec2
 ↓
EC2 service

describe-instances
 ↓
Operation
```

---

# 6. `aws`

Every AWS CLI command normally starts with:

```bash
aws
```

It tells your shell:

> Execute an AWS CLI command.

---

# 7. Service

Next comes the AWS service you want to interact with.

Examples:

```bash
aws ec2
aws s3
aws iam
aws rds
aws lambda
aws cloudwatch
```

For example:

```bash
aws ec2 describe-instances
```

means:

> Work with the EC2 service.

---

# 8. Operation

After the service comes the operation.

Examples:

```bash
aws ec2 describe-instances
```

```text
describe-instances
```

means retrieve information about EC2 instances.

Another:

```bash
aws s3 ls
```

means list S3 buckets/objects depending on the command context.

---

# 9. Parameters / Options

You can provide additional options.

Example:

```bash
aws ec2 describe-instances --region ap-south-1
```

Here:

```text
--region
```

is an option.

```text
ap-south-1
```

is its value.

So:

```text
aws ec2 describe-instances --region ap-south-1
```

means:

> Describe EC2 instances in the `ap-south-1` Region.

# 11. AWS CLI and Regions

AWS resources can be Region-specific.

You can specify a Region:

```bash
aws ec2 describe-instances --region ap-south-1
```

Or configure a default Region.

For example:

```text
ap-south-1
```

is the AWS Mumbai Region.

Then you don't necessarily need to specify `--region` on every command.

---

# 12. AWS CLI Configuration

Before using the CLI to access your AWS account, you need credentials/configuration.

A common command is:

```bash
aws configure
```

It asks for information such as:

```text
AWS Access Key ID
AWS Secret Access Key
Default region name
Default output format
```

Example:

```text
AWS Access Key ID:     ********
AWS Secret Access Key: ********
Default region:       ap-south-1
Output format:        json
```

### ⚠️ Important security point

Never put AWS access keys directly into:

* GitHub repositories
* Scripts committed to Git
* Public websites
* Chat messages
* Docker images

For workloads running on AWS, prefer **IAM roles** where appropriate rather than embedding long-term credentials.

---

# 13. AWS CLI Profiles

Profiles allow you to maintain configurations for different AWS accounts/environments.

For example:

```text
default
development
production
```

You can then use:

```bash
aws ec2 describe-instances --profile development
```

or:

```bash
aws ec2 describe-instances --profile production
```

This is very useful when working with multiple AWS accounts.

---

# 14. Output Formats

AWS CLI can return information in different formats.

Common ones include:

```text
json
text
table
```

For example:

```bash
aws ec2 describe-instances --output json
```

or:

```bash
aws ec2 describe-instances --output table
```

### JSON

Very useful for automation and scripts.

```json
{
  "Reservations": []
}
```

### Table

Easier for humans to read.

```text
--------------------------------
|        DescribeInstances     |
+------------------------------+
| InstanceId                   |
+------------------------------+
| i-1234567890abcdef0          |
+------------------------------+
```

# 15. AWS CLI + Querying

One particularly useful feature is filtering/querying output.

AWS CLI supports the `--query` option using **JMESPath** expressions.

For example:

```bash
aws ec2 describe-instances \
  --query 'Reservations[].Instances[].InstanceId'
```

Instead of receiving a huge EC2 response, you can retrieve only the instance IDs.

Conceptually:

```text
Huge AWS response
       ↓
    --query
       ↓
Only information you need
```

This becomes extremely useful for automation.

# 17. AWS CLI + PowerShell

This connects to what you just learned.

You can run AWS CLI commands from PowerShell.

For example:

```powershell
aws ec2 describe-instances
```

Then combine the CLI with PowerShell automation.

You could build:

```text
PowerShell
     ↓
AWS CLI
     ↓
AWS API
     ↓
AWS resources
```

Alternatively, you can use **AWS Tools for PowerShell**:

```text
PowerShell
     ↓
AWS Tools for PowerShell
     ↓
AWS API
```

So there are two approaches.

---

# 18. AWS CLI vs AWS Tools for PowerShell

| AWS CLI                  | AWS Tools for PowerShell                    |
| ------------------------ | ------------------------------------------- |
| Command-line tool        | PowerShell-specific tools                   |
| `aws ec2 ...`            | PowerShell cmdlets                          |
| Works well across shells | Integrates naturally with PowerShell        |
| Common in Linux/DevOps   | Very useful for Windows administration      |
| JSON/text/table output   | PowerShell objects                          |
| Excellent scripting tool | Excellent Windows/Azure/AVD automation tool |

Example:

### AWS CLI

```bash
aws ec2 describe-instances
```

### PowerShell

```powershell
Get-EC2Instance
```

Both can interact with AWS.

---

# 19. AWS CLI vs SDK

This is another important distinction.

### AWS CLI

You interact using commands:

```bash
aws ec2 describe-instances
```

### AWS SDK

You interact with AWS programmatically from a programming language.

For example, Python using Boto3:

```python
import boto3

ec2 = boto3.client("ec2")

response = ec2.describe_instances()
```

So:

```text
Console → GUI
CLI     → Terminal commands
SDK     → Programming language
```

All ultimately interact with AWS APIs.

---

# 20. AWS CLI vs API

Don't confuse these.

### API

The underlying interface that AWS services expose for programmatic interaction.

### CLI

A tool that makes interacting with those APIs easier from the command line.

Think:

```text
                 AWS API
                    ↑
        ┌───────────┼───────────┐
        │           │           │
     Console       CLI         SDK
        │           │           │
       GUI       Commands    Code
```

So:

> **CLI is not the API itself.**

It is a client/interface that uses AWS APIs.

# 🧠 The Mental Model You Should Remember

You have now learned three different AWS interfaces:

```text
                    AWS APIs
                       ↑
          ┌────────────┼────────────┐
          │            │            │
      Management      CLI          SDK
       Console         │             │
          │            │          Python/
          │            │          Java/etc.
          ↓            ↓             ↓
         GUI        Commands        Code
```

And PowerShell adds another useful option:

```text
                 AWS APIs
                    ↑
          ┌─────────┴─────────┐
          │                   │
      AWS CLI        AWS Tools for PowerShell
          │                   │
       Commands            Cmdlets
```

### The simplest way to remember:

> **Console = Click**

> **CLI = Command**

> **SDK = Code**

> **PowerShell Tools = Cmdlets**

> **API = The underlying interface they communicate with**

For your **Cloud Engineer → DevOps path**, I would learn AWS CLI alongside **PowerShell**, rather than treating CLI as something you only need for the Cloud Practitioner exam.
