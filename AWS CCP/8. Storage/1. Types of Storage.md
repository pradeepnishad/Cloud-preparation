# 💾 Types of AWS Storage Services

The screenshot introduces the **three fundamental types of storage** you need to understand for AWS Cloud Practitioner:

```text
AWS STORAGE
│
├── EBS → Block Storage
├── EFS → File Storage
└── S3  → Object Storage
```

The most important question is:

> **How does the application need to access the data?**

---

# 1. Amazon EBS — Block Storage

## Definition

**Amazon Elastic Block Store (EBS)** provides **block storage volumes** that can be attached to EC2 instances.

Think of EBS as a **virtual hard drive attached to a virtual machine**.

```text
             EBS
              │
              ↓
        EC2 Instance
              │
              ↓
        Operating System
              │
              ↓
        Application
```

The screenshot describes data as being divided into **blocks** that can be directly accessed by the operating system.

---

## What Is Block Storage?

Data is divided into fixed-size blocks.

Conceptually:

```text
EBS Volume
┌────┬────┬────┬────┬────┐
│ B1 │ B2 │ B3 │ B4 │ B5 │
└────┴────┴────┴────┴────┘
```

The operating system manages the filesystem and determines how those blocks are used.

This makes block storage suitable for workloads that need a disk-like storage device.

---

## Why Use EBS?

Use EBS when you need:

* A virtual disk for an EC2 instance
* Operating-system storage
* Application storage
* Database storage
* Low-latency block-level storage

### Scenario

You launch an Ubuntu EC2 instance.

You need somewhere to install:

```text
Ubuntu
Application
Configuration
Logs
Files
```

An EBS volume can provide the disk storage:

```text
EC2
 │
 └── EBS Volume
       ↓
    Filesystem
       ↓
    Application
```

---

## Important EBS Point

The screenshot says:

> **Supports only a single write volume**

For your exam notes, understand this as the typical EBS model where a volume is attached to an EC2 instance for use as its block device.

There are service-specific exceptions such as **EBS Multi-Attach** for supported volume types, so don't memorize "EBS can never attach to multiple instances" as an absolute rule.

---

## 🧠 Memory

> **EBS = Virtual Hard Drive**

---

# 2. Amazon EFS — File Storage

## Definition

**Amazon Elastic File System (EFS)** is a **managed file storage service** that provides a shared filesystem that multiple resources can access over a network.

Think of it like a **shared network drive**.

```text
             EFS
              │
       ┌──────┼──────┐
       ↓      ↓      ↓
      EC2    EC2    EC2
       │      │      │
       └──────┴──────┘
          Shared Files
```

---

# 3. What Is File Storage?

With file storage, data is organized into:

```text
Folders
   ↓
Files
   ↓
File metadata
```

For example:

```text
/shared
 ├── app
 │    ├── config.txt
 │    └── data.txt
 │
 └── logs
      ├── app.log
      └── error.log
```

Multiple systems can access the same filesystem.

The screenshot mentions:

* Network sharing
* Multiple connections
* Multiple reads
* File write locks

EFS uses network file-system access, commonly through **NFS**.

---

# 4. Why Use EFS?

Use EFS when:

> **Multiple users, servers, or VMs need access to the same filesystem.**

For example:

```text
EC2-A ──┐
        │
EC2-B ──┼──→ EFS
        │
EC2-C ──┘
```

All of these instances can access the shared filesystem according to the configured permissions.

---

## Scenario

Imagine you have three web servers:

```text
Load Balancer
      ↓
 ┌────┼────┐
 ↓    ↓    ↓
EC2  EC2  EC2
 └────┼────┘
      ↓
     EFS
```

All three servers need access to the same uploaded files.

Instead of maintaining separate copies on each EC2 instance, EFS can provide shared file storage.

---

## EFS vs EBS

This distinction is extremely important.

### EBS

```text
EC2
 ↓
EBS
 ↓
Virtual Disk
```

Primarily associated with an EC2 instance.

### EFS

```text
        EFS
      /  |  \
    EC2 EC2 EC2
```

Designed for shared network file access.

### 🧠 Memory

> **EBS = One server's virtual disk**

> **EFS = Shared network filesystem**

---

# 5. Amazon S3 — Object Storage

## Definition

**Amazon Simple Storage Service (S3)** is an **object storage service**.

Instead of treating data as blocks or a traditional shared filesystem, S3 stores data as **objects**.

An object consists conceptually of:

```text
Object
│
├── Data
├── Metadata
└── Unique identifier/key
```

---

# 6. What Is Object Storage?

Think of S3 as:

```text
                 S3 Bucket
                     │
       ┌─────────────┼─────────────┐
       ↓             ↓             ↓
    Object 1      Object 2      Object 3
     image.jpg      video.mp4     report.pdf
```

Each object has data and metadata and is identified by its object key.

---

# 7. Why Use S3?

Use S3 when you simply want to **store and retrieve objects/files without managing the underlying storage infrastructure**.

Examples:

* Images
* Videos
* Documents
* Backups
* Logs
* Static website files
* Data for analytics

### Scenario

You have a website where users upload profile pictures.

Instead of attaching a disk to your application server:

```text
User
 ↓
Website
 ↓
S3
 ↓
profile.jpg
```

The application can upload and retrieve the object through AWS APIs.

---

# 8. How Do You Access S3?

The screenshot shows:

```text
HTTPS
API
```

This is important.

S3 is accessed through network/API interfaces rather than being mounted as a normal block disk in the same way as EBS.

Conceptually:

```text
Application
     ↓
 HTTPS / API
     ↓
   S3
     ↓
 Object
```

You can interact with S3 using:

* AWS Management Console
* AWS CLI
* AWS SDKs
* AWS APIs
* HTTPS-based requests

---

# 9. S3 Doesn't Work Like a Normal Disk

This is a very important distinction.

With EBS:

```text
EC2
 ↓
Disk
 ↓
Filesystem
 ↓
Files
```

With S3:

```text
Application
 ↓
API
 ↓
Bucket
 ↓
Objects
```

S3 is **object storage**, not a traditional block device.

---

# 10. S3 and File Size

The screenshot says:

> **Scales with limited/no file or storage limit**

For Cloud Practitioner, the important concept is:

> **S3 is designed to provide highly scalable object storage.**

Don't interpret this as literally unlimited with no AWS service constraints. AWS services have documented limits and quotas.

---

# 11. EBS vs EFS vs S3

This is probably the **most important table from this topic**.

| Feature             | EBS                                                       | EFS                  | S3                                 |
| ------------------- | --------------------------------------------------------- | -------------------- | ---------------------------------- |
| Storage type        | **Block**                                                 | **File**             | **Object**                         |
| Think of it as      | Virtual hard drive                                        | Shared network drive | Object/file repository             |
| Access              | Block device                                              | Network filesystem   | API/HTTPS                          |
| Typical use         | EC2 disk                                                  | Shared files         | Files/objects                      |
| Multiple EC2 access | Generally one attachment model, with supported exceptions | ✅ Shared             | ✅ Many applications can access     |
| Filesystem          | Managed by OS on the volume                               | Shared filesystem    | Object-based                       |
| Best for            | OS/apps/databases on EC2                                  | Shared filesystem    | Backups, images, videos, documents |

---

# 12. The Three Storage Models

Memorize this:

```text
                 STORAGE
                    │
        ┌───────────┼───────────┐
        ↓           ↓           ↓
      BLOCK        FILE        OBJECT
        ↓           ↓           ↓
       EBS         EFS          S3
        ↓           ↓           ↓
   Virtual Disk  Shared FS   Objects
```

# 13. Scenario-Based Example

Imagine you're building an application with multiple EC2 servers.

```text
                 Load Balancer
                      ↓
             ┌────────┼────────┐
             ↓        ↓        ↓
            EC2      EC2      EC2
             │        │        │
             ↓        ↓        ↓
            EBS      EBS      EBS
                      │
                      │
                     EFS
                      │
                      ↓
                     S3
```

You might use the services for different purposes:

### EBS

Each EC2 instance needs its own disk:

```text
EC2 → EBS
```

### EFS

All EC2 instances need access to shared files:

```text
EC2 ─┐
EC2 ─┼→ EFS
EC2 ─┘
```

### S3

The application needs to store objects such as:

```text
Images
Videos
Backups
Documents
Logs
```

```text
Application → S3
```

---

# 14. How to Choose

Ask yourself:

### "I need a virtual hard disk attached to my EC2."

→ **EBS**

### "Multiple EC2 instances need the same filesystem."

→ **EFS**

### "I just need scalable storage for files/objects."

→ **S3**
