# Cloud Service Models

Cloud computing is commonly divided into **three main service models**:

1. **IaaS — Infrastructure as a Service**
2. **PaaS — Platform as a Service**
3. **SaaS — Software as a Service**

The main difference is **how much of the IT environment is managed by the customer vs. the cloud provider**.

---

# 1. IaaS — Infrastructure as a Service

### NIST Definition

> The capability provided to the consumer is to provision **processing, storage, networks, and other fundamental computing resources**, where the consumer can deploy and run arbitrary software, including operating systems and applications.

The consumer **does not manage the underlying physical cloud infrastructure**, but has control over the **operating system, storage, deployed applications**, and possibly some networking components.

### AWS Definition

> IaaS contains the basic building blocks for cloud IT. It typically provides access to networking features, computers (virtual or dedicated hardware), and data storage space.

### Explanation

IaaS provides the **basic infrastructure** required to build and run applications. Instead of purchasing physical servers, you rent infrastructure from a cloud provider.

You are responsible for managing:

* Operating System
* Applications
* Data
* Runtime
* Some networking configurations

The provider manages:

* Physical servers
* Data centers
* Networking hardware
* Virtualization

**Example:** Amazon EC2

```text
YOU:       Application
           Data
           Runtime
           Guest OS
           ↑
PROVIDER:  Virtualization
           Physical Infrastructure
```

### Key Point

> **IaaS gives you the highest level of flexibility and control among the three cloud service models.**

**Think:** *Rent the infrastructure and manage it yourself.*

---

# 2. PaaS — Platform as a Service

### NIST Definition

> The capability provided to the consumer is to deploy **consumer-created or acquired applications** onto the cloud infrastructure using programming languages, libraries, services, and tools supported by the provider.

The consumer **does not manage the underlying infrastructure, operating system, or storage**, but has control over the deployed applications and some configuration settings.

### AWS Definition

> PaaS removes the need for you to manage the underlying infrastructure, usually hardware and operating systems, allowing you to focus on the deployment and management of your applications.

### Explanation

PaaS provides a **ready-to-use platform for developing and deploying applications**.

The cloud provider takes care of:

* Physical infrastructure
* Virtualization
* Servers
* Operating systems
* Runtime
* Platform maintenance
* Patching

You mainly focus on:

* Application
* Data
* Application configuration

```text
YOU:       Application
           Data
           ↑
PROVIDER:  Runtime
           Guest OS
           Virtualization
           Physical Infrastructure
```

### Example

**AWS Elastic Beanstalk** is an example of a PaaS-style service. You upload your application, while AWS handles much of the underlying infrastructure management.

### Key Point

> **PaaS allows developers to focus on building and deploying applications instead of managing infrastructure.**

**Think:** *The provider manages the platform; you manage your application.*

---

# 3. SaaS — Software as a Service

### NIST Definition

> The capability provided to the consumer is to **use the provider's applications running on a cloud infrastructure**.

The applications can be accessed through devices such as laptops and smartphones using interfaces like a **web browser or application**.

The consumer does not manage the underlying infrastructure, operating systems, storage, or the application itself, except for limited user-specific configuration.

### AWS Definition

> SaaS provides you with a **complete product that is run and managed by the service provider**.

You don't need to worry about how the service or underlying infrastructure is maintained. You primarily focus on **using the software**.

### Explanation

SaaS is the **most complete and ready-to-use cloud service**.

The provider manages almost everything:

* Physical infrastructure
* Virtualization
* Servers
* Operating systems
* Runtime
* Application
* Maintenance
* Updates and patching

The customer mainly:

* Uses the application
* Manages their account/data within the application's available controls
* Configures user-specific settings

```text
YOU:       Use the Application
           ↑
PROVIDER:  Application
           Data/Service infrastructure
           Runtime
           Guest OS
           Virtualization
           Physical Infrastructure
```

### Examples

* Gmail
* Microsoft 365
* Salesforce

### Key Point

> **SaaS provides a complete application that you can use without managing the underlying infrastructure.**

**Think:** *Just use the software.*

---

# IaaS vs PaaS vs SaaS

| Layer              | On-Premises | IaaS     | PaaS     | SaaS      |
| ------------------ | ----------- | -------- | -------- | --------- |
| **Application**    | You         | You      | You      | Provider  |
| **Data**           | You         | You      | You      | Provider* |
| **Runtime**        | You         | You      | Provider | Provider  |
| **Guest OS**       | You         | You      | Provider | Provider  |
| **Virtualization** | You         | Provider | Provider | Provider  |
| **Physical**       | You         | Provider | Provider | Provider  |

*The customer may still have responsibility for their data depending on the service and agreement.

## ⭐ Exam Shortcut

Remember the responsibility shift:

```text
ON-PREMISES
You manage EVERYTHING
        ↓
IaaS
You manage OS + Applications
        ↓
PaaS
You manage Applications
        ↓
SaaS
You mainly USE the Application
```

### One-line definitions

**IaaS →** Rent **infrastructure** and manage the OS and applications.

**PaaS →** Rent a **platform** and focus on developing/deploying applications.

**SaaS →** Use **ready-made software** managed by the provider.

> **IaaS = Infrastructure** → **PaaS = Platform** → **SaaS = Software**
