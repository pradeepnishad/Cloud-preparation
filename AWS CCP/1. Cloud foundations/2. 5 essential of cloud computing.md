# 5 Essential Characteristics of Cloud Computing — NIST

According to **NIST**, cloud computing has **5 essential characteristics**. These characteristics help distinguish cloud computing from traditional IT infrastructure.

---

## 1. On-Demand Self-Service

> **The ability to create IT resources, such as compute, storage, and databases yourself, without the need to interact with other humans to do the work.**

### Explanation

**On-demand self-service** means that a customer can **provision and manage cloud resources whenever they need them**, without having to contact the cloud provider's staff.

For example, suppose you need a virtual server.

In traditional IT:

```text
You need a server
      ↓
Request server from IT team
      ↓
IT team purchases/configures hardware
      ↓
Server becomes available
```

With cloud computing:

```text
You need a server
      ↓
Open AWS Console / CLI
      ↓
Create EC2 instance
      ↓
Server is available
```

You can also perform actions such as:

* Create a virtual machine
* Increase storage
* Create a database
* Create a network
* Delete resources
* Increase or decrease resources

### Key Point

**Self-service = You provision resources yourself.**

**On-demand = You can do it whenever you need it.**

---

# 2. Broad Network Access

> **The cloud resources are available to us over a network and are accessible through standard protocols.**

### Explanation

Cloud resources are accessed through a **network**, usually the Internet, using standard networking mechanisms and protocols.

You don't need to physically be inside the cloud provider's data center.

For example:

```text
Laptop
   │
   │ Internet
   ↓
AWS Cloud
   │
   ├── EC2
   ├── S3
   ├── RDS
   └── Other Services
```

You can access these resources from different types of devices:

```text
             AWS Cloud
                 │
       ┌─────────┼─────────┐
       ↓         ↓         ↓
    Laptop     Mobile    Server
```

For example, you can manage an AWS EC2 instance using:

* Web browser
* AWS CLI
* APIs
* SDKs

### Why "Broad"?

**Broad network access** means cloud services should be accessible across a wide range of network-connected devices and platforms.

### Key Point

**Broad network access = Cloud resources are accessible over a network using standard mechanisms/protocols.**

---

# 3. Resource Pooling

> **The provider's computing resources are pooled to serve multiple customers, with physical and virtual resources dynamically assigned and reassigned according to demand.**

### Explanation

Cloud providers have **large pools of physical resources** such as:

* CPUs
* RAM
* Storage
* Network bandwidth
* Physical servers

These resources are shared among **multiple customers**.

For example:

```text
                AWS Data Center
                      │
              Resource Pool
                      │
        ┌─────────────┼─────────────┐
        ↓             ↓             ↓
    Customer A    Customer B    Customer C
        │             │             │
      EC2           EC2           EC2
```

The customers don't need to know exactly **which physical server** their workload is running on.

The cloud provider dynamically allocates resources according to demand.

### Example

Imagine AWS has:

```text
100 Physical Servers
       ↓
Shared Resource Pool
       ↓
Many Customers
```

One customer may need more CPU today, while another needs more storage.

The provider dynamically allocates resources based on requirements.

### Virtualization

**Virtualization** is an important technology that enables resource pooling.

A physical server can be divided into multiple virtual machines:

```text
        Physical Server
              │
       Hypervisor
       /    |    \
      ↓     ↓     ↓
    VM-1   VM-2   VM-3
```

Each VM can operate independently even though the underlying physical hardware is shared.

### Key Point

**Resource pooling = Provider pools physical/virtual resources and dynamically allocates them to multiple customers.**

> **Important:** Your original point #3 was the same definition as Broad Network Access. For NIST, **Resource Pooling** is a separate characteristic and should not be confused with network access.

---

# 4. Rapid Elasticity

> **The ability to quickly scale your cloud resources based on changing demands.**

### Explanation

**Rapid elasticity** means cloud resources can be **quickly increased or decreased** according to workload requirements.

For example, imagine an e-commerce website.

Normally:

```text
100 users
   ↓
2 Servers
```

During a festival sale:

```text
100,000 users
      ↓
More servers required
      ↓
10 Servers
```

After the sale:

```text
Traffic decreases
      ↓
Resources decrease
      ↓
2 Servers
```

This allows organizations to avoid permanently maintaining large amounts of infrastructure just for occasional traffic spikes.

### Scaling can happen in two directions

**Scale up/out:**

```text
More demand
    ↓
More resources
```

**Scale down/in:**

```text
Less demand
    ↓
Fewer resources
```

### Elasticity vs Scalability

A useful exam distinction:

* **Scalability** → Ability to handle increased workload by adding resources.
* **Elasticity** → Ability to **automatically/rapidly increase AND decrease** resources according to demand.

### Key Point

**Rapid elasticity = Resources can be rapidly provisioned and released as demand changes.**

---

# 5. Measured Service

> **The cloud provider has automated systems to provide transparent billing details about the cloud resources you are consuming, allowing you, as the customer, to have monitoring and reporting capabilities of these cloud resources.**

### Explanation

Cloud providers **measure resource usage** and use that information for monitoring, reporting, and billing.

For example, AWS can track things such as:

```text
Compute usage
Storage usage
Network usage
Database usage
API requests
```

You can then see how much of a resource you are consuming.

For example:

```text
EC2
│
├── Running time
├── CPU usage
└── Data transfer

S3
│
├── Storage used
└── Requests
```

This supports the **pay-as-you-go** model.

If you use more resources:

```text
More usage
    ↓
Higher bill
```

If you use fewer resources:

```text
Less usage
    ↓
Lower bill
```

### Key Point

**Measured service = Cloud resource usage is monitored, measured, reported, and used for billing.**

# Quick Revision

| Characteristic             | Simple Meaning                                      | Remember                   |
| -------------------------- | --------------------------------------------------- | -------------------------- |
| **On-Demand Self-Service** | Create resources yourself whenever needed           | **I can create it myself** |
| **Broad Network Access**   | Access resources through a network                  | **Access over network**    |
| **Resource Pooling**       | Provider shares a pool of resources among customers | **Shared resources**       |
| **Rapid Elasticity**       | Quickly increase/decrease resources                 | **Scale quickly**          |

```text
1. Self-Service
      ↓

      ↓

      ↓

4. Rapid Elasticity
      ↓

      ↓
Usage is measured and billed
```

**NIST = 5 Essential Characteristics → Self-Service + Network Access + Resource Pooling + Elasticity + Measured Service.**
