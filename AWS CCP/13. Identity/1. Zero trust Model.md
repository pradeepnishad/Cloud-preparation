# 🔐 Zero Trust Model

## 1. Definition

The **Zero Trust model** operates on the principle:

> **“Trust no one, verify everything.”**

The main idea is that you **don't automatically trust a user, device, network, or location** just because they are inside an organization's environment.

Instead, access should be **verified and controlled continuously**.

---

# 2. Why Zero Trust?

Traditional security often relied heavily on **network boundaries**, such as:

* Firewalls
* VPNs
* Corporate networks

But modern environments have:

* Remote employees
* Bring-your-own-device (BYOD)
* Cloud resources
* Remote workstations
* Users accessing resources from different locations

Because of this, simply trusting someone because they are connected to the corporate network is no longer sufficient.

---

# 3. Identity Becomes the Primary Security Perimeter

This is the **most important concept in your screenshot**.

In Zero Trust:

> **Identity becomes the primary security perimeter.**

Instead of asking only:

> "Is this user inside our network?"

You ask:

> "Who is this user, what device are they using, what are they trying to access, and should they be allowed to access it?"

# 5. Network-Centric Security — Old Way

Traditional security was heavily **network-centric**.

The organization built a security boundary around its network:

```text id="x0a1da"
Internet
   ↓
Firewall
   ↓
Corporate Network
   ↓
Employees
```

VPNs were commonly used to allow remote employees to connect into that trusted network.

The basic assumption was closer to:

> If you're inside the trusted network, you're more trusted.

---

# 6. Identity-Centric Security — New Way

Zero Trust shifts the focus toward **identity**.

The screenshot gives examples of identity-based controls such as:

* **MFA**
* Provisioning access based on risk
* Considering **where** the user is
* Considering **when** access occurs
* Considering **what** the user wants to access

So access can be evaluated using multiple factors:

```text id="c0qj4f"
User Identity
     +
MFA
     +
Device/context
     +
Location
     +
Time
     +
Requested resource
     ↓
Access decision
```

# 7. Scenario

Imagine an employee wants to access an AWS resource.

### Traditional approach

```text id="x4yb3w"
Employee
   ↓
VPN
   ↓
Corporate Network
   ↓
Resource
```

Once connected to the corporate network, traditional controls may give the user access based heavily on network location.

### Zero Trust approach

```text id="3y8k1w"
Employee
   ↓
Verify Identity
   ↓
MFA
   ↓
Evaluate context/risk
   ↓
Check requested resource
   ↓
Grant appropriate access
```

The fact that the employee is remote, inside a VPN, or on a particular network does **not by itself establish trust**.

---

# 8. Zero Trust Does NOT Mean "No Network Security"

This is an important line from your screenshot:

> **Identity-Centric does not replace but augments Network-Centric Security.**

In other words, Zero Trust doesn't mean:

```text
❌ Throw away firewalls
❌ Stop using VPNs
❌ Ignore network security
```

Instead:

```text
Network Security
      +
Identity Security
      +
Context/Risk
      ↓
Stronger security model
```

So organizations can continue using network controls while adding identity-based controls.
