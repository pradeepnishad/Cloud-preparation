# ☁️ AWS Single Sign-On (AWS SSO)

## 1. Definition

**AWS Single Sign-On (AWS SSO)** is a service that allows you to **create or connect workforce identities once and centrally manage their access across your AWS Organization**.

The key idea from your source is:

> **Create/connect workforce identities once → manage access centrally → users get single-click access.**

Think of it as a **central identity and access system for your organization**.

---

## 2. Why Use AWS SSO?

In a large organization, you may have:

```text
Company
│
├── AWS Account — Development
├── AWS Account — Production
├── AWS Account — Testing
├── Office 365
├── Slack
├── Dropbox
└── Other applications
```

Managing separate credentials and permissions for every system can become difficult.

AWS SSO provides a central place to manage workforce access.

```text
                AWS SSO
                   │
       ┌───────────┼───────────┐
       ↓           ↓           ↓
   AWS Accounts  Business    SAML Apps
                 Apps
```

# 3. Identity Sources

Your screenshot shows that AWS SSO can use different identity sources:

### AWS SSO

Identities can be created/managed directly within the AWS identity system.

### Active Directory

You can connect an organization's **on-premises Active Directory**.

```text
On-Premises AD
      ↓
 AD Connector / AD Trust
      ↓
   AWS SSO
```

This allows existing corporate users and groups to participate in centralized access management.

### SAML 2.0 Identity Provider

An external identity provider can also be used through **SAML 2.0**.

So the identity source can be:

```text
AWS SSO
   OR
Active Directory
   OR
SAML 2.0 IdP
```

# 5. Scenario

Imagine a company has:

```text
             Corporate Users
                    ↓
             Active Directory
                    ↓
                AWS SSO
                    ↓
       ┌────────────┼─────────────┐
       ↓            ↓             ↓
   Dev AWS       Prod AWS       Slack
    Account       Account
```

An employee logs in through the organization's identity system.

AWS SSO then provides the appropriate access based on the permissions assigned to that user/group.

Instead of administrators separately managing access across every AWS account and application, access can be managed centrally.

# 6. AWS SSO vs Normal IAM

This is an important distinction.

### IAM

AWS IAM primarily manages **access to resources within an AWS account**.

```text
IAM
 ↓
Users / Groups / Roles
 ↓
AWS Resources
```

### AWS SSO

AWS SSO is designed around **workforce identity and centralized access across AWS accounts and applications**.

```text
AWS SSO
   ↓
Central identity
   ↓
Multiple AWS accounts
   +
Business applications
   +
SAML applications
```

So:

> **IAM → AWS resource access**

> **AWS SSO → Centralized workforce access**
