# 🔐 AWS Account Root User

## 1. Definition

The **AWS Account Root User** is the special identity created when an AWS account is first created.

It has **full access to the AWS account**, and its permissions cannot normally be limited using IAM policies.

Think of the AWS account structure as:

```text
AWS Account
│
├── Root User
│     └── Full account access
│
└── IAM Users
      ├── Developer
      ├── Administrator
      └── Auditor
```

### Important distinction

**AWS Account ≠ Root User ≠ IAM User**

* **AWS Account** → contains your AWS resources.
* **Root User** → special identity associated with the account, with full access.
* **IAM User** → identity created for regular AWS tasks with assigned permissions.

---

# 2. Root User vs IAM User

|                             | Root User                   | IAM User                               |
| --------------------------- | --------------------------- | -------------------------------------- |
| Created                     | When AWS account is created | Created by account administrator       |
| Login                       | Email + password            | Account ID/alias + username + password |
| Permissions                 | Full account access         | Assigned permissions                   |
| Permissions can be limited? | Not by IAM policies         | Yes                                    |
| Daily use                   | ❌ Avoid                     | ✅ Appropriate                          |
| MFA                         | ✅ Strongly recommended      | ✅ Recommended                          |

---

# 3. Why Shouldn't You Use Root User Daily?

The root user has extremely powerful access.

If the root credentials are compromised, the attacker can potentially perform highly privileged account-level actions.

Therefore, the recommended approach is:

```text
Root User
   ↓
Secure it
   ↓
Enable MFA
   ↓
Don't use for normal work
   ↓
Use IAM identities/roles instead
```

This also follows the **Principle of Least Privilege** you just learned.

# 4. Root User Access Keys

Your source strongly recommends:

> **Never use Root User Access Keys.**

Avoid creating root access keys for normal automation or applications.

Instead, use appropriate IAM roles or other AWS-supported credential mechanisms.

For example:

```text
❌ Application
   ↓
Root Access Key
   ↓
AWS

✅ Application / EC2
   ↓
IAM Role
   ↓
AWS
```

---

# 5. MFA for Root User

Your source strongly recommends enabling **MFA for the Root User**.

The idea is:

```text
Root email + password
        +
       MFA
        ↓
    Root access
```

This provides an additional authentication factor if the root password becomes compromised.

---

# 6. How Many Root Users?

There can be **only one root user associated with an AWS account**.

Don't confuse this with IAM users.

You could have:

```text
1 Root User

+
100 IAM Users
```

The number of IAM users can be managed separately.

---

# 7. When Should You Use the Root User?

Your source says the root user should be used for **specific and specialized tasks that are infrequent or rarely performed**.

Examples from your source include:

### Account settings

The root user can change certain account settings such as:

* Account name
* Account email address
* Root user password
* Root user access keys

### Restore IAM permissions

If the only IAM administrator accidentally removes their own permissions, the root user can be used to restore access.

```text
IAM Admin
   ↓
Accidentally removes own permissions
   ↓
Cannot administer IAM
   ↓
Root User
   ↓
Restore permissions
```

### Billing access

The source lists:

> Activate IAM access to the Billing and Cost Management console.

### Other account-level tasks

Your source also lists:

* View certain tax invoices
* Close the AWS account
* Change or cancel AWS Support plan
* Register as a seller in Reserved Instance Marketplace
* Enable MFA Delete on an S3 bucket
* Edit/delete certain S3 bucket policies containing invalid VPC/VPC endpoint IDs
* Sign up for GovCloud
