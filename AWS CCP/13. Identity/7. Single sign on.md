# 🔑 Single Sign-On (SSO)

## 1. Definition

**Single Sign-On (SSO)** is an authentication scheme that allows a user to **log in once and access multiple systems and software using a single identity**.

From your source:

> **SSO allows a user to log in with a single ID and password to different systems and software.**

Simple idea:

```text
User
 ↓
Login once
 ↓
Identity Provider / Directory
 ↓
 ┌──────┬──────┬──────────┬──────────┐
 ↓      ↓      ↓          ↓
 AWS   Slack  Google    Salesforce
```

Instead of entering separate credentials for every application, the user's identity is centrally managed.

# 2. Why Use SSO?

The screenshot highlights two major benefits.

### For Users

The login experience becomes **seamless**.

Once the user has logged into their primary directory, they can access supported applications without repeatedly seeing another login screen.

### For IT Departments

IT can:

* Administer a single identity
* Manage access centrally
* Allow that identity to access many machines and cloud services

So instead of:

```text
User
 ├── AWS password
 ├── Slack password
 ├── Salesforce password
 ├── Google Workspace password
 └── Other passwords
```

You have:

```text
User
  ↓
Single Identity
  ↓
Multiple Applications
```

# 4. SSO and SAML

This connects directly to the previous topic.

### SAML

**SAML** is a standard used to exchange authentication/authorization information between an **Identity Provider (IdP)** and a **Service Provider (SP)**.

### SSO

**SSO** is the login experience/architecture where one authentication can provide access to multiple applications.

So:

```text
SAML = Protocol
SSO  = Single-login experience
```

They are related but **not the same thing**.

Your screenshot gives:

```text
Azure AD
   ↓
 SAML
   ↓
 SSO
   ↓
AWS / Slack / Salesforce / Google Workspace
```

# 5. Identity Provider and Service Provider

This is another useful connection.

### Identity Provider (IdP)

The IdP manages the user's identity and authenticates the user.

In your diagram:

> **Azure Active Directory**

acts as the identity provider.

### Service Provider (SP)

The application/service the user wants to access.

Examples shown in the screenshot:

* AWS
* Slack
* Google Workspace
* Salesforce

So:

```text
User
 ↓
IdP
(Azure AD)
 ↓
SAML
 ↓
Service Provider
(AWS / Slack / Salesforce)
```

# 🔥 Important Distinctions

| Concept                     | Meaning                                                          |
| --------------------------- | ---------------------------------------------------------------- |
| **Identity Provider (IdP)** | Manages identity and authenticates users                         |
| **SSO**                     | One authentication → access to multiple applications             |
| **SAML**                    | Standard for exchanging authentication/authorization information |
| **Service Provider (SP)**   | Application/service being accessed                               |
| **Federated Identity**      | Identity linked across separate identity systems                 |
