# 🏢 Active Directory (AD)

## 1. Definition

**Active Directory Domain Services (AD DS)** is Microsoft's directory service for managing users, computers, and other resources in a Windows-based organization.

According to your source, Microsoft introduced **Active Directory Domain Services in Windows 2000** so organizations could manage multiple on-premises infrastructure components and systems using a **single identity per user**.

Simple idea:

```text
                    Active Directory
                          ↓
        ┌─────────────────┼─────────────────┐
        ↓                 ↓                 ↓
      Users           Computers          Resources
        ↓
   One identity
```

---

# 2. Why Use Active Directory?

Without a centralized directory, an organization would have to manage identities and resources separately across many systems.

Active Directory provides a centralized way to organize and manage:

* Users
* Computers
* Groups
* Other network resources

The major idea from your screenshot is:

> **One identity can be used to manage/access multiple infrastructure components and systems.**

However, **OU is not actually below Domain as a child domain**. OUs are containers *inside a domain*.

A better mental model is:

```text

│    │

│         │

│
└── Another Tree
     │
     └── Domain
          │
          └── OUs
```

---

# 4. Domain

A **Domain** is a logical administrative/security boundary containing users, computers, and other AD objects.

For example:

```text
company.com
```

could contain:

```text
company.com
│
├── Users
├── Computers
├── Groups
└── OUs
```

A domain is one of the most important building blocks of Active Directory.

---

# 5. Tree

An **AD Tree** is a collection of domains that share a **contiguous DNS namespace** and have a hierarchical relationship.

For example:

```text
company.com
     │
     ├── india.company.com
     │
     └── uk.company.com
```

These domains form a tree because they share the `company.com` namespace.

---

# 6. Forest

A **Forest** is the highest-level logical structure shown in your diagram.

It can contain:

* One or more trees
* Multiple domains

Example:

```text
Forest
│
├── Tree 1
│    ├── company.com
│    └── india.company.com
│
└── Tree 2
     ├── example.net
     └── child.example.net
```

The important idea:

> **Forest = collection of one or more AD trees.**

---

# 7. Organizational Unit (OU)

An **Organizational Unit (OU)** is a container inside a domain used to organize AD objects.

For example:

```text
company.com
│
├── OU: Mumbai
│    ├── User1
│    ├── User2
│    └── Computer1
│
├── OU: Bangalore
│    ├── User3
│    └── Computer2
│
└── OU: IT
     ├── User4
     └── Computer3
```

OUs are useful for organizing objects and applying administrative controls such as Group Policy.

---

# 8. Important Relationship

Remember the hierarchy like this:

```text
🌳 Forest
   ↓
🌲 Tree
   ↓
🏢 Domain
   ↓
📁 Organizational Units
   ↓
👤 Users / 💻 Computers / 👥 Groups
```

But technically, **OUs are containers within a domain**, rather than a hierarchical level equivalent to Forest → Tree → Domain.

---

# 9. Scenario

Imagine a company has offices in Mumbai and Bangalore.

You could have:

```text
Forest
   ↓
company.com
   ↓
Domain
   ↓
OUs
 ├── Mumbai
 │    ├── Users
 │    └── Computers
 │
 └── Bangalore
      ├── Users
      └── Computers
```

Users and computers can be centrally managed through Active Directory.

# 🔥 Active Directory vs Directory Service

You just learned **Directory Service** before this.

Think of the relationship as:

> **Directory Service = concept**

> **Active Directory = Microsoft's implementation of a directory service**

So:

```text
Directory Service
       ↓
General concept
       ↓
Microsoft Active Directory
       ↓
AD DS
```
