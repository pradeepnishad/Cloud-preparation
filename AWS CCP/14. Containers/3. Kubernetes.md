# Kubernetes

## 1. Definition

**Kubernetes** is an **open-source container orchestration system** used to automate:

* **Deployment**
* **Scaling**
* **Management**

of containers.

In simple terms:

> **Docker runs containers; Kubernetes manages containers at scale.**

Kubernetes is commonly abbreviated as **K8s**.

### Why K8s?

The word **Kubernetes** has 10 letters.

```text
K + 8 letters + s = K8s
```

---

## 2. Why use Kubernetes?

Running a few containers manually is manageable:

```text
Server
 ├── Container 1
 ├── Container 2
 └── Container 3
```

But imagine an application with **tens or hundreds of services** and containers distributed across multiple VMs.

You need something to manage:

* Where containers run
* Deployments
* Scaling
* Container management

This is where Kubernetes comes in.

---

## 3. Kubernetes vs Docker

The source specifically highlights Kubernetes' ability to run containers **distributed across multiple VMs**.

Think:

### Docker

```text
VM
 ├── Container
 ├── Container
 └── Container
```

### Kubernetes

```text
              Kubernetes
                  ↓
       ┌──────────┴──────────┐
       ↓                     ↓
      VM                    VM
   ┌───────┐             ┌───────┐
   │ Pods  │             │ Pods  │
   │Pods   │             │Pods   │
   └───────┘             └───────┘
```

Kubernetes coordinates containers across multiple machines.

---

# 4. What is a Pod?

A **Pod** is one of the unique concepts in Kubernetes.

According to the source:

> A pod is a group of one or more containers with shared storage, network resources, and other shared settings.

So:

```text
Pod
 ├── Container
 ├── Container
 └── Shared resources
```

A Pod can contain **one or more containers**.

For many common workloads, a Pod contains one primary application container, but multiple containers can be placed together when they need to share the Pod's resources.

# 6. Microservices + Kubernetes

Kubernetes is particularly useful for **microservice architectures** where an organization may have tens to hundreds of services to manage.

For example:

```text
Application
    │
    ├── User Service
    ├── Payment Service
    ├── Order Service
    ├── Notification Service
    └── Report Service
```

Each service can run in containers, and Kubernetes can coordinate those containers across multiple nodes.

---

# 7. Scenario

Imagine an e-commerce company has:

```text
100 microservices
500 containers
20 virtual machines
```

Managing every container manually would become difficult.

Kubernetes provides an orchestration layer to manage these containerized workloads across the VMs.

Conceptually:

```text
              Kubernetes
                   │
      ┌────────────┼────────────┐
      ↓            ↓            ↓
    Node 1       Node 2       Node 3
      │            │            │
    Pods         Pods         Pods
      │            │            │
 Containers    Containers   Containers
```

---

## 8. When to use Kubernetes

Kubernetes is useful when you have:

* Many containers
* Multiple services
* Microservice architectures
* Containers distributed across multiple machines
* A need for automated deployment, scaling, and management

For a very small application with only one or two containers, Kubernetes can introduce unnecessary complexity.

# Summary

| Concept        | Meaning                                                                 |
| -------------- | ----------------------------------------------------------------------- |
| **Kubernetes** | Container orchestration system                                          |
| **K8s**        | Short name for Kubernetes                                               |
| **Pod**        | Group of one or more containers                                         |
| **Node**       | Machine that runs Pods                                                  |
| **API Server** | Kubernetes control-plane interface                                      |
| **Scheduler**  | Determines where workloads should run                                   |
| **Controller** | Helps maintain desired state                                            |
| **etcd**       | Component shown in the control plane for Kubernetes state/configuration |
| **Kubelet**    | Node agent                                                              |
| **Proxy**      | Networking component shown on nodes                                     |

### 🧠 Exam Memory

> **Kubernetes = Deploy + Scale + Manage Containers**

And the most important distinction:

**Docker → Container runtime/tooling**

**Kubernetes → Container orchestration**

**Pod → Smallest deployable unit in Kubernetes, containing one or more containers**
