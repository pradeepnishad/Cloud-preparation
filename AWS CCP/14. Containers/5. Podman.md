# Podman, Buildah and Skopeo

These three tools are commonly associated with the **OCI/container ecosystem** and can be used together as alternatives or complements to parts of the Docker workflow.

## 1. Podman

### Definition

**Podman** is an **OCI-compliant container engine** and can be used as a drop-in replacement for Docker in many container workflows.

### Key points from your source

* **Daemonless:** Podman does not require a central container daemon in the same way Docker traditionally uses a container daemon.
* **Supports pods:** Podman can create and manage **pods**, similar to the Kubernetes concept.
* **Not a complete Docker replacement:** Podman replaces primarily the container-engine portion of the Docker ecosystem.
* It is intended to be used alongside tools such as **Buildah** and **Skopeo**.

### Simple mental model

```text
Docker
  ↓
Container Engine
  ↓
Run containers
```

Podman can perform that container-engine role:

```text
Podman
  ↓
Container Engine
  ↓
Run containers / Pods
```

### Why use Podman?

If you want a container engine that:

* Doesn't rely on a central daemon
* Supports OCI standards
* Can work with pods
* Fits well into the broader Red Hat/OCI container ecosystem

Podman is an option.

### Scenario

Suppose you have a container image and want to run it locally.

Instead of:

```bash
docker run my-app
```

you can commonly use:

```bash
podman run my-app
```

# 2. Buildah

### Definition

**Buildah** is a tool used to **build OCI container images**.

Think:

> **Buildah = Build container images**

The workflow can be:

```text
Dockerfile / Build instructions
          ↓
       Buildah
          ↓
    Container Image
```

### Why use Buildah?

It separates the **image-building** function from the container-running function.

For example:

```text
Buildah → Build image
Podman  → Run container
Skopeo  → Move/copy image
```

This separation is an important concept to remember.

---

# 3. Skopeo

### Definition

**Skopeo** is a tool for **moving container images between different types of container storage**.

Think:

> **Skopeo = Move/copy container images**

For example, an image might exist in:

```text
Container Registry
       ↓
     Skopeo
       ↓
Another Registry / Container Storage
```

It can be useful when moving or copying images between different container repositories or storage locations.

---

# 4. Podman vs Buildah vs Skopeo

This is the most important part to remember:

| Tool        | Main purpose               | Memory    |
| ----------- | -------------------------- | --------- |
| **Podman**  | Run/manage containers      | **Run**   |
| **Buildah** | Build OCI container images | **Build** |
| **Skopeo**  | Move/copy container images | **Move**  |

### Easy memory:

> 🏃 **Podman = Run**
> 🔨 **Buildah = Build**
> 🚚 **Skopeo = Move**

---

# 5. How they work together

A typical workflow could look like:

```text
        Application
             ↓
          Buildah
             ↓
      Container Image
             ↓
          Skopeo
             ↓
      Container Registry
             ↓
          Podman
             ↓
       Running Container
```

So rather than thinking of Podman, Buildah and Skopeo as one product, think of them as **different tools handling different parts of the container lifecycle**.

---

## Exam-focused summary

* **Podman** → OCI-compliant container engine; daemonless; supports pods.
* **Buildah** → builds OCI container images.
* **Skopeo** → moves/copies container images between container storage locations.
* **Podman is not the entire Docker ecosystem replacement**; the source specifically emphasizes that it replaces one part of Docker and works alongside Buildah and Skopeo.
* **Docker → Podman**: container-engine comparison.
* **Dockerfile/image building → Buildah**.
* **Image movement between registries/storage → Skopeo**.

### 🧠 One-line memory

**Buildah builds → Skopeo moves → Podman runs.**
