# 🔔 SNS vs 📬 SQS

Both are AWS messaging services, but they solve **different problems**.

### The easiest memory trick:

> **SNS = Send/Push**  
> **SQS = Store/Queue/Pull**

---

## 1. AWS SNS — Simple Notification Service

**SNS is a Pub/Sub (Publish/Subscribe) messaging service.**

The basic idea:

```text
Publisher
    ↓
   SNS Topic
   ↙ ↓ ↘
Subscriber Subscriber Subscriber
```

A publisher sends a message to an **SNS Topic**, and SNS passes that message to its subscribers.

### What can subscribe?

The slide gives examples:

- HTTP
- Email
- SQS
- SMS

So SNS can distribute a message to **multiple destinations**.

### Example

Suppose your AWS application detects a billing event:

```text
AWS Service
     ↓
SNS Topic
 ↙   ↓    ↘
Email SMS  Lambda
```

One event can trigger multiple subscribers.

---

# 2. AWS SQS — Simple Queue Service

**SQS is a message queue.**

Instead of immediately pushing messages to consumers, SQS **stores messages in a queue**.

```text
Producer
   ↓
 SQS Queue
   ↓
Consumer
```

The application/consumer **pulls messages from the queue using the AWS SDK**.

### Example

Imagine an online shopping website.

```text
Customer places order
        ↓
     SQS Queue
        ↓
 Order Processing App
```

If 10,000 orders arrive at once, the queue can hold the messages while your application processes them.

---

# 🔥 Main Difference

| SNS | SQS |
|---|---|
| **Push** messages | **Queue/store** messages |
| Pub/Sub | Message queue |
| Sends to subscribers | Consumers pull messages |
| One message → multiple subscribers | Messages wait in queue |
| Good for notifications | Good for asynchronous processing |
| Can send to HTTP, Email, SMS, SQS, etc. | Applications consume using AWS SDK |
| Common for event notifications | Common for delayed/background tasks |

# 🧠 SNS = "Tell everyone"

Think of SNS like a **WhatsApp announcement group**.

You send:

> "Server is down!"

Everyone subscribed gets the message.

```text
             SNS
              ↓
       ┌──────┼──────┐
       ↓      ↓      ↓
     Email    SMS   Lambda
```

---

# 🧠 SQS = "Put it in line"

Think of SQS like a **restaurant queue**.

Customers/orders wait in line until a worker processes them.

```text
Orders
 ↓
┌─────────────┐
│ Order 1     │
│ Order 2     │
│ Order 3     │
│ Order 4     │
└─────────────┘
      ↓
   Worker
```

This is useful when the producer and consumer don't need to work at exactly the same time.

# Important SQS points from the slide

### ⏳ Message retention

The slide says SQS can retain a message for **up to 14 days**.

So:

```text
Producer → SQS → [message waits] → Consumer
```

The consumer doesn't have to process it immediately.

### 🔢 Sequential or parallel processing

The slide says messages can be sent:

- Sequentially
- In parallel

### 📨 At-least-once delivery

The slide highlights that SQS can ensure messages are delivered **at least once**.

For the exam, remember:

> **At-least-once = a message may potentially be delivered more than once, so applications should handle duplicates appropriately.**

# Where would you use each?

### Use SNS when:

You want to **notify multiple subscribers**.

Example:

```text
AWS Event
    ↓
SNS
 ↓   ↓   ↓
Email SMS Lambda
```

Typical use cases:

- Notifications
- Pub/Sub
- Webhooks
- Triggering Lambda
- Sending alerts

---

### Use SQS when:

You want to **queue work for processing**.

Example:

```text
Website
   ↓
 SQS
   ↓
Worker
   ↓
Database
```

Typical use cases:

- Background jobs
- Order processing
- Asynchronous workloads
- Decoupling applications
- Handling traffic spikes

---

# ⭐ Very Important: SNS + SQS Together

This is a common AWS architecture.

You can use **SNS to broadcast** and **SQS to buffer/process**.

```text
                 SNS Topic
                /         \
               ↓           ↓
          SQS Queue A   SQS Queue B
              ↓             ↓
          App Server A   App Server B
```

For example, an order event happens:

```text
              Order Created
                    ↓
                   SNS
                /       \
               ↓         ↓
          SQS Orders   SQS Analytics
               ↓         ↓
        Order Service  Analytics
```

SNS distributes the event, while SQS gives each application its own queue to process the work.
