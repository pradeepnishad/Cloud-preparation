# 🔐 Anatomy of an IAM Policy

An **IAM Policy** is a JSON document that defines **what API actions are allowed or denied**.

The policy is made up of several important elements.

---

## 1. `Version`

```json
"Version": "2012-10-17"
```

### What is it?

Specifies the **policy language version** being used.

Your source identifies `2012-10-17` as the latest version.

### Remember:

**Version → Policy language version**

---

## 2. `Statement`

```json
"Statement": [
   ...
]
```

### What is it?

`Statement` is the **container for the individual policy rules**.

A policy can contain **multiple statements**.

For example:

```text
Policy
  │
  └── Statement
       ├── Rule 1
       ├── Rule 2
       └── Rule 3
```

### Remember:

**Statement → Contains the rules**

---

## 3. `Sid`

```json
"Sid": "Deny-Barclay-S3-Access"
```

### What is it?

`Sid` means **Statement ID**.

It is an **optional identifier/label** used to identify a particular statement.

For example:

```text
Statement 1 → Sid: Deny-S3
Statement 2 → Sid: Allow-S3
```

### Remember:

**Sid → Label for a statement**

---

# 4. `Effect`

```json
"Effect": "Allow"
```

or

```json
"Effect": "Deny"
```

### What is it?

Defines whether the policy **allows or denies** the specified action.

Two values:

```text
Allow
Deny
```

Example:

```json
"Effect": "Allow"
```

→ Allow the specified action.

```json
"Effect": "Deny"
```

→ Deny the specified action.

### Remember:

**Effect → Allow or Deny**

---

# 5. `Action`

```json
"Action": "s3:*"
```

### What is it?

Specifies the **AWS API actions** that the policy allows or denies.

For example:

```json
"Action": "s3:GetObject"
```

means the policy applies to the S3 `GetObject` action.

You can also specify multiple actions:

```json
"Action": [
    "s3:GetObject",
    "s3:PutObject"
]
```

### Remember:

**Action → What can the identity do?**

---

# 6. `Principal`

```json
"Principal": {
    "AWS": [
        "arn:aws:iam::123456789012:user/barclay"
    ]
}
```

### What is it?

`Principal` identifies the **account, user, role, or federated user** to which the access is being granted or denied.

Think:

> **Who is this policy statement talking about?**

Example:

```text
Principal
    ↓
Specific IAM User
    ↓
barclay
```

### Remember:

**Principal → Who?**

---

# 7. `Resource`

```json
"Resource": "arn:aws:s3:::my-bucket"
```

### What is it?

Specifies the **AWS resource to which the action applies**.

For example:

```text
Action:
s3:GetObject

Resource:
my-bucket
```

The statement therefore defines what the principal can/cannot do **to that resource**.

### Remember:

**Resource → Which AWS resource?**

---

# 8. `Condition`

```json
"Condition": {
    "StringLike": {
        "iam:AWSServiceName": [
            "rds.amazonaws.com"
        ]
    }
}
```

### What is it?

`Condition` specifies **optional circumstances under which the policy applies**.

In simple terms:

> **Under what conditions should this rule apply?**

Your screenshot gives `Condition` as optional.

Examples of conditions shown in your source include:

* IP address
* Requested Region
* MFA status
* Current time
* Other AWS condition keys

### Remember:

**Condition → Under what circumstances?**

---

# 🧩 Put Everything Together

A simplified IAM policy looks like:

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "ExampleStatement",
            "Effect": "Allow",
            "Action": "s3:GetObject",
            "Principal": "*",
            "Resource": "arn:aws:s3:::my-bucket/*",
            "Condition": {}
        }
    ]
}
```

Think about the policy as asking a series of questions:

```text
Version
   ↓
Which policy language version?

Statement
   ↓
What rule?

Sid
   ↓
What is this rule called?

Effect
   ↓
Allow or Deny?

Action
   ↓
What action?

Principal
   ↓
Who?

Resource
   ↓
Which resource?

Condition
   ↓
Under what circumstances?
```

---

# 🎯 Exam Memory Trick

The most important elements to remember:

| Element       | Question                       |
| ------------- | ------------------------------ |
| **Version**   | Which policy language version? |
| **Statement** | What rule?                     |
| **Sid**       | What is the rule called?       |
| **Effect**    | Allow or Deny?                 |
| **Action**    | What can/can't be done?        |
| **Principal** | Who?                           |
| **Resource**  | Which resource?                |
| **Condition** | Under what conditions?         |

### 🧠 One-line memory

> **Principal → Action → Resource → Effect → Condition**

Think:

**WHO → DOES WHAT → TO WHAT → ALLOW/DENY → WHEN/UNDER WHAT CONDITIONS**.
