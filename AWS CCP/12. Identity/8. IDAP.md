# 🔐 LDAP — Lightweight Directory Access Protocol

## 1. Definition

**LDAP (Lightweight Directory Access Protocol)** is an **open, vendor-neutral, industry-standard application protocol** used for accessing and maintaining **distributed directory information services** over an IP network.

Simple idea:

> **LDAP = A protocol used to communicate with and access a directory service.**

It is not itself the directory database. It is the **protocol used to access/manage directory information**.

---

# 2. What Does LDAP Store?

A common use of LDAP, according to your source, is providing a central place to store:

* Usernames
* Passwords
* Directory information

# 4. LDAP vs SSO

This is **very important**, because the screenshot specifically compares LDAP with SSO.

### LDAP

LDAP can provide **same-sign-on** according to your source.

The user has:

> **One ID and password**

But they may have to **enter it every time they log in** to another system.

Example:

```text
User
 ↓
Username + Password
 ↓
System A

User
 ↓
Same Username + Password
 ↓
System B
```

---

### SSO

With **Single Sign-On**, the user authenticates once and can access multiple supported applications without repeatedly entering credentials.

```text
User
 ↓
Login once
 ↓
SSO
 ├── AWS
 ├── Slack
 ├── Salesforce
 └── Google Workspace
```

So:

> **LDAP → same identity/credentials can be used**

> **SSO → authenticate once and access multiple systems**

---

# 5. Why Use LDAP if SSO Is More Convenient?

Your source gives three important reasons.

### 1. SSO systems often use LDAP

LDAP can act as an underlying directory/identity source for authentication systems.

```text
LDAP
 ↓
Identity information
 ↓
SSO system
 ↓
Applications
```

### 2. LDAP wasn't designed natively for web applications

LDAP was designed as a directory access protocol rather than specifically as a modern web application authentication mechanism.

### 3. Some systems support LDAP but not SSO

This is the practical reason highlighted by your source.

Some applications may have **LDAP integration** available but may not support your organization's SSO mechanism.

So LDAP can still be necessary for compatibility.

# 🔥 LDAP vs Directory Service vs Active Directory vs SSO

This is where these concepts can get confusing.

| Concept               | What it is                                                                            |
| --------------------- | ------------------------------------------------------------------------------------- |
| **Directory Service** | System that stores/organizes information about users, computers, resources, etc.      |
| **Active Directory**  | Microsoft's directory service                                                         |
| **LDAP**              | Protocol used to access/maintain directory information                                |
| **SSO**               | Authentication experience where one login can provide access to multiple applications |

### Simple architecture

```text
Directory Service
      │
      └── Active Directory
              │
              ↓
             LDAP
              │
              ↓
       Applications/Systems
```

And SSO can sit above/alongside the identity infrastructure:

```text
User
 ↓
SSO
 ↓
Identity Provider
 ↓
Directory / Identity Store
 ↓
Applications
```
